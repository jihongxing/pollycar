# 统一错误模型

本文档定义 PollyCar API、后台操作和异步命令的错误分类、响应结构、披露规则、重试语义和审计要求。机器可检查错误码以 `spec/api/error-codes.yaml` 为准。

## 设计原则

- 错误码稳定，中文提示可以在不改变语义的前提下优化。
- 用户提示不暴露风控阈值、他人信息、内部标识、支付机构原文或安全证据。
- 同一业务原因在同步 API、异步任务和后台操作中使用同一错误码。
- 客户端只依据错误码和结构化字段决定行为，不解析中文提示。
- 可重试错误必须明确重试条件，不得默认无限重试。
- 安全、支付、权限和并发错误必须生成对应等级的审计记录。
- 未知内部异常统一收敛，不向用户返回堆栈、SQL、路径或第三方凭据。

## 标准错误响应

```json
{
  "error": {
    "code": "ELIGIBILITY_SUSPENDED",
    "message": "弹性参与资格当前已暂停",
    "request_id": "req_01J...",
    "retryable": false,
    "details": {
      "appeal_allowed": true
    }
  }
}
```

字段规则：

| 字段 | 必需 | 含义 |
| --- | --- | --- |
| `code` | 是 | 稳定机器错误码 |
| `message` | 是 | 面向当前语言环境的安全提示 |
| `request_id` | 是 | 用于客服和审计定位的请求标识 |
| `retryable` | 是 | 当前请求是否可在条件不变时重试 |
| `details` | 是 | 经过白名单控制的结构化详情，可为空对象 |

禁止返回：

- 内部异常堆栈、数据库信息和文件路径。
- 风险分数、职业化阈值和规则表达式。
- 他人身份、联系方式、举报者身份或安全证据。
- 完整支付机构错误响应、交易凭据或密钥。
- 可以推断账号是否存在的认证细节。

## 错误命名

格式：

`<领域>_<具体原因>`

领域前缀：

| 前缀 | 范围 |
| --- | --- |
| `VALIDATION_` | 请求字段、格式和业务输入 |
| `AUTHENTICATION_` | 登录、令牌和身份会话 |
| `AUTHORIZATION_` | 角色、资源范围和职责分离 |
| `ELIGIBILITY_` | 弹性资格申请、审核、启用和申诉 |
| `QUOTA_` | 车主配额和接单窗口 |
| `PAYMENT_` | 支付、退款和支付机构结果 |
| `TRIP_` | 订单和行程状态 |
| `SAFETY_` | 安全冻结、证据和高风险处置 |
| `CONFLICT_` | 幂等、版本和并发竞争 |
| `RATE_LIMIT_` | 频率限制和冷却时间 |
| `INTERNAL_` | 系统不可预期错误和依赖故障 |

## HTTP 状态映射

| HTTP 状态 | 使用场景 |
| --- | --- |
| `400` | 请求结构或字段无效 |
| `401` | 未认证、令牌失效或会话不可用 |
| `403` | 已认证但无权限，或安全策略禁止 |
| `404` | 资源不存在，且披露存在性安全 |
| `409` | 状态冲突、版本冲突、重复资源或订单竞争 |
| `422` | 请求格式正确但业务守卫不满足 |
| `429` | 频率、冷却或尝试次数限制 |
| `500` | 未分类内部异常 |
| `502` | 外部依赖返回无效结果 |
| `503` | 临时不可用或依赖故障 |
| `504` | 外部依赖超时 |

## 重试语义

`retryable: true` 只表示客户端可以根据 `details.retry_after` 或幂等键安全重试，不代表一定成功。

可重试：

- 支付机构临时不可用或超时。
- 服务器临时不可用。
- 明确允许重试的并发冲突。
- 带有冷却时间的频率限制。

不可直接重试：

- 权限不足。
- 资格暂停、撤销或到期。
- 配额窗口已满。
- 审核拒绝。
- 请求字段无效。

状态、配额或资料变化后可以重新发起新请求，但不视为对原请求的直接重试。

## 详情字段白名单

可使用：

- `field`：无效字段名。
- `state`：当前公开状态标识。
- `allowed_actions`：允许用户执行的下一动作。
- `appeal_allowed`：是否允许申诉。
- `retry_after`：可再次尝试的时间或秒数。
- `window`：命中的公开配额窗口，例如 `PT24H`。
- `limit`：公开配额上限。
- `current_count`：本人当前计数。
- `payment_status`：安全支付状态。

禁止使用：

- 风险分数、内部阈值、其他车主计数。
- 审核员身份、内部工单内容。
- 举报者身份、聊天或位置证据。
- 支付机构完整响应和内部堆栈。

## 披露等级

| 等级 | 含义 | 示例 |
| --- | --- | --- |
| `public` | 可直接向用户说明具体原因 | 字段无效、配额窗口已满 |
| `limited` | 说明结果和下一动作，不说明内部依据 | 审核拒绝、资格暂停 |
| `generic` | 只返回通用安全提示 | 安全冻结、认证失败 |
| `internal_only` | 用户仅收到通用内部错误 | 未知异常、依赖协议错误 |

## 审计等级

| 等级 | 要求 |
| --- | --- |
| `none` | 普通输入错误可不单独记录安全审计 |
| `standard` | 记录请求、错误码、主体和结果 |
| `sensitive` | 记录角色、资源、状态、策略版本和关联链路 |
| `strict` | 全量记录成功失败、原因引用、权限判断和人工操作，不记录敏感原文 |

## 错误处理流程

1. 领域或授权层产生稳定内部错误码。
2. API 层映射 HTTP 状态和安全中文提示。
3. 根据披露等级过滤 `details`。
4. 根据审计等级写入对应审计事件。
5. 返回 `request_id`，不返回内部异常。
6. 未注册错误码统一映射为 `INTERNAL_UNEXPECTED_ERROR`，同时触发内部告警。

## 安全要求

- 认证失败统一提示，避免账号枚举。
- 权限拒绝不披露资源是否真实存在。
- 安全冻结不披露触发规则、举报者和证据。
- 支付错误不返回银行卡、账户或支付机构敏感详情。
- 同一错误在高频出现时触发滥用、攻击或系统故障监控。

## 兼容与版本

- 已对外使用的错误码不得改变含义。
- 错误码废弃时保留兼容期，并记录替代错误码。
- 新增 `details` 字段必须为可选，客户端必须忽略未知字段。
- OpenAPI 必须引用统一错误响应结构和错误码注册表。

## 实施验收

- 所有 API 非成功响应符合统一结构。
- 所有文档和规范引用的错误码都存在于注册表。
- HTTP 状态、重试和披露规则与注册表一致。
- 权限、安全、支付和并发错误生成要求等级的审计。
- 不存在堆栈、路径、SQL、密钥或敏感原文泄露。
- 客户端不解析中文提示决定业务行为。
