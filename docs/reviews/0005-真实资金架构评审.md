## 外部公开材料核验

### 出行平台公开模式

- Uber 官方使用条款将其服务描述为数字交易市场平台，并对第三方服务费用采用代表第三方服务提供者收取费用的有限收款代理结构；同时明确支付可能由第三方支付服务商处理。该模式证明“平台管理订单和交易、服务由第三方提供、平台协助收款”具有行业先例，但其美国条款不能直接作为中国法律结论。
- 曹操出行官方隐私政策将交易支付列为平台核心能力，并说明使用第三方支付时平台取得支付工具和订单支付状态等必要信息，用于确认支付、维护交易秩序和处理纠纷。
- 美团规则中心公开材料显示，美团打车为在线支付处理支付时间、金额和渠道信息，并接入第三方支付类软件开发包。
- 滴滴出行的公开协议入口采用动态短链接和 App 内协议中心，本轮未获得稳定、可长期引用的支付合同文本，因此不把滴滴条款作为本决策的唯一证据。

行业参考结论：

- PollyCar 可以采用平台管理报价、订单、责任和账务，持牌支付机构执行外部资金动作的模式。
- 竞品条款不能替代 PollyCar 根据自身经营主体、运输责任和支付产品形成正式合同。

### 微信支付官方能力

微信支付官方商户文档公开列出：

- APP 下单和 APP 调起支付。
- 按微信支付订单号或商户订单号查询订单。
- 关闭订单和支付成功回调通知。
- 申请退款、查询单笔退款、异常退款和退款结果通知。
- 申请交易账单、申请资金账单和下载账单。
- 分账和商家转账产品。
- 微信支付公钥和平台证书安全工具。

结论：微信支付公开能力原则上覆盖本设计需要的支付、查询、退款、通知、账单、分账和付款边界；具体主体准入、行业类目、分账比例、结算周期和接口权限必须以商户申请结果和合同为准。

### 支付宝官方能力

支付宝官方 APP 支付产品材料确认：

- 商家 App 可以集成支付宝 SDK 完成支付。
- 产品需要完成签约和技术集成。
- 支持原路退款。
- 存在交易服务费和结算规则。
- 新签约或交易时间不足的商家可能适用不同结算安排。

支付宝开放平台同时提供支付、交易查询、退款、账单和资金产品目录。结论：支付宝原则上可以作为候选支付供应商，但实际费率、退款期限、结算方式、分账和转账能力必须以正式签约产品为准。

## 工程评审

### 通过项

- 领域边界清晰，资金状态不再依附行程状态。
- 幂等记录要求绑定操作、主体、资源和请求摘要。
- 支付机构回调先验签和校验，再改变状态和记账。
- 账本要求数据库级借贷平衡和不可变分录。
- 对账支持逐笔、汇总、重跑、差异案件和关账门禁。
- 未知结果通过查询原请求恢复，不盲目重试。

### 实施停止线

- 不得先接支付 SDK 再补账本。
- 不得用 App 上传金额创建真实支付。
- 不得使用行程 JSON 作为支付或余额唯一事实源。
- 不得使用负数支付代替退款。
- 不得允许管理员直接修改余额。
- 不得在账本和对账完成前开放真实结算或提现。

## 安全评审

### 通过项

- 默认关闭和依赖门禁继续生效。
- 生产密钥不进入 App、日志和公开构建。
- 回调要求验签、防重放、唯一事件和金额校验。
- 高风险人工操作要求经办和复核分离。
- 非零金额差异会冻结后续资金动作。

### 待外部证据

- 支付机构商户号、证书、密钥托管和轮换方案。
- 生产资金后台强认证和权限审计方案。
- 支付机构安全事件、退款失败和拒付责任合同。

## 财务与税务评审

内部候选已经确定：

- 最小复式科目框架。
- 支付手续费首期由平台承担。
- 服务费和车主所得在履约或责任确定后确认。
- 取消费首期关闭。
- 北京时间账务日和日终关账机制。

仍需专业签署：

- 正式会计科目表。
- 服务费、税费和车主所得比例。
- 发票和税务处理。
- 拒付、坏账和追偿政策。
- 财务证据保留期限。

## 法律与合规评审

内部候选已经确定：

- 平台不建立储值钱包。
- 外部资金动作由持牌支付机构执行。
- 平台账本只记录内部资金归属，不替代支付机构清算。

尚未获得：

- 平台在具体支付产品中的法律角色书面意见。
- 支付机构合同和数据处理责任。
- 车主所得、分账、税务和争议责任意见。

因此不能把本次内部评审解释为真实资金合法性批准。

## 架构评审关闭情况

原五项问题已经按架构实施范围处理：

1. 平台资金关系已收敛为“平台管理订单和账务、持牌支付机构执行外部资金动作”；最终合同角色转入生产启用评审。
2. 微信支付和支付宝公开能力已完成初步核验；具体商户申请和合同转入生产启用评审。
3. 支付手续费确定由平台承担；服务费、税务和运营收入等待独立服务费与运营系统设计。
4. 财务数据已建立分类型 `30 年／10 年／5 年`内部保守基线，正式法律映射转入生产启用评审。
5. 生产密钥和商户号只能在申请后完成，转入生产启用评审。

## 最终评审结论

### 允许

- 建立 `Money`、报价、支付、退款、结算、提现和拒付机器契约。
- 建立合成支付机构适配器。
- 建立 PostgreSQL 复式账本和余额投影。
- 建立合成回调 Inbox、未知结果恢复和孤立资金案件。
- 建立合成对账批次、差异项和关账门禁。
- 建立权限和审计测试。

### 禁止

- 接入真实支付生产密钥。
- 发起任何真实扣款、退款、分账或提现。
- 保存真实银行卡或真实支付凭据。
- 将真实资金门禁改为开启。
- 宣称真实资金能力已经通过法律、财务或生产评审。

## 生产启用保留项

以下事项不再阻止合成资金内核实现，但继续阻止真实资金启用：

1. 最终经营主体、运输服务责任和支付代收角色合同。
2. 微信支付或支付宝正式商户申请、行业类目和产品权限。
3. 服务费与运营系统设计、正式会计科目、税务和发票方案。
4. 财务数据保留期限的正式法律、税务和隐私签署。
5. 生产密钥、商户号、权限分离、轮换和双人复核演练。
6. 真实供应商沙箱、对账账单和异常恢复验收。

## 重新评审条件

- 选择具体支付机构或更换支付产品。
- 引入平台余额、充值、储值、借贷或垫资。
- 启用取消费。
- 改变服务费、车主所得或税务模式。
- 引入跨境资金或外币。
- 准备首次真实资金演练或生产启用。
