# 平台服务费与多运营主体分成评审

## 评审结论

`尚不能批准真实资金生产启用`

内部商业分配候选已收敛为：

```text
平台服务费：15%
运营主体经营份额：45%
车主应付款：40%
用户支付手续费：平台承担
车主付款手续费：运营主体承担
```

允许继续：

- 服务费和分成合成计算。
- 订单分成快照。
- 多运营主体和车主归属领域建模。
- 复式账本与五段对账设计。
- 默认关闭的供应商中立资金内核。

禁止继续：

- 真实收款。
- 真实分账。
- 真实运营主体商户入驻。
- 真实车主付款或提现。
- 真实商户号、密钥和银行账户接入。
- 向用户或车主承诺真实结算时间。

## 已通过事项

| 事项 | 结论 |
| --- | --- |
| 商业比例 | 使用订单可分配金额的 `15%/45%/40%` |
| 分配层级 | 平台 `15%`，运营主体承接 `85%`，其中 `40%` 为车主应付款 |
| 用户支付手续费 | 平台承担，不减少运营主体和车主份额 |
| 车主付款手续费 | 运营主体承担，不减少车主应付款 |
| 舍入 | 平台和运营主体向下取整，尾差进入车主份额 |
| 历史快照 | 接单时锁定运营主体、合同和规则版本 |
| 多运营主体 | 每笔订单只绑定一个运营主体 |
| 车主付款责任 | 运营主体负责，平台不建立车主钱包 |
| 优惠 | 出资方承担，不得无规则减少车主应付款 |
| 代垫费用 | 不参与比例分配，按实际承担方全额归还 |
| 取消费 | 继续关闭，未来使用独立分配策略 |

## 支付产品能力评审

### 微信支付

- 普通商户分账公开默认最高分账比例为 `30%`。
- 服务商分账公开默认最高分账比例为 `30%`。
- 平台 `15%` 在公开默认比例范围内。
- 平台收付通支持二级商户、佣金、分账、补差、退款、余额、提现和账单，是当前最符合多运营主体结构的候选。
- 运营主体和车主的 `45%/40%` 不能假设通过普通分账一次完成。

### 支付宝

- 商家分账公开最高分出金额不超过订单金额的 `30%`。
- 分账接收方可以是企业或个人支付宝账户。
- 个人接收方不支持分账回退。
- 商家分账不能作为直接向车主分出 `40%` 的首期默认路径。
- 需要支付宝针对平台、多运营主体、退款和车主付款提供独立书面产品方案。

## 当前阻断

### 阻断 1：平台和运营主体的运输经营法律角色

需要确认：

- 平台主体是否属于网络预约出租汽车经营者或乘车服务主要责任人。
- 运营主体能否作为乘车服务合同和收款主体。
- 平台是否可以只按 `15%` 提供技术与撮合服务。
- 哪一主体承担承运、安全、保险、投诉、退款和消费者责任。

未关闭影响：不能确定乘车服务合同、收款主体、发票主体和法定责任。

### 阻断 2：会计总额或净额确认

需要确认：

- 平台是否按净额确认 `15%` 收入。
- 运营主体按总额确认 `85%` 并将 `40%` 记为成本，还是按净额确认 `45%`。
- 分配子账如何映射到各法律实体法定总账。

未关闭影响：不能形成正式会计科目表和财务报表。

### 阻断 3：发票和税务

需要确认：

- 谁向乘车人开具乘车服务发票。
- 平台如何向运营主体开具 `15%` 服务费发票。
- 车主 `40%` 对应的所得性质、凭证、税率和代扣代缴。
- `15%/45%/40%` 是否按含税成交价计算。

未关闭影响：不能真实付款、开票或报税。

### 阻断 4：支付机构书面产品方案

需要取得：

- 微信支付平台收付通或其他合适产品的行业准入确认。
- 平台和运营主体商户关系。
- 平台 `15%` 佣金或分账能力。
- 运营主体 `85%` 收款、退款、回退、余额和账单能力。
- 车主付款能力、失败查询和对账能力。
- 支付手续费承担和退款时手续费处理。

未关闭影响：不能选择真实资金路径。

### 阻断 5：运营主体资金责任

需要明确：

- 运营主体余额不足时如何保障乘车人退款和车主付款。
- 运营主体拒绝付款、失联、注销或账户冻结时如何处理。
- 是否需要风险准备、保证责任或保险，以及其合法形式。
- 平台可以冻结哪些新业务能力，不能挪用哪些资金。

未关闭影响：多运营主体真实启用存在资金断裂风险。

### 阻断 6：生产密钥、商户号和权限

需要在申请后补充：

- 生产商户号和应用标识。
- 平台、运营主体和支付机构账户映射。
- 密钥托管、轮换、吊销和应急流程。
- 真实退款、分账、付款和对账的权限分离。

未关闭影响：真实资金门禁不能打开。

## 风险接受边界

不能接受：

- 把运营主体收到的 `85%` 全部视为运营主体自由资金。
- 从车主 `40%` 中扣除付款手续费。
- 从运营主体或车主份额中扣除平台支付手续费。
- 使用个人接收方直接分账但无法可靠退分账。
- 运营人员直接修改历史比例、订单主体、余额或付款成功状态。
- 用新订单资金长期填补旧订单退款或车主应付款。
- 因内部追偿失败无限期拖延乘车人合法退款。

可以在合成环境接受：

- 支付机构具体资金时序使用供应商中立状态模拟。
- 法定会计总额或净额使用双映射候选。
- 真实费率、商户号和结算周期保持未配置。

## 通过条件

- 六项阻断全部有书面证据。
- `docs/decisions/0014-平台服务费与多运营主体分成.md` 更新为 `已批准`。

- 财务负责人批准正式科目和会计映射。
- 税务负责人批准发票和代扣代缴。
- 法律负责人批准合同和运输责任。
- 支付机构书面确认真实产品能力和行业准入。
- 安全负责人批准生产密钥和资金权限。
- 最终决策人单独批准真实资金生产启用。
