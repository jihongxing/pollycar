# 产品语义与边界基线

本文档是产品定位、术语、用户表达和禁止能力的唯一真相源。

## 当前阶段

`阶段 0：产品语义、安全边界与架构决策`

## 核心语义

| 术语 | 定义 |
| --- | --- |
| 乘客 | 通过审核、发起符合运营规则行程的成年用户 |
| 车主 | 通过身份、车辆、安全与资格审核，可偶发自主接单的非职业私家车主 |
| 行程邀请 | 乘客发出的有限时、有限范围请求，不代表平台承诺履约 |
| 等单状态 | 车主主动进入、持续时间有限、到期自动退出的可接单状态 |
| 接受 | 一名合格车主对有效行程作出的明确履约承诺 |
| 固定价格 | 下单前明确展示、与个人属性和关系结果无关的行程价格 |
| 临时对话 | 行程完成后双方共同同意才开放、最长 72 小时且可提前永久关闭的沟通窗口 |
| 职业化风险 | 持续经营、收益优化、批量获客、商业导流或其他偏离偶发参与定位的行为信号 |

## 产品可以提供

- 车辆、车主、乘客身份和资格审核。
- 固定价格行程、有限订单展示、等单和自主接单。
- 接单前有限且必要的信息。
- 行程记录、安全工具、举报拉黑和人工处置。
- 行程后双方确认的 72 小时临时对话。
- 邀请码、候补、区域、时段和发单规模控制。

## 平台不判断的动机

平台不判断未表达且未形成违规行为的内心动机。用户可以因好奇、新鲜感、车辆体验、认识不同人群或希望交流而参与，但这些动机不得被平台定义为可购买、可排序或可保证的权益。

## 不得产品化的灰度

- 不按性别、年龄、外貌、身份或受欢迎程度筛选、排序或提高曝光。
- 不付费进入特定车主或乘客候选池，不付费提高被接受概率。
- 不建立魅力值、人气值、收藏、关注、粉丝或关系转化榜。
- 不出售更多照片、资料、联系方式、聊天权或延长对话时长。
- 不承诺“成功认识”“关系转化”或其他行程外结果。
- 不把互动质量、暧昧程度或关系结果纳入评价。

## 绝对红线

- 性交易、陪伴交易、约会服务或其他以利益交换亲密行为。
- 车主个人定价、乘客竞价、按时间购买陪同或关系权益。
- 强迫改变目的地、拒绝下车、限制人身自由。
- 酒驾、毒驾、危险驾驶、不合规车辆。
- 性骚扰、持续骚扰、偷拍、传播隐私。
- 未成年人参与。
- 线下加价、诱导取消平台订单、价格表、职业导流或批量商业获客。
- 因外貌不符进行羞辱式拒载。

## 内容与表达

可以使用：

- 固定费用行程、发出行程、等待回应。
- 车主正在等单、本次暂未成行、限量开放。
- 临时对话、城市体验、双方自主决定是否继续交流。

禁止使用：

- 认识新朋友、异性匹配、陪伴体验、高端社交。
- 优质人群连接、心动、邂逅、脱单。
- 豪车车主等你、更容易认识某类人。
- 购买聊天或联系方式、成功率、匹配率、关系转化率。

## 场景标签

首期允许：安静行程、轻松聊天、城市夜游、随意路线。

约束：

- 标签属于订单，不属于人物，只表达行程氛围。
- 标签不构成车主必须提供的互动服务。
- “随意路线”仍受区域、距离、时长和目的地规则约束。
- 不提供约会、陪伴、认识异性、高端社交等标签。
- 标签不改变价格或接单曝光。

## 评价边界

仅评价可验证的行程履约：准时、车辆一致、驾驶安全、规则遵守、卫生和基本礼貌。

不得评价外貌、吸引力、聊天趣味、继续认识意愿、暧昧体验、社会地位或经济能力。

## 功能决策硬检查

1. 以提高单位时间收益、持续经营能力或职业化接单效率为目标的功能，不做。
2. 把性别、外貌或身份变成排序变量的功能，不做。
3. 让付款被理解为购买某个人或关系结果的功能，不做。
4. 建立长期好友、关注、粉丝或私信资产的功能，不做。
5. 扩大灰度但降低平台控制能力的功能，不做。
6. 通过放宽审核、无限购买额度、逐单充值或提高收入承诺补足供给的功能，不做。
7. 改善真实行程、安全、自主选择或退出能力的功能，可以继续评估。

## 付费参与资格边界

平台可以评估“付费申请有限弹性参与资格”，但必须同时满足：

- 付费购买的是增强审核、持续资格评估和有限周期的参与资格，不是具体订单、乘客曝光或接单成功率。
- 支付不保证资格通过；未通过时不得保留未实际发生的服务费用。
- 资格不能逐单充值、无限续买、叠加购买或转让。
- 获得资格后仍受日、周、月滚动上限、等单限制、订单展示限制和职业化风控约束。
- 资格不得提高订单排序、乘客信息可见范围、接单成功优先级或单笔收入。
- 平台可因安全、履约、职业化或合规风险立即暂停资格，付费不能豁免处置。
- 在法律、税务、保险和“付费获得接单机会”的公平性评审完成前，不得上线。

## 冲突优先级

1. `AGENTS.md` 和 `ROADMAP.md` 定义工作方式与阶段边界。
2. 本文档定义产品语义和禁止边界。
3. 领域、接口、数据规范定义业务规则和可执行契约。
4. 交付文档定义配置、发布、回滚和运营要求。
5. 测试、迁移与脚本证明实现事实。

发现冲突时，必须在同一个变更单元中修正文档或实现。
