# 产品体验规格索引

本目录负责把产品定位、领域规则、状态机、权限、错误和机器契约翻译为可实现的功能、页面、交互流程和纵向产品切片。

## 产品形态

PollyCar 采用：

- 一个用户 App；
- 一个用户账户；
- 一个当前身份上下文；
- 可同时具备乘客身份和车主身份；
- 通过显式身份切换进入对应工作台；
- 一个独立的内部运营后台。

乘客与车主不是两个 App，也不是两个相互独立的账户。身份切换只改变当前工作上下文、导航、可见数据和允许操作，不合并资格、车辆、配额、订单责任或审计记录。

## 事实归属

- 产品定位和非目标仍以 `docs/00-product-thesis.md` 为准。
- 产品语义和禁止表达仍以 `docs/01-semantic-alignment.md` 为准。
- 业务规则仍以 `docs/04-domain-model.md` 为准。
- 状态和转换守卫仍以 `docs/09-state-machines.md` 为准。
- 权限和职责分离仍以 `docs/10-permission-matrix.md` 为准。
- 本目录只定义这些规则如何呈现为用户任务、页面、导航、交互和实现切片，不复制可变业务参数。
- 根目录 `DESIGN.md` 是 App 视觉、组件和交互设计唯一真相源。

## 维护规则

1. 新增用户可见功能前，必须先登记到功能地图和对应旅程。
2. 新增页面前，必须说明服务的用户任务和所属旅程。
3. 页面操作必须映射到权限、应用命令、成功事件、错误处理和验收场景。
4. 同一账户切换身份不得绕过对应身份的准入、资格、配额或安全限制。
5. 内部沙箱页面必须明确显示沙箱标识，并保持所有真实能力关闭。
6. 未形成纵向切片规格的功能，不得进入产品实现。
7. 运营后台必须先完成 `admin/` 设计和准入评审；结论未批准前不得创建后台工程代码。
