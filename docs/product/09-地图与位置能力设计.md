# 地图与位置能力设计

## 目标

御驾出行 · REGO 的地图能力只服务于真实出行主流程：

1. 乘车人准确确认上车点和目的地；
2. 车主自主接单后能够前往上车点；
3. 乘车人能够看到车辆位置和预计到达时间；
4. 行程双方能够理解路线、剩余距离和异常状态；
5. 安全与责任处理能够使用最小必要的位置证据。

地图不是独立工作台。产品页面不得向普通用户展示供应商名称、请求编号、坐标系、缓存状态或内部错误码。

### 商用许可与服务保障

- 高德将“技术服务许可”描述为企业开发者对外使用基础 LBS、基础地图定位和基础搜索服务所需获取的授权方案。
- 技术服务许可包含更高配额、合规资讯、安全与隐私检测、临时超限应急额度和服务可用性承诺。
- 公开页面显示基础版服务可用性不低于 99.95%，高级版不低于 99.99%；基础服务请求在高德服务器产生的平均响应中，99.5% 可控制在 300 毫秒以内。
- 正式商业运营前必须由法务和采购根据产品形态确认是否必须购买技术服务许可，不能把企业认证或免费额度视为永久商用授权。

### SDK 与 Expo 结论

- 高德官方提供 Android 地图、定位、导航和猎鹰 SDK。
- 高德官方提供 iOS 地图、定位、导航和猎鹰 SDK。
- 高德官方提供 Flutter 地图和定位插件。
- 官方文档未提供 React Native 或 Expo 插件。
- Android Key 绑定应用包名、调试 SHA1 和发布 SHA1；一个 Key 只能用于一个应用。
- iOS Key 需要绑定 Bundle Identifier。
- 地图 SDK 在调用任何接口前必须完成官方隐私展示和同意接口；否则可能白屏或调用失败。

因此 PollyCar 不直接依赖非官方 React Native 封装。推荐在 Expo Development Build 中建立自有最薄原生模块，分别包装官方 Android 和 iOS SDK；Web 预览继续使用合成地图或受限 JS 地图适配器。

## 产品范围

### 第一阶段：叫车选点

- 设备前台定位；
- 定位拒绝、超时和不可用恢复；
- 地图拖动选择上车点；
- POI 输入提示和关键词搜索；
- 逆地理编码；
- 家、公司和最近地点；
- 上车点与目的地确认；
- 起终点标记；
- 驾车路线预览；
- 距离和预计时间。

### 第二阶段：接驾

- 车主位置上传；
- 乘车人查看车辆最新位置；
- 车辆方向和更新时间；
- 前往上车点的路线与预计到达时间；
- 位置过旧、断网和后台切换恢复；
- 到达上车点和上车码联动。

### 第三阶段：履约

- 行程路线和剩余时间；
- 路线偏离提示；
- 到达目的地地理围栏；
- 滑动确认到达；
- 异常停车和定位中断提示；
- 最小位置证据与安全保留锁。

### 首期排除

- 自研地图、导航、路线规划、地址数据库、轨迹纠偏或交通算法；
- 永久保存完整行程轨迹；
- App 直接调用高德 Web 服务；
- 在客户端放置 Web 服务 Key；
- 未经前台授权持续后台定位；
- 在 Web 预览中处理真实位置。

## 架构

```text
App 页面
  ├─ MapPresentationAdapter：底图、标记、路线和视口
  ├─ DeviceLocationProvider：系统定位权限和位置
  └─ VehicleLocationPublisher：行程内位置上传
          ↓
Server 地图应用服务
  ├─ MapProvider：搜索、逆地理编码和路线规划
  ├─ MapCache：供应商结果短期缓存
  ├─ MapQuotaGuard：账户、设备、接口和供应商额度保护
  └─ VehicleLocationRepository：最新位置和最小轨迹事件
          ↓
SyntheticMapProvider / AmapWebServiceProvider
```

App 不感知业务层使用高德还是合成供应商。高德 Web 服务 Key 只允许保存在 Server 密钥系统中。

## 坐标规则

项目内部坐标必须显式携带坐标系：

```text
wgs84：设备或外部来源的全球坐标
gcj02：高德地图和中国大陆地图展示坐标
```

- 高德展示和高德 Web 服务统一使用 GCJ-02。
- 坐标转换只能经过统一 `CoordinateTransformer`。
- 禁止在页面、行程服务或 Repository 中散落转换公式。
- 每个坐标最多保留六位小数。
- 未标记坐标系的数据不得进入路线规划、位置展示或持久化。

## 地点模型

地点必须包含：

- 平台地点 ID；
- 可选供应商 POI ID；
- 名称和格式化地址；
- 城市、行政区和城市代码；
- 主坐标；
- 可选入口坐标；
- 地点类型；
- 来源；
- 可选置信度；
- 供应商和生成时间。

大型车站、机场、商场和小区应优先使用入口或上车区坐标，而不是 POI 中心点。

## 搜索与选点

- 输入两个字符后开始搜索；
- 防抖时间 350 毫秒；
- 以当前城市和当前位置作为搜索偏置；
- 单次最多返回 10 条；
- 相同查询、城市和位置网格命中 5 分钟缓存；
- 最近地点最多保存 10 条；
- 搜索失败时保留最近地点、家、公司和地图拖动选点；
- 逆地理编码失败时允许显示“地图选定位置”并提交上车说明。

## 路线规划

路线模型保存：

- 路线 ID；
- 起终点快照；
- 距离；
-基础耗时；
- 路况耗时；
- 编码折线；
- 生成和过期时间；
- 供应商；
- 是否包含实时交通。

同一行程阶段一分钟内不得重复刷新相同路线。路线失败不得伪造距离或预计时间。

## 实时车辆位置

| 阶段 | 建议上传间隔 |
| --- | --- |
| 未接单 | 不上传 |
| 已接单且距离较远 | 10–15 秒 |
| 接近上车点 | 3–5 秒 |
| 等待乘车人 | 5–10 秒 |
| 行程中 | 5–10 秒 |
| 后台、弱网或低电量 | 降频并允许有界批量补传 |
| 行程结束或取消 | 立即停止 |

位置载荷必须包含行程、账户、序列号、采集时间、坐标、精度、速度、方向和前后台状态。乘车人只能读取 Server 接受的最新位置。

位置超过 15 秒显示更新时间；超过 30 秒标记为陈旧；超过 60 秒不再作为实时车辆位置展示。

## 缓存和额度保护

| 能力 | 缓存或限制 |
| --- | --- |
| POI 输入提示 | 350 毫秒防抖；每用户每分钟最多 10 次 |
| POI 查询 | 相同查询缓存 5 分钟 |
| 逆地理编码 | 约 50 米坐标网格缓存 10 分钟 |
| 路线规划 | 同一起终点和策略缓存 60 秒 |
| 路线刷新 | 同一行程阶段至少间隔 60 秒 |
| 供应商软额度 | 月配额达到 70% 告警 |
| 供应商高风险额度 | 月配额达到 85% 限制非必要刷新 |
| 供应商硬额度 | 月配额达到 95% 进入降级模式 |

搜索免费额度低于基础 LBS，因此必须优先优化输入提示与搜索调用，不能只关注路线规划额度。

## 隐私和数据生命周期

- 家、公司属于敏感常用位置，必须加密存储、支持单项删除并禁止进入普通日志。
- 实时位置只保存最新值和短期更新窗口。
- 精确行程轨迹不得默认提供给运营人员。
- 安全案件可对必要位置证据施加保留锁，但不能无限延长普通位置数据。
- App 必须在初始化高德 SDK 前展示地图和定位处理说明，并调用官方隐私同意接口。
- 后台定位必须单独获得系统权限和产品必要性批准。

## 门禁

```yaml
real_map_enabled: false
external_map_provider_enabled: false
real_device_location_enabled: false
background_location_enabled: false
real_vehicle_location_stream_enabled: false
amap_sdk_enabled: false
amap_web_service_enabled: false
```

只有生产启用、真实数据接入、地图许可、隐私评估、Key 管理和位置生命周期全部批准后，真实地图门禁才可以开启。

## 高德接入顺序

1. 企业主体注册并完成高德企业认证；
2. 法务确认技术服务许可和服务条款；
3. 创建独立的 Android、iOS 和 Web 服务 Key；
4. Android 分离 debug 与 release SHA1；
5. iOS 绑定正式 Bundle Identifier；
6. Server 密钥系统保存 Web 服务 Key；
7. Expo Development Build 接入自有原生模块；
8. App 调用 SDK 前完成高德隐私接口；
9. 先接 POI、逆地理编码和路线规划；
10. 再接原生底图和行程内位置流；
11. 最后评审导航 SDK 和猎鹰轨迹服务是否必要。

## 验收

- 合成供应商和高德供应商可以在组合根切换，页面和领域模型不变；
- App 源码中不存在高德 Web 服务 Key；
- 坐标系缺失或错误时请求被拒绝；
- POI、逆地理编码和路线规划均有缓存、限流、超时和降级；
- 定位拒绝时仍可手动选择上车点；
- 车辆位置过旧时不会伪装为实时位置；
- 行程结束后停止位置上传；
- 真实地图门禁关闭时只允许合成数据；
- Android 和 iOS 在高德 SDK 初始化前完成隐私同意调用；
- 生产启用前取得商业授权、隐私和安全批准。

## 企业接入评审结论

2026 年 7 月 13 日已完成企业认证、商用授权、隐私影响和 Key 管理方案评审，结论为“有条件通过”：

- 允许继续实现和验证供应商中立适配器、Expo Development Build 原生壳及关闭态；
- 企业认证材料必须由实际企业主体在高德控制台提交，仓库不得虚构或保存认证原件；
- 对外商用前必须取得技术服务许可适用范围的书面确认，并在需要时购买有效许可；
- 精确位置与行踪轨迹按敏感个人信息处理，必须完成单独同意和个人信息保护影响评估；
- Web 服务 Key 只允许存在于 Server 密钥系统，Android、iOS 和 Web Key 必须分离；
- 七项真实地图与位置门禁继续保持关闭。
