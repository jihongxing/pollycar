# 阶段三实施前设计评审

## 评审结论

`产品、安全、隐私与工程设计通过；已批准默认关闭门禁后的合成代码实现`

阶段三已经形成唯一契约和六页高保真方案。最终决策人已于 2026-07-14 批准合成代码实现，所有能力必须置于默认关闭的 `synthetic_admin_trip_operations` 与 `synthetic_admin_case_management` 门禁后。

## 产品评审

通过：

- 工作入口从异常任务和案件出发，不从数据库表出发；
- 行程 360° 只读聚合权威状态；
- 客服案件只形成沟通、调查和升级动作；
- 安全案件突出冻结、调查、独立复核和应急阻断；
- 未知结果有独立恢复页，不诱导重复提交；
- 平台和运营主体使用同一案件事实，但接收不同的隔离视图。

不允许：

- 通用行程状态编辑器；
- 客服自由文本触发退款、安全恢复或资格恢复；
- 运营主体查看另一主体内部信息；
- 将“结果未知”展示为失败并提供“重新提交”。

## 安全评审

通过：

- 安全调查与客服职责分离；
- 冻结经办人与恢复复核人分离；
- `sev1`、`sev2` 明确应急、证据、资格和阻断检查；
- 证据访问绑定案件、工单、目的、字段和期限；
- 聊天原文、完整轨迹和导出要求双人批准；
- 紧急破窗最长十五分钟并要求事后复盘。

实现前仍需证明：

- 角色或组织上下文变化能实时撤销证据授权；
- 字段级读取和拒绝均进入追加式审计；
- 应用日志、指标和追踪不包含证据原文；
- 证据保全与数据删除冻结能够兼容。

## 隐私评审

通过：

- 默认遮蔽和最小必要披露；
- 客服、运营主体、技术运维均不能读取安全证据包；
- 运营主体协作任务不披露另一主体员工、联系方式或内部备注；
- 审计只记录字段标识、目的和结果，不记录原文；
- 合成实现明确拒绝真实聊天、真实轨迹和真实紧急联系人。

实现前仍需补充：

- 前端缓存、浏览器历史和复制行为的清理验证；
- 授权到期后的重新遮蔽测试；
- 导出文件加密、到期和下载审计设计。

## 工程评审

通过：

- 行程、安全、资格、通信和资金事实保持原权威来源；
- 阶段三只新增运营任务、客服案件、协作任务、证据授权和恢复任务；
- 所有领域动作通过明确命令、资源版本、请求摘要和幂等键；
- 未知结果通过原幂等结果、权威状态、审计和 Outbox 收敛；
- 技术恢复只确认技术事实，不形成业务结论。

实现前必须：

1. 复用阶段一服务端组织上下文、统一授权和追加式审计；
2. 复用阶段二行程运营主体快照与主体范围边界；
3. 为两个门禁分别证明默认关闭和依赖关系；
4. 使用唯一命令入口并禁止事务外自动提交；
5. 为跨主体隔离、职责分离、证据授权撤销和未知结果恢复编写 Server 测试；
6. 不直接包装既有应用服务为 CRUD 页面。

## 高保真页面

| 页面 | 核心任务 | 关键关闭态 |
| --- | --- | --- |
| 行程运营中心 | 分诊异常、创建协作、请求领域动作 | 直接修改行程状态关闭 |
| 行程 360° | 查看权威时间线、主体快照和关联案件 | 历史事实不可修改 |
| 客服案件详情 | 调查、沟通、等待和升级 | 安全证据与资金操作关闭 |
| 安全案件详情 | 调查、应急、证据保全和独立复核 | 阻断未清时恢复关闭 |
| 证据访问控制 | 字段级限时披露和撤销 | 完整原文与导出默认关闭 |
| 未知结果恢复 | 查询原请求并形成技术结论 | 重复提交和业务决定关闭 |

六页都必须覆盖：

- 内部合成环境；
- 功能关闭；
- 组织范围不匹配；
- 权限不足；
- 严格敏感字段遮蔽；
- 资源版本冲突；
- 未知结果；
- 桌面与移动无页面级横向溢出。
