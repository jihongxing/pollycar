# 运营后台交互与审计要求

## 操作层级

### 普通操作

示例：

- 调整筛选；
- 查看摘要；
- 保存非敏感草稿。

要求：

- 即时反馈；
- 不产生业务状态变化；
- 无需二次确认。

### 业务决定

示例：

- 要求补充；
- 批准；
- 拒绝；
- 升级；
- 释放任务。

要求：

- 结构化理由；
- 影响说明；
- 用户可见结果预览；
- 二次确认；
- 幂等键；
- 审计。

### 高风险操作

示例：

- 查看严格受限原文；
- 安全升级；
- 推翻原决定；
- 人工重放；
- 永久处置相关动作。

要求：

- 工单和目的；
- 限时权限；
- 独立角色；
- 更强确认；
- 不可修改的审计记录；
- 必要时双人批准。

## 决定栏

- 固定在详情页可见位置，但不遮挡材料。
- 只有任务所有者和状态允许时启用。
- 批准、拒绝和升级不得使用相邻且视觉相同的按钮。
- 默认主操作由当前任务状态决定，不永远突出批准。
- 键盘快捷键不得直接提交高风险决定。

## 理由

- 优先选择机器可识别的结构化原因。
- 自由文本只作补充，不替代结构化原因。
- 用户可见说明与内部说明分离。
- 内部说明不得包含无关敏感信息。
- 拒绝和升级必须展示用户是否可申诉或重新申请。

## 二次确认

确认面板展示：

- 当前申请；
- 当前任务所有权；
- 即将发生的状态变化；
- 用户可见文案；
- 影响的后续任务；
- 理由；
- 当前版本；
- 是否会触发通知或冻结。

确认后若版本变化，必须中止并显示最新状态。

## 并发与所有权

- 所有写操作携带任务和业务版本。
- 任务所有权丢失时，决定栏立即禁用。
- 并发错误显示是谁或什么系统改变了状态，但不得披露无权查看的信息。
- 重新加载后保留非敏感理由草稿，敏感原文不得缓存。

## 审计可见性

审核详情的审计摘要至少显示：

- 任务创建；
- 认领、释放和转派；
- 字段访问；
- 补充要求；
- 材料重新提交；
- 批准、拒绝和升级；
- 复核；
- 任务重试、死信和重放。

审计记录只读，不提供编辑和删除。

## 日志与可观测性

- 页面展示关联 ID，便于支持和排障。
- 不在前端日志记录材料原文。
- 未知结果状态使用关联 ID 查询后端命令结果。
- 性能指标不得演变为鼓励审核员快速批准的排名。
- 可以监控队列等待时间、错误率和重试率，但不得只以单位时间审核量评价质量。

## 可访问性

- 支持键盘完成列表浏览和普通表单操作。
- 焦点在列表、详情和确认层之间保持可预测。
- 状态不只依赖颜色。
- 遮蔽字段的读屏文案明确说明“内容已隐藏”。
- 弹层关闭后焦点返回触发位置。
- 高密度表格支持放大和横向适配，不强制固定小字号。
