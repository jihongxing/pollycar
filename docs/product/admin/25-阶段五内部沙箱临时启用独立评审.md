# 阶段五内部沙箱临时启用独立评审

## 评审结论

评审日期：2026 年 7 月 14 日；完整治理复验日期：2026 年 7 月 15 日。

技术控制结论：`APPROVED FOR TEMPORARY INTERNAL-SANDBOX ENABLEMENT`。

原独立评审确认的四项高风险阻断已全部关闭，阶段五控制达到单进程、本机回环、全合成数据内部沙箱的临时启用条件。预约 E2E 的固定服务端时间与真实浏览器时钟分裂问题已经修复，完整治理预检及全部 49 项 App E2E 均通过，临时启用暂停解除。

产品验收结论：`FULL ADMIN PRODUCT ACCEPTANCE FAILED`。

2026 年 7 月 15 日人工验收确认，当前运营控制台仍属于内部能力验证台，不具备完整运营后台的产品可用性，主要缺口为：

- 缺少后台账号邀请激活、登录、会话恢复和工作身份选择；
- 平台用户与运营公司用户的组织范围和产品入口尚未形成完整闭环；
- 角色菜单隔离不完整，部分角色会看到不属于其职责的菜单；
- 列表缺少统一服务端分页、搜索、筛选和排序能力；
- 页面存在过多技术、治理和实现门槛术语，不符合普通运营人员的产品表达。

因此阶段五当前状态固定为：

> 技术控制验收通过，但完整运营后台产品验收未通过。

阶段五门禁可以继续用于受控内部沙箱问题盘点和重构验收，但不得将技术控制通过解释为运营后台已经具备正式运营可用性。完整产品验收必须等待账号登录、组织角色、菜单隔离、分页列表、信息架构和产品文案重构全部完成。

本结论不改变默认配置。门禁继续保持：

```yaml
synthetic_admin_executive_dashboard: false
```

每次临时启用必须显式开启阶段一至阶段四依赖、指定隔离状态目录，并在验收结束后关闭门禁。不得将本结论解释为允许生产启用、真实数据接入、多进程部署或外部网络访问。

## 阻断关闭证据

### 1. 门禁依赖已端到端失败关闭

Server 的 `resolveFeatureGates` 现在使用阶段一至阶段四门禁的解析后结果。以下任一条件不满足时，阶段五强制解析为关闭：

- `internalSandbox`；
- `syntheticAdminMultiOrganization`；
- `syntheticAdminOperatorManagement`；
- `syntheticAdminTripOperations`；
- `syntheticAdminCaseManagement`；
- `syntheticAdminFinanceOperations`；
- `syntheticAdminExecutiveDashboard`。

Admin Shell 同样要求阶段一至阶段四前端门禁全部开启后才显示阶段五入口。专项测试覆盖任一依赖关闭和全部依赖开启两类结果，未发现只开阶段五即可绕过依赖的路径。

### 2. 治理状态、幂等结果和审计已持久化

阶段五启用时必须显式提供本机隔离状态目录，否则启动失败并返回 `ADMIN_EXECUTIVE_STATE_DIR_REQUIRED`。

隔离目录内持久化：

- 追加式高层意见；
- 导出申请、审批、撤销、下载和过期状态；
- 幂等键、请求摘要、执行身份和原结果；
- 阶段五授权与治理审计事件。

状态文件采用临时文件写入后原子替换。主动重启验证确认：

```text
重启前意见数量：1
重启后意见数量：1
相同幂等键重放：返回原意见
第二笔意见：未产生
历史专项审计：可恢复
```

损坏或不可解析的状态文件会使阶段五启动失败，不会回退为空状态继续运行。

### 3. L3 精确金额已独立授权并专项审计

`finance_lead` 读取资金安全页时先执行 `admin_executive.finance.read`，返回精确聚合金额前再独立执行：

```text
admin_executive.finance.amount.read
```

该授权固定要求：

- `finance_lead`；
- 平台组织上下文；
- 独立访问决定；
- 独立追加式审计。

项目决策人和运营主体负责人继续只读取 `L2` 状态、区间和趋势。专项测试确认 L3 响应中存在精确金额，并存在同一访问主体的 `admin_executive.finance.amount.read` 允许审计。

### 4. 导出关账与真实加密临时存储已落地

资金导出申请会先读取服务端权威资金事实：

- 资金期间未关账时拒绝并返回 `ADMIN_EXECUTIVE_UNCLOSED_DATA_RESTRICTED`；
- 任一关键来源读取失败时返回 `SERVICE_UNAVAILABLE`；
- 不会先创建申请再异步补做关账判断。

导出文件只在隐私复核和职责域复核全部批准后生成，使用 `AES-256-GCM` 加密写入隔离目录。密文文件包含随机初始化向量和认证标签，测试确认原用途文本不能直接从文件读取。

批准文件的生命周期为：

```text
批准
→ 写入加密文件
→ 最长保留 30 分钟
→ 下载时解密
→ 返回内容前删除密文
→ 状态持久化为 downloaded
```

撤销和到期均删除密文。服务重启后会恢复批准状态、密钥和密文文件；重复下载被拒绝，不会重新生成第二份文件。

## 临时启用约束

临时启用必须同时满足：

1. Server 与 Admin 的阶段一至阶段五合成门禁全部显式开启；
2. `POLLYCAR_EXECUTIVE_STATE_DIR` 指向本机专用隔离目录；
3. Server 仅绑定 `127.0.0.1`，允许来源仅包含本机验收地址；
4. 只使用合成身份、合成经营事实和合成资金事实；
5. 只运行单个 Server 进程，不共享状态目录给第二个进程；
6. 真实组织账号、真实经营数据、真实资金、真实支付和生产启用继续关闭；
7. 验收结束后关闭阶段五门禁，并按测试批次保留或受控清理隔离证据。

## 残余风险

| 风险 | 级别 | 是否阻断本次临时启用 |
| --- | --- | --- |
| 本机文件状态库不支持多进程并发写入 | 中 | 否；本次限定单进程 |
| 加密密钥为本机隔离文件，不是生产级 KMS/HSM | 中 | 否；本次仅含合成数据 |
| 文件权限依赖本机操作系统账户边界 | 中 | 否；本次限定受控开发机 |
| 未执行真实数据、真实资金或生产网络验证 | 高 | 否；这些能力明确不在批准范围 |

| 真实数据与生产启用关闭 | 已满足 | 否 |

以上残余风险在内部沙箱临时启用范围内可接受，但在任何共享部署、多进程运行、真实数据接入或生产启用前均必须重新设计并独立评审。

## 失效条件

出现以下任一情况，本批准立即失效：

- 任一阶段一至阶段四依赖门禁关闭；
- 未提供或无法读取隔离状态目录；
- 状态文件或加密密钥损坏；
- 启动第二个共享同一状态目录的 Server 进程；
- 接入真实组织、真实经营、真实资金或真实个人数据；
- 绑定非回环地址或扩大到未批准来源；
- 修改授权、数据分级、导出审批或关账契约。
