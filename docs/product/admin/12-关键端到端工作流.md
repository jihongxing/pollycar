# 运营控制台关键端到端工作流

## 通用流程规则

所有流程必须具备：

- 明确触发事件；
- 任务队列和所有权；
- 状态守卫；
- 结构化理由；
- 数据披露范围；
- 幂等键和资源版本；
- 经办与复核；
- 成功、失败和未知结果；
- 审计和用户通知；
- 超时、转派和恢复路径。

## 流程一：运营主体入驻到激活

```text
创建入驻案件
→ 提交主体资料和城市范围
→ 资料完整性检查
→ 法务、运营、财务和安全并行审核
→ 商户、结算和付款能力检查
→ 风险与未决事项汇总
→ 平台经办提交激活建议
→ 独立负责人复核
→ 合成激活或保持关闭
```

关键控制：

- 未完成外部法律、支付或资质结论时只能进入合成关闭态；
- 单一部门不能独立激活主体；
- 激活不自动开放真实清算和付款；
- 所有资料变更保留版本和冷静期。

## 流程二：车主加入主运营主体到可接单

```text
车主提交申请
→ 车辆和资格审核
→ 运营主体确认管理关系
→ 平台校验城市、车辆和主体能力
→ 创建唯一主运营关系
→ 资格和配额生效
→ 安全限制检查
→ 获得合成接单资格
```

异常路径：

- 已存在有效主运营关系；
- 车辆已绑定其他有效车主；
- 主体暂停或城市未开放；
- 资料待补充；
- 安全案件未关闭；
- 迁移尚未到生效时间。

## 流程三：异常行程到客服闭环

```text
行程异常或用户报障
→ 创建客服案件
→ 关联行程时间线和必要摘要
→ 判断运营、费用或安全类别
→ 普通客服处理
→ 必要时升级运营、安全或财务
→ 形成责任和恢复动作
→ 预览用户通知
→ 完成案件并记录审计
```

客服不得：

- 自行修改行程历史；
- 直接核销资金差异；
- 查看无关聊天和位置原文；
- 用自由文本代替退款或安全任务。

## 流程四：安全事件到恢复访问

```text
安全告警或举报
→ 创建安全案件
→ 临时冻结和证据保全
→ 申请必要证据访问
→ 安全人员调查
→ 形成安全结论
→ 独立安全负责人复核
→ 维持限制或恢复访问
→ 通知相关业务域
→ 重大事件复盘
```

恢复访问不能由原冻结经办人单独完成。安全案件关闭不自动修改审核、客服或资金结论。

## 流程五：资金分配到运营主体清算

```text
支付最终成功且行程责任确定
→ 锁定可分配金额
→ 对账批次关闭
→ 固定 15%/45%/40% 分配过账
→ 生成运营主体清算候选
→ Server 汇总 85% 清算批次
→ 财务经办检查
→ 独立复核
→ 合成提交和结果查询
→ 成功、失败或未知恢复
→ 下一对账批次核对
```

任意非零差异、未解决案件、重复分配项或无效主体账户都必须阻止清算。

## 流程六：T+1 车主付款到对账关账

```text
资金分配入账日 T
→ T+1 生成车主付款候选
→ 校验清算、账户、冷静期和冻结
→ 12:00 前生成付款批次
→ 财务经办检查
→ 独立复核
→ 18:00 前合成提交
→ 处理中、成功、失败或未知
→ 记录运营主体承担的付款手续费
→ 四方对账
→ 解决全部差异
→ 双人日终关账
```

关键控制：

- 车主应付款不能被手续费减少；
- 未知状态只查询原请求；
- 提前结算保持关闭；
- 付款成功必须具备账本交易和对账事实；
- 未解决差异阻止付款和关账。

## 跨流程升级关系

| 来源流程 | 升级目标 | 场景 |
| --- | --- | --- |
| 主体入驻 | 合规或高层待决 | 外部责任未明确 |
| 主运营关系 | 平台运营 | 关系冲突或迁移争议 |
| 客服案件 | 安全 | 人身、骚扰或证据风险 |
| 客服案件 | 财务 | 退款、重复扣款或金额争议 |
| 安全案件 | 运营 | 主体或车主暂停 |
| 对账差异 | 资金案件 | 未知、孤立资金或资金不足 |
| 付款逾期 | 风险合规 | 限制或暂停运营主体 |
