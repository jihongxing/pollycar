# 阶段四实施前设计评审

## 评审结论

`设计通过；已批准在默认关闭门禁后进入合成代码实现`

评审日期：`2026-07-14`

评审依据：

- `docs/decisions/0013-真实资金架构与复式账本.md`
- `docs/decisions/0014-平台服务费与多运营主体分成.md`
- `docs/decisions/0018-运营控制台资金运营与职责分离.md`
- `docs/product/admin/21-阶段四资金运营契约.md`
- `spec/admin/finance-operations.yaml`

## 产品评审

通过：

- 七页覆盖分配、清算、付款、退款、冲正、对账、资金案件、关账和账本查询；
- 每页从财务任务出发，不从数据库表或 Repository 出发；
- 金额、比例、余额和可执行状态均为 Server 只读事实；
- 未提供钱包、余额编辑、任意记账或提前结算入口；
- 未将阶段五高层驾驶舱提前并入阶段四。

## 财务与会计评审

通过：

- 后台不改变 `15%/45%/40%`、尾差、手续费承担和历史快照；
- 退款与完整冲正保持独立交易，原记录不可覆盖；
- 账本查询不构成手工总账工具；
- 非零差异同时阻止清算、付款和关账；
- 资金案件不形成余额事实。

保留条件：

- 真实收入确认、发票、税务和法定付款责任仍需书面结论；
- 真实资金能力不因后台设计通过而获准。

## 权限与安全评审

通过：

- 平台与运营主体资金范围分离；
- 平台财务、运营主体财务、审计和技术运维没有通用管理员角色；
- 经办人与复核人必须不同；
- 组织上下文切换不能规避职责分离；
- 收款引用、商户标识和账本字段按数据等级披露；
- 受控导出需要目的、范围、时限和双人批准。

## 隐私评审

通过：

- 页面不展示完整银行卡、支付凭据、法人证件或税务原文；
- 车主付款列表默认脱敏；
- 运营主体不能看到其他主体车主、付款或案件；
- 审计不记录完整收款信息或导出原文。

## 工程评审

通过：

- 唯一命令入口已冻结；
- 未来实现必须复用阶段一组织上下文和统一授权；
- 只调用已完成的账本、对账和资金编排内核；
- 不允许新建影子余额、替代对账或重复资金状态机；
- 幂等摘要冲突、资源版本冲突和未知结果均有固定恢复路径；
- 前端禁用不能替代 Server 与数据库拒绝。

## 高保真验收范围

| 页面 | 主要角色 | 核心验收 |
| --- | --- | --- |
| 资金运营中心 | 平台财务 | 阻断优先、待复核、未知结果与资金案件统一队列 |
| 分配与清算 | 平台财务、运营主体只读 | 比例只读、跨主体隔离、对账阻断 |
| 车主付款 | 运营主体财务 | `T+1`、双人复核、手续费不减车主应付款 |
| 退款与冲正 | 平台财务 | 引用原记录、无负数支付、无任意分录 |
| 对账与资金案件 | 平台／本主体财务 | 四方事实、差异证据、独立复核 |
| 日终关账 | 平台财务 | 全部运行关闭、零差异、双人关闭 |
| 账本查询 | 财务、审计、本主体财务 | 只读、脱敏、组织过滤、无编辑入口 |

## 阻断项

以下任一项未完成，不得进入代码实现：

1. `spec/admin/finance-operations.yaml` 和场景 Schema 未通过；
2. 财务角色、授权动作和禁止组合未冻结；
3. 错误码未覆盖越权、职责冲突、对账阻断、未知结果和余额修改；
4. 七页高保真未完成桌面与 390px 验收；
5. 默认关闭门禁或三项资金依赖未被机器检查；
6. 未获得新的“批准进入阶段四合成代码实现”指令。

## 当前决定

阶段四合成代码实现已于 `2026-07-14` 获得明确批准。允许新增阶段四合成模块、内部沙箱 HTTP 路由和七页工作区；`synthetic_admin_finance_operations` 保持默认关闭，真实资金接入和生产启用继续禁止。
