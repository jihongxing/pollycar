## 阶段范围

阶段二只包含：

- 运营主体档案与生命周期；
- 运营主体入驻案件；
- 城市与能力授权；
- 运营主体 360°；
- 车主 360°；
- 车辆 360°；
- 主运营关系列表、历史和受控迁移；
- 现有资格、配额和车辆审核事实的聚合与跳转。

不包含：

- 真实运营主体、真实材料或真实账号；
- 行程状态操作、客服案件处置和安全案件调查；
- 清算、付款、退款、冲正、对账解决或余额修改；
- 高层驾驶舱；
- 生产启用。

## 运营主体生命周期

固定状态：

```text
候选
→ 入驻审查
→ 待激活
→ 运营中
→ 受限
→ 暂停
→ 退出处理中
→ 已退出
```

规则：

1. 所有状态变化使用明确命令和追加式状态事件。
2. `候选` 不能直接进入 `运营中`。
3. 入驻通过只进入 `待激活`。
4. 至少一项有效城市能力是进入 `运营中` 的必要条件。
5. `受限` 禁止新增车主、车辆和主运营关系。
6. `暂停` 禁止新的运营活动，但保留历史查询、案件和退出任务。
7. `退出处理中` 必须关闭未完成关系、任务、案件和资金阻断。
8. `已退出` 不可恢复；重新合作必须新建档案。

限制、暂停、恢复和退出均要求经办与复核分离。

## 入驻案件

固定状态：

```text
草稿
→ 已提交
→ 审查中
→ 待补充
→ 待独立复核
→ 已通过／已拒绝／已取消
```

必需检查组：

- 主体身份摘要；
- 遮蔽联系人摘要；
- 申请城市与能力；
- 运营责任；
- 数据处理准备度；
- 安全协作准备度；
- 车主与车辆治理准备度。

固定决定：

- `approve`：通过并进入 `pending_activation`；
- `request_changes`：请求补充并保留案件；
- `reject`：拒绝并关闭案件。

同一候选主体同一时间最多存在一个未关闭入驻案件。经办人不能复核自己的建议。

## 城市与能力

能力必须按“运营主体 + 城市 + 能力”明确授权：

- `driver_operations`：车主关系和运力任务；
- `vehicle_operations`：车辆关系和证照任务；
- `trip_coordination`：行程协作，只在阶段三实现操作；
- `support_coordination`：客服协作，只在阶段三实现操作；
- `safety_collaboration`：安全协作，只在阶段三实现操作。

状态固定为：

```text
待生效／有效／受限／暂停／已到期／已撤销
```

禁止通配城市、全国范围、“全部能力”和运营主体自行授权。每次授权、限制、暂停、恢复、到期和撤销均保留历史。

## 360° 页面

### 运营主体 360°

必须包含：

- 主体摘要与当前生命周期；
- 城市能力矩阵；
- 入驻案件和状态历史；
- 车主、车辆和任务摘要；
- 风险与阻断；
- 账本与资金只读关闭态。

不得包含：

- 法定证件、银行账户和完整联系人原文；
- 通用编辑主体表单；
- 资金余额编辑；
- 绕过案件的生命周期按钮。

### 车主 360°

必须聚合：

- 合成账户摘要和服务状态；
- 资格、配额和限制；
- 当前及历史主运营关系；
- 关联车辆；
- 行程和案件引用；
- 严格敏感字段遮蔽状态。

运营主体人员只能查看本主体当前或任务明确关联的车主。平台角色必须处于显式主体和城市范围。

### 车辆 360°

必须聚合：

- 合成车辆摘要；
- 车辆审核状态与版本；
- 当前有效车主关系；
- 证照到期摘要；
- 行程和案件引用；
- 返回既有车辆审核任务的入口。

车辆 360° 不提供第二套审核决定或状态修改。

## 主运营关系

唯一范围：

```text
driver_account_id
× city_code
× vehicle_id
```

同一范围只能存在一个有效主运营关系。历史关系只允许结束，不允许改写运营主体、开始时间或既有行程快照。

## 受控迁移

固定状态：

```text
草稿
→ 检查中
→ 待来源主体确认
→ 待目标主体确认
→ 待独立复核
→ 已安排
→ 已生效
```

终止状态：

- 已取消；
- 已拒绝。

迁移必须同时满足：

- 来源主体和目标主体不同；
- 目标主体具备对应城市的车主与车辆能力；
- 车主资格和车辆审核处于可服务状态；
- 无同范围未关闭迁移；
- 无进行中行程；
- 无未完成安全移交；
- 无未解决非零对账差异；
- 无未知付款结果或阻断资金案件；
- 资源版本未变化；
- 经办、来源确认、目标确认和独立复核满足职责分离；
- 安排未来生效时间。

生效动作必须在一个数据库事务中：

1. 结束旧关系；
2. 建立新关系；
3. 追加迁移状态事件；
4. 追加审计事件。

生效后不得回滚历史；反向变更必须新建迁移案件。

## 审计要求

必须追加记录：

- 运营主体、车主和车辆 360° 查看；
- 严格敏感字段披露；
- 入驻案件认领、决定和复核；
- 生命周期变化提议和复核；
- 城市能力变化；
- 迁移创建、检查、双方确认、复核、安排、生效、取消和阻断；
- 所有允许与拒绝授权判定。

审计不得记录严格敏感原文。

## 默认关闭门禁

```yaml
synthetic_admin_multi_organization: false
synthetic_admin_operator_management: false
real_admin_organization_accounts: false
production_admin_enabled: false
```

`synthetic_admin_operator_management` 必须依赖内部沙箱和阶段一多组织底座。门禁关闭时继续使用阶段一只读名录，不显示阶段二写操作或深链接。

## 实现前禁止项

在独立准入评审通过前不得：

- 新增阶段二 HTTP 路由；
- 新增阶段二应用服务或 Repository；
- 新增运营主体管理数据库迁移；
- 修改阶段一 Shell 导航以暴露阶段二模块；
- 将既有资金编排服务包装为后台迁移接口；
- 用前端状态模拟生命周期或迁移成功。
