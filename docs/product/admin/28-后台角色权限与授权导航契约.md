# 后台角色权限与授权导航契约

## 文档状态

- 实施批准日期：`2026-07-15`

- 机器契约：`spec/admin/role-access-matrix.yaml`
- 默认门禁：`synthetic_admin_role_access_matrix=false`

## 核心原则

1. 平台工作身份不等于全权限；
2. 运营公司工作身份固定为本公司；
3. 功能角色与组织范围正交；
4. 菜单、路由、操作、字段、导出和 API 使用同一服务端判定；
5. 无权菜单隐藏，深链接与 API 仍必须拒绝；
6. 不存在超级管理员；
7. 审计和技术运维均不能执行普通业务决定。

所有运营公司角色的 `operator_id` 固定；任何菜单、列表、搜索、详情、操作或导出都不得接受可扩大范围的运营公司参数。

## 操作包

操作权限不直接从菜单继承，固定使用以下操作包：

- `identity_access_governance`：邀请、成员关系、角色申请、会话撤销；
- `operator_governance`：入驻、生命周期、城市能力和迁移；
- `fleet_review`：车主车辆查询、审核和复核；
- `trip_operations`：运营任务和行程领域命令申请；
- `support_case_management`：客服案件；
- `safety_investigation`：安全调查、恢复复核和证据；
- `finance_operations`：分配、清算、付款、退款、冲正、对账和关账；
- `analytics_read`：去标识报表；
- `executive_read`：高层聚合、钻取和意见；
- `audit_read`：追加式审计只读；
- `technical_recovery`：原请求结果查询、死信和受控恢复。

每个操作包只包含机器规范明确列出的动作；菜单可见不能推导操作包，操作包也不能推导额外组织范围。

## 字段规则

- L4 字段默认不返回；
- 只有已分配审核、已关联安全案件或隐私法律案件才能申请 L4 最小字段；
- 运营公司人员永远不能读取其他公司内部备注、人员身份、安全推理、原始聊天或完整位置轨迹；
- 财务角色可以读取授权范围内精确金额，但完整付款凭据、完整银行账号和平台密钥永远禁止；
- 高层和数据分析只读取去标识聚合，不读取人员排名或严格敏感原文；
- 技术运维只读取技术元数据，不读取业务正文；
- 审计读取事件引用、决策、范围摘要和控制证据，不默认读取业务秘密原文。

## 导出规则

- 没有专门导出档位即禁止导出；
- 申请、批准、生成、下载和撤销均需严格审计；
- 导出条件不得超出当前页面组织范围；
- 导出字段不得多于当前字段档位；
- 资金导出必须满足对账与关账要求；
- 安全证据和高层导出继续复用既有双人批准规则；
- 运营公司导出只包含本公司；
- 导出文件短期加密存储、单次下载、到期删除。

## 路由与拒绝体验

- 服务端只返回授权菜单；
- 前端路由守卫使用服务端路由权限，不使用角色名称硬编码；
- 无菜单权限的直接路由返回统一无权限页；
- 无资源范围的深链接返回不泄漏资源存在性的通用结果；
- 浏览器返回、刷新和新标签页必须重新校验；
- 角色或作用域变化后旧导航清单和旧会话失效。

## 实施门禁

当前允许维护设计、机器契约和测试；禁止新增导航接口、角色菜单代码、路由守卫或权限组件实现。进入实现必须获得单独批准，并继续保持所有真实账号和生产门禁关闭。
