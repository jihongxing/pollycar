# 运营后台产品规格索引

本目录定义 PollyCar 多组织运营控制台的产品目标、角色任务、信息架构、能力地图、领域实体、关键流程、敏感数据披露、页面状态、高层驾驶舱和实施门禁。

## 当前状态

`阶段一至阶段五技术控制已完成；完整运营后台产品验收未通过，当前进入产品化重构实施前设计`

当前允许：

- 产品规格；
- 信息架构；
- 用户流程；
- 低保真和高保真设计参考；
- 权限、安全、隐私和工程评审；
- 机器映射设计。
- 按 `14-实施阶段与功能门禁.md` 拆分后续纵向实施包。
- 维护和验证阶段一多组织后台底座的合成实现。
- 维护和验证阶段二组织与运力模块的合成实现。
- 维护和验证阶段三行程、客服和安全模块的实施前契约与高保真设计。
- 在 `synthetic_admin_trip_operations` 与 `synthetic_admin_case_management` 默认关闭门禁后实施阶段三合成代码。
- 维护和验证默认关闭门禁后的阶段四资金运营合成应用服务、唯一命令入口和七页工作区。
- 维护和验证阶段五高层驾驶舱技术控制、机器契约、验收场景和六页工作区。
- 设计后台邀请激活、登录、组织身份、角色权限、服务端授权导航、统一分页列表和产品化语言。

当前仍禁止：

- 未经明确阶段批准实施完整后台新模块；
- 未经阶段批准实现行程、客服、安全、资金或高层驾驶舱新增模块；
- 未经新的明确批准实现阶段五高层驾驶舱运行时、HTTP API 或 Admin 页面；
- 在账号、会话和权限契约批准前实现新增后台认证代码；
- 在服务端导航和角色权限矩阵批准前继续扩展硬编码菜单；
- 在统一分页契约批准前为各业务页面分别实现分页；
- 一次性创建全权限后台 Shell 或通用管理员角色；
- 未更新角色、权限和组织契约就添加后台 HTTP 路由；
- 接入真实用户或真实车辆材料；
- 将 Server 应用服务直接包装为 CRUD 页面；
- 因 Server 能力已存在而默认批准后台实现。
- 因高层职级绕过职责分离或敏感数据限制；
- 为运营主体建立独立余额、钱包或影子资金事实源。

## 事实归属

- 角色权限和职责分离以 `docs/10-permission-matrix.md` 为准。
- 数据等级和处理要求以 `docs/11-data-classification.md` 为准。
- 错误语义以 `docs/12-error-model.md` 为准。
- 验收场景以 `docs/13-acceptance-matrix.md` 为准。
- 车辆审核状态以 `spec/domain/vehicle-review.yaml` 为准。
- 运营主体生命周期、城市能力和迁移边界以 `spec/admin/operator-management.yaml` 为准。
- 主运营关系事实以 `spec/finance/operator-funds.yaml` 和 `pollycar_finance.driver_operator_memberships` 为准。
- 行程、客服、安全、证据和恢复边界以 `spec/admin/trip-case-management.yaml` 为准。
- 资金运营后台边界以 `spec/admin/finance-operations.yaml` 为准，资金事实仍以 `spec/finance/` 为准。
- 高层驾驶舱边界以 `spec/admin/executive-dashboard.yaml` 为准，所有经营、资金和风险事实仍归原领域所有。
- 后台账号、邀请、MFA、会话和工作身份边界以 `spec/admin/authentication-session.yaml` 为准，业务授权继续由阶段一权限事实源判定。
- 后台角色目录、授权导航、字段、导出和组织范围矩阵以 `spec/admin/role-access-matrix.yaml` 为准。
- 后台产品化入口、Shell、分页和产品语言体验以 `spec/admin/admin-product-experience.yaml` 为准。
- 本目录只负责把这些规则翻译为后台任务、导航、页面和交互，不另行修改业务规则。

## 维护规则

1. 后台功能必须从内部角色的任务出发，不从数据库表或 Server 方法出发。
2. 每个页面操作必须映射权限、状态守卫、字段披露、理由、审计和错误处理。
3. 敏感原文默认隐藏，访问必须具备目的、工单和审计。
4. 平台人员、运营主体人员、高层、审核、安全、财务、审计和技术运维不得共享无差别管理员角色。
5. 现有车辆审核高保真设计和首个实施切片已经完成；新增模块必须按阶段重新设计和验收。
6. 任何实现批准只适用于明确的纵向切片，不自动批准完整后台。
7. 运营主体数据范围必须由 Server 和数据库边界共同约束，不能只依赖前端筛选。
8. 资金页面只能展示账本、对账和资金编排事实，不得维护独立余额。
