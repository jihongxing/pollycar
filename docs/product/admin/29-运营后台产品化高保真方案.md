## 设计目标

本方案把账号、会话和权限矩阵转化为可直接实施和验收的运营后台体验，解决五个问题：

1. 后台人员如何被邀请、激活、登录和恢复；
2. 一个自然人如何确认当前平台或运营公司工作身份；
3. 服务端如何向不同角色签发不同菜单与路由权限；
4. 增长型列表如何统一分页、搜索、筛选和恢复；
5. 普通页面如何使用业务语言，而不是内部技术语言。

本方案已获准在默认关闭门禁后进入认证、导航、分页和页面运行时代码实现；真实账号、真实数据和生产启用继续禁止。

## 信息架构

全局一级导航固定为：

```text
工作台
组织与账号
运营公司
车主与车辆
行程运营
客服与安全
资金运营
数据与报表
高层驾驶舱
审计与系统
```

服务端只返回当前工作身份获准的一级菜单和子页面。前端不根据角色名称拼装菜单，也不展示无权入口后再让用户点击报错。

## 账号入口

### 登录

登录页只展示：

- 工作邮箱；
- 密码；
- 继续按钮；
- 忘记密码；
- 邀请激活入口；
- 帮助与安全说明。

密码验证通过后进入 TOTP 页面，在 MFA 完成前不签发业务会话。错误信息统一使用“邮箱、密码或账号状态无法通过验证”，不披露账号是否存在。

### 邀请激活

流程固定为：

```text
验证邀请
→ 确认组织与初始角色
→ 设置密码
→ 登记 TOTP
→ 保存恢复码
→ 激活完成
```

激活页只确认组织和角色摘要，不允许受邀人修改角色或组织。

### 工作身份选择

存在多个有效成员关系时，按两组展示：

- 平台工作身份；
- 运营公司工作身份。

每张身份卡只显示组织、产品角色、授权城市摘要和最近使用时间。身份选择成功后由服务端签发新会话；切换身份不修改前端本地状态冒充服务端授权。

## 全局 Shell

### 顶栏

持续显示：

- 御驾出行运营工作台；
- 当前工作身份；
- 当前组织；
- 当前城市或运营公司范围；
- 通知；
- 帮助；
- 个人与会话菜单。

普通页面不显示功能门禁名、内部用户标识、数据等级编码、端口或服务端实现名称。

### 侧边栏

- 只渲染服务端授权导航清单；
- 以业务域分组，不按阶段或技术模块分组；
- 一级菜单可折叠，当前页面和待办数量清晰；
- 运营公司用户不显示跨主体选择器；
- 平台人员的观察范围切换只能缩小到已授权范围，不改变角色。

### 页面标题区

固定包含：

- 页面名称；
- 一句任务说明；
- 当前组织范围摘要；
- 主操作；
- 必要的状态或阻断提示。

## 角色工作台

高保真方案覆盖：

- 平台运营工作台；
- 运营公司运营工作台；
- 客服工作台；
- 安全工作台；
- 财务工作台；
- 高层工作台；
- 审计工作台。

工作台只展示该角色需要处理的待办、风险、等待复核、未知结果和最近操作。高层与审计工作台保持只读，技术运维只展示运行恢复任务。

## 服务端授权导航

导航清单固定返回：

```text
navigation_version
work_identity_id
organization_context
role_ids
items
route_permissions
operation_permissions
field_profiles
export_profiles
scope_digest
expires_at
```

页面行为：

- 清单签发失败：进入“暂时无法加载工作权限”状态；
- 无菜单权限：不显示菜单；
- 手工输入无权路由：显示统一无权限页；
- 资源越权：不披露资源是否存在；
- 角色或范围变化：旧会话和旧清单失效，返回身份确认页；
- 页面刷新、新标签页和浏览器返回：重新执行路由授权。

## 统一列表与分页

### 请求契约

增长型列表统一使用游标分页：

```text
page_size
after
before
search
filters
sort
```

规则：

- 默认 `page_size=25`；
- 允许 `25`、`50`、`100`；
- 最大 `100`；
- `after` 与 `before` 不能同时出现；
- 游标由服务端签名，不透明且绑定查询摘要与组织范围摘要；
- 默认排序必须包含稳定唯一键作为最后排序项；
- 搜索、筛选或排序变化后清空旧游标；
- 不允许客户端请求精确总数作为分页前提。

### 响应契约

```text
items
page_info.has_next_page
page_info.has_previous_page
page_info.start_cursor
page_info.end_cursor
page_info.approximate_total
query_digest
scope_digest
as_of
```

`approximate_total` 可为空。资金、审计和高敏感列表默认不返回精确总数，避免昂贵查询和范围侧信道。

### 页面交互

- 首次加载使用骨架屏；
- 搜索采用提交式搜索，不在每个字符输入时自动请求；
- 筛选条件以可移除标签展示；
- 排序只允许服务端白名单字段；
- 返回列表恢复搜索、筛选、排序、游标和滚动位置；
- 数据变化导致游标失效时，提示“列表内容已更新”，从首屏重新加载；
- 批量选择只作用于当前明确选中的记录，不提供“选择全部结果”；
- 导出使用当前服务端查询摘要重新授权，不复用前端勾选结果扩权。

## 产品语言

### 普通页面转换

| 内部技术表达 | 产品表达 |
| --- | --- |
| 门禁关闭 | 功能暂未开放 |
| Synthetic／合成身份 | 演示账号或演示数据，仅在内部环境说明 |
| L2／L3／L4 | 可查看摘要／部分信息受限／需额外授权 |
| Server 拒绝 | 当前账号无权执行此操作 |
| 幂等键 | 请求处理中，请勿重复提交 |
| Unknown result | 结果确认中 |
| Command | 操作请求 |
| Adapter／Port | 普通页面不展示 |
| Outbox／Dead letter | 待恢复消息，仅在系统运行页展示 |
| Scope digest | 当前数据范围，仅在审计详情展示摘要 |

### 保留技术语言的页面

只有以下位置允许出现必要技术术语：

- 审计事件详情；
- 系统运行与恢复；
- 开发者诊断环境；
- 合规证据导出。

即使在这些页面，也不得展示认证秘密、完整请求载荷或严格敏感业务原文。

## 页面与状态

高保真原型固定包含八个视图：

1. 登录；
2. 邀请激活与 TOTP；
3. 工作身份选择；
4. 平台运营工作台；
5. 运营公司工作台；
6. 统一分页列表；
7. 权限、会话与异常状态；
8. 产品语言与组件规范。

所有视图覆盖：

- `ready`；
- `loading`；
- `empty`；
- `error`；
- `feature_unavailable`；
- `unauthorized`；
- `session_expired`；
- `scope_changed`；
- `unknown_result`。

## 响应式与可访问性

- 核心运营页面基准视口为 `1440px`；
- 窄桌面与平板基准为 `1024px`；
- 登录、激活、身份选择和异常页覆盖 `390px`；
- 高风险复核、资金批次和严格证据不在手机端提供写操作；
- 所有控件支持键盘、可见焦点、语义标签和不少于 `44px` 的主要触控目标；
- 页面缩放到 `200%` 时不产生页面级横向溢出。

## 实施门禁

当前允许：

- 维护本方案、机器契约、高保真原型和验收检查；
- 使用合成文案和合成数据验证角色差异。

当前禁止：

- 实现真实邀请、登录、MFA 或会话；
- 实现服务端导航接口、菜单重构和路由守卫；
- 实现新的分页 API 或迁移业务列表；
- 默认开启 `synthetic_admin_authentication` 或 `synthetic_admin_role_access_matrix`；
- 使用真实人员、组织或业务数据；
- 生产启用。
