## 依赖与门禁

阶段四仅在以下门禁同时满足时才允许未来的合成实现：

```text
internal_sandbox
+ synthetic_admin_multi_organization
+ synthetic_financial_ledger
+ synthetic_financial_reconciliation
+ synthetic_operator_funds
+ synthetic_admin_finance_operations
```

`synthetic_admin_finance_operations` 默认关闭。设计通过不等于允许打开门禁。

## 权威状态边界

| 事实 | 权威源 | 后台权限 |
| --- | --- | --- |
| 支付与退款 | 支付聚合领域 | 只读聚合或调用受控退款命令 |
| 账本交易与分录 | 复式账本 | 只读；完整冲正必须引用原交易 |
| 余额 | 账本余额投影 | 只读；显示投影时间与重建状态 |
| 四方对账与差异 | 对账内核 | 调查、提交证据、独立复核 |
| 分配 | 多运营主体资金编排 | 只读；比例不可编辑 |
| 运营主体清算 | 多运营主体资金编排 | 平台准备与独立复核 |
| 车主付款 | 多运营主体资金编排 | 本主体准备与独立复核 |
| 资金案件 | 多运营主体资金编排 | 本主体或平台按范围处理 |
| 账务日 | 对账内核 | 平台双人关闭 |

后台不得保存第二份资金状态或余额事实。

## 角色与组织范围

| 角色 | 组织 | 允许 | 禁止 |
| --- | --- | --- | --- |
| 平台财务经办 | 平台 | 准备清算、发起退款／冲正、调查差异 | 复核自己的动作、关闭账务日 |
| 平台财务负责人 | 平台 | 独立复核、关闭账务日、批准受控导出 | 修改金额、任意记账 |
| 运营主体财务经办 | 固定主体 | 查看本主体分配、准备本主体付款、处理资金案件 | 查看其他主体、批准自己的批次 |
| 运营主体财务负责人 | 固定主体 | 独立复核本主体付款与案件 | 跨主体、平台清算和账务日关闭 |
| 审计人员 | 治理／平台 | 只读账本、对账和审计 | 任何资金写动作 |
| 技术运维 | 平台 | 查询原幂等结果、Outbox 和恢复状态 | 退款、核销、批准、关账和记账 |

组织范围必须由 Server 根据内部会话解析，前端传入的 `operator_id` 不能扩大范围。

## 金额契约

- API 金额字段固定使用十进制整数字符串和 `CNY`；
- 页面不得使用浮点数重新计算；
- 分配展示必须同时显示总额、平台 `15%`、运营主体 `45%`、车主 `40%` 和规则版本；
- 任何合计必须来自 Server；
- 付款手续费单独展示为运营主体费用；
- “可付款”“可清算”“可关账”是服务端门禁结果，不是前端推导；
- 金额字段不提供输入框。

## 唯一命令入口

未来阶段四仅允许一个后台写入口：

```text
POST /v1/internal-sandbox/admin/finance-operations/commands
```

允许命令固定为：

- `prepare_operator_settlement`
- `review_operator_settlement`
- `prepare_driver_payout`
- `review_driver_payout`
- `request_driver_payout`
- `request_refund`
- `request_full_reversal`
- `submit_reconciliation_resolution`
- `review_reconciliation_resolution`
- `prepare_business_day_close`
- `review_business_day_close`
- `query_finance_command_recovery`

每个命令必须包含幂等键、请求摘要、资源版本、理由码和关联标识。不得为编码阶段保留第二个写入口。

## 分配与清算

- 分配只在满足主运营关系和对账门后由既有资金内核产生；
- 后台只能查看分配明细、规则版本、账本交易和对账状态；
- 清算金额固定为运营主体份额与车主份额之和；
- 平台财务经办准备清算批次，平台财务负责人独立复核；
- 批次条目只能属于同一运营主体；
- 已入批分配不得重复入批；
- 非零差异、未关闭对账或资金案件阻断时不得清算。

## `T+1` 车主付款

- 仅纳入上一业务日且未入其他批次的合格分配；
- 车主应付款为分配中的车主 `40%`，不得由后台修改；
- 付款手续费由运营主体承担并单独记账；
- 运营主体财务经办准备，本主体财务负责人独立复核；
- 未知结果时禁止创建第二笔付款；
- 提前结算继续返回 `DRIVER_EARLY_SETTLEMENT_DISABLED`。

## 退款与完整冲正

- 退款必须引用原支付订单和责任结论；
- 退款完成由支付机构结果驱动，后台不得直接标记成功；
- 完整冲正必须引用一笔可冲正原账本交易；
- 冲正方向相反、金额相同，原交易保持不变；
- 不提供部分手工分录或负数支付入口；
- 退款例外和完整冲正必须独立复核。

## 对账差异与资金案件

- 四方事实源固定为业务、支付聚合、复式账本和支付机构；
- 差异必须保留类型、金额、稳定引用、原因、证据和恢复动作；
- 非零差异不得自动核销；
- 差异解决必须经办与复核分离；
- 资金案件不得形成余额事实；
- 运营主体只能看到本主体案件及最小必要平台摘要。

## 日终关账

- 时区固定为 `Asia/Shanghai`；
- 全部对账运行必须关闭；
- 四方事实必须完整；
- 缺失或无效账单、未解决差异、未知结果和阻断案件均阻止关账；
- 平台财务经办准备，平台财务负责人独立复核；
- 已关闭业务日不得重新打开或覆盖。

## 账本查询

- 支持按交易、来源事件、订单、运营主体、车主、账户维度和全局序列查询；
- 运营主体只能查询本主体相关的脱敏分录；
- 审计人员可只读查询但不能触发资金命令；
- 不显示完整支付凭据、银行账号或严格敏感原文；
- 不提供编辑、删除、补记或直接冲正按钮。

## 未知结果恢复

未知结果页面只允许：

- 查询原幂等键和请求摘要；
- 查询账本交易、领域记录和 Outbox；
- 确认原命令成功、失败或仍未知；
- 将技术结论返回原业务角色。

禁止重新提交、换幂等键重试或由技术运维作业务决定。

## 固定页面

1. 资金运营中心；
2. 分配与运营主体清算；
3. `T+1` 车主付款；
4. 退款与完整冲正；
5. 对账差异与资金案件；
6. 日终关账；
7. 账本查询。

七页都必须覆盖默认关闭、组织越权、职责冲突、对账阻断、版本冲突、未知结果、敏感字段遮蔽和移动端无页面级横向溢出。
