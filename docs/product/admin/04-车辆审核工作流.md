# 运营后台车辆审核工作流

## 任务状态

后台任务状态与车辆审核业务状态分离。

任务状态建议：

```text
available
→ claimed
→ in_progress
→ completed
```

异常状态：

```text
claimed → released
claimed → expired
in_progress → escalated
available/claimed → cancelled
```

任务状态不替代 `spec/domain/vehicle-review.yaml` 的车辆审核状态。

## 队列进入

待处理列表只显示：

- 合成申请编号；
- 当前业务状态；
- 材料完整性摘要；
- 风险提示等级；
- 提交时间；
- 等待时长；
- 是否需要线下检查；
- 当前任务所有权。

不得在列表显示：

- 完整身份信息；
- 完整保险和权属原文；
- 车牌原文；
- 用户联系方式；
- 风险模型内部细节。

## 任务认领

### 正常认领

1. 审核员选择一个可用任务。
2. 系统显示任务摘要和预计处理范围。
3. 审核员确认认领。
4. Server 原子校验任务仍可用。
5. 成功后记录所有者、认领时间、到期时间和审计。

### 并发认领

- 只有一个审核员成功；
- 失败方看到“任务已由其他审核员认领”；
- 页面刷新任务所有权和队列状态；
- 不自动跳转到下一个任务，避免误操作。

### 释放与超时

- 主动释放必须选择原因；
- 超时回收由系统任务执行；
- 有未提交决定时，释放前提示草稿是否会丢失；
- 回收后所有写操作立即失效。

## 审核详情

详情按顺序呈现：

1. 任务和所有权；
2. 当前业务状态；
3. 客观准入检查项；
4. 最小必要材料；
5. 历史补充记录；
6. 关联风险摘要；
7. 审计时间线；
8. 决定操作区。

不得以车辆品牌、价格或能源类型作为排序和审核重点。

## 要求补充材料

1. 审核员选择结构化缺失项。
2. 系统只允许选择用户可补充的字段。
3. 审核员预览用户可见文案。
4. 设置截止条件时只能使用政策允许值。
5. 确认后更新审核状态、创建用户任务并记录审计。
6. 原审核任务进入等待用户状态，不继续占用活跃认领名额。

## 批准

批准前必须：

- 所有必需检查项完成；
- 不存在未关闭的高风险提示；
- 当前审核员仍持有任务；
- 版本与 Server 最新状态一致；
- 展示批准后影响；
- 预览用户可见结果；
- 填写结构化批准依据。

批准不得自动开启真实接单、邀请或试点。

## 拒绝

拒绝前必须：

- 选择客观、可披露的结构化原因；
- 区分可重新申请、可申诉和不可恢复情形；
- 预览用户可见文案；
- 避免使用“综合评分不足”等模糊理由；
- 高风险伪造类原因先升级安全，不由普通审核员直接结束。

## 升级

升级类型：

- 高级审核复核；
- 线下车辆检查；
- 疑似材料伪造；
- 疑似车辆替换；
- 账户或车辆重复绑定；
- 重大安全风险。

每种类型进入不同队列，必须填写：

- 升级类型；
- 触发事实；
- 已查看字段范围；
- 建议下一步；
- 是否需要临时冻结；
- 关联审计和工单。

## 复核

- 复核人必须与原决定人不同；
- 显示原决定、理由和用户可见文案；
- 复核可以维持、推翻、退回或升级安全；
- 推翻必须记录独立理由；
- 不得静默覆盖原决定历史。

## 恢复与失败

- 并发冲突：加载最新版本，不允许覆盖。
- 权限失效：保留只读页面，禁止提交。
- 任务失去所有权：立即禁用决定操作。
- 网络失败：明确“尚未提交成功”，保留本地非敏感草稿。
- 结果未知：通过幂等键查询命令结果，不重复提交。
- 任务死信：只由技术运维进入受控重放，不在审核页面提供重放按钮。
