## 阻断项关闭结果

### 1. 指标登记与页面展示不一致：已关闭

机器契约已登记八项核心指标和十一项页面支撑指标，共十九项；每项均固定来源、精度、新鲜度和关账要求。

同时必须冻结：

- 分母为零时返回 `not_applicable`，不得返回 `0%`；
- 迟到事件和历史修正如何更新已发布快照；
- 比率小数位、金额展示单位和四舍五入规则；
- 组合指标采用最旧来源时间，不能以最新子源掩盖陈旧数据。

### 2. 主体健康度算法未冻结：已关闭

`operator_health` 已固定为最严重维度优先的 `operator-health-v1`，禁止加权平均，并返回四维状态和触发原因。

### 3. 聚合读取架构和 API 未冻结：已关闭

现有阶段二至阶段四应用服务是任务工作台接口，不足以直接计算八项指标，也不应被高层角色绕过原授权直接调用。实现前必须固定：

- 独立 `ExecutiveDashboardQueryService`；
- 每个领域只提供只读、去标识、按组织范围过滤的指标适配器；
- 快照唯一键至少包含指标、指标版本、窗口、维度、组织范围摘要和截至时间；
- 六页查询 API、指标口径 API、钻取 API 和错误语义；
- 单一来源失败时页面局部降级，正式报告和导出失败关闭。

### 4. 数据等级与资金展示冲突：已关闭

契约规定驾驶舱最高 `L2`，但当前资金高保真展示精确金额，而既有 `payment.summary` 为 `L3`。在编码前必须决定不同高层角色能否看到精确资金金额，不能依赖前端遮蔽。

### 5. 导出流程不完整：已关闭

目前只冻结导出申请路径，尚未冻结批准、拒绝、下载、过期和撤销路径及状态转换。必须补充完整状态机、审批角色矩阵、对象存储期限、加密、单次下载、失败恢复和审计字段。

### 6. 页面状态不完整：已关闭

契约和六页原型已经补齐：

- 全局门禁关闭；
- 单一来源不可用；
- 数据陈旧；
- 小样本抑制；
- 无权限钻取；
- 空待决事项；
- 导出待复核、拒绝、过期和已下载；
- 窄屏下长指标定义和长错误说明。

这些状态必须在实现前形成固定页面行为，不要求新增页面，但必须补齐状态矩阵或原型。

## 已确认的最终产品决策

### 决策一：高层是否记录决策

已决定采用推荐方案：允许追加式记录高层决策意见，但不执行任何业务命令。

### 决策二：精确资金金额的披露

已决定采用推荐方案：项目决策人与运营主体负责人只看状态、区间和趋势；财务负责人通过独立 `L3` 授权查看精确聚合金额。

### 决策三：运营主体导出的批准人

已决定采用推荐方案：运营主体负责人提交后，由平台隐私合规和对应职责域负责人双人批准。

## 产品评审

通过：

- 六页覆盖经营、主体、资金、安全合规、待决事项和指标口径；
- 页面从高层判断任务出发，不从数据库表或 Repository 出发；
- 待决事项只链接原职责工作台，不提供直接批准；
- 无虚荣指标、个人惩罚排名或通用管理员视图。

## 指标与数据评审

通过。

- 八项核心指标均登记来源、公式、时区、新鲜度和关账要求；
- 客户端不重新计算金额、比率或健康等级；
- 未关账数据、陈旧数据和小样本均有固定展示规则；
- 驾驶舱快照可重建且不是经营或资金事实源。

## 权限与隐私评审

通过。

- 平台高层与运营主体高层范围分离；
- 高层默认只读取聚合脱敏数据；
- 明细钻取重新执行原领域权限；
- 严格敏感原文、个人排名和可重识别小样本禁止进入驾驶舱；
- 高层职级不获得经办、复核、技术恢复或生产启用权限。

## 财务与安全评审

通过，业务事实只读和不复制余额方向正确。

- 未对账、处理中和未知付款不会表达为已到账；
- 资金卡片不形成余额或清算事实；
- 安全指标不以投诉数替代调查结论；
- 重大案件仅展示必要摘要，证据原文仍留在安全工作台。

## 受控导出评审

通过。

- 页面范围与导出范围一致；
- 导出申请包含目的、字段、时间范围和有效期；
- 申请与批准分离；
- 下载链接短期、单次并全程审计；
- 导出不会扩大组织范围或数据等级。
