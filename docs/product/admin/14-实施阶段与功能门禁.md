# 运营控制台实施阶段与功能门禁

## 总体原则

完整后台按纵向切片实施，每个阶段必须同时包含权限、任务、页面、审计、错误恢复和测试。不得先建立一个全权限 Shell，再依赖后续补权限。

## 阶段一：多组织后台底座

### 范围

- 内部用户和组织上下文；
- 平台与运营主体范围；
- 功能角色和城市范围；
- 新全局 Shell 和导航；
- 我的工作台；
- 通知中心；
- 临时授权；
- 审计框架；
- 环境和功能门禁。

### 验收

- 运营主体用户不能访问其他主体；
- 未授权模块不显示；
- 深链接重新校验；
- 组织切换不改变真实角色；
- 审计覆盖登录、范围切换和数据披露。

## 阶段二：组织与运力运营

### 范围

- 运营主体名录和 360° 页面；
- 入驻案件；
- 城市范围和能力；
- 车主和车辆 360°；
- 主运营关系；
- 主体迁移；
- 资格、配额和现有车辆审核整合。

### 验收

- 主运营关系唯一；
- 历史关系不可改写；
- 运营主体只能处理本主体任务；
- 现有车辆审核流程不回退；
- 敏感字段按目的披露。

## 阶段三：行程、客服和安全

### 范围

- 行程运营中心；
- 预约和异常行程；
- 统一客服案件；
- 申诉；
- 安全案件和告警；
- 应急响应；
- 证据访问。

### 验收

- 后台不能自由修改行程状态；
- 客服和安全权限隔离；
- 安全恢复双人复核；
- 证据访问具备工单、目的、期限和审计；
- 未知结果具有恢复路径。

## 阶段四：资金运营

### 范围

- 分配查询；
- 运营主体清算；
- `T+1` 车主付款；
- 退款和冲正；
- 对账差异；
- 资金案件；
- 日终关账；
- 账本查询。

### 验收

- 页面金额均来自 Server 和账本；
- 无余额编辑入口；
- 非零差异阻止清算、付款和关账；
- 经办和复核分离；
- 提前结算保持关闭；
- 运营主体付款数据严格隔离。

## 阶段五：经营分析与高层驾驶舱

### 范围

- 指标口径登记；
- 城市和主体健康；
- 经营趋势；
- 资金安全；
- 安全与合规；
- 待决事项；
- 受控导出。

### 验收

- 每个指标有来源、时区、新鲜度和关账状态；
- 驾驶舱只读；
- 钻取不扩大权限；
- 导出与页面使用相同范围；
- 未关账数据有醒目标识。

## 阶段六：生产准备

### 范围

- 强认证和设备安全；
- 真实组织账号；
- 权限申请与撤销；
- 会话和临时授权；
- 数据脱敏和导出控制；
- 多主体隔离测试；
- 故障、并发和灾备；
- 安全、隐私、财务和法律验收。

### 验收

- 完成职责分离演练；
- 完成主体越权攻击测试；
- 完成敏感字段披露审计；
- 完成付款、对账和未知结果演练；
- 完成权限撤销和离职回收；
- 获得生产启用独立批准。

## 功能门禁建议

```yaml
synthetic_admin_multi_organization: false
synthetic_admin_operator_management: false
synthetic_admin_trip_operations: false
synthetic_admin_case_management: false
synthetic_admin_finance_operations: false
synthetic_admin_executive_dashboard: false
real_admin_organization_accounts: false
real_admin_finance_operations: false
production_admin_enabled: false
```

依赖关系：

```text
组织与权限底座
→ 组织与运力
→ 行程、客服和安全
→ 资金运营
→ 经营分析和高层驾驶舱
→ 生产准备
```

资金运营必须依赖已经完成的复式账本、对账和多运营主体资金编排，不能建立替代资金逻辑。

## 实施包边界

每个实施包至少包含：

- 明确角色和组织范围；
- 对应公开契约；
- 页面和状态；
- Server 端权限守卫；
- 审计事件；
- 幂等和并发处理；
- 目标测试；
- 越权和敏感数据测试；
- 功能门禁；
- 路线图验收记录。

## 首个建议实施切片

首个切片建议选择“多组织后台底座 + 运营主体只读名录”，而不是直接实现资金页面。

原因：

- 所有后续模块都依赖组织隔离；
- 可以尽早验证平台和运营主体两种视角；
- 不涉及真实资金写操作；
- 可复用现有后台 Shell、环境标识和审计组件；
- 能为现有车辆审核模块提供正确的组织归属。
