## 产品边界

本契约负责后台账号、组织任职、邀请激活、登录、MFA、会话和工作身份选择。业务角色的完整菜单、路由、操作、字段和导出权限由重构第二项冻结，本契约不建立通用管理员。

后台与乘客／车主 App 账号隔离，不开放公众注册，不允许共享账号，不为运营公司建立独立认证系统。

## 产品用户分类

产品层固定为两类工作身份：

| 工作身份 | 组织归属 | 可见范围 |
| --- | --- | --- |
| 平台工作身份 | 平台组织 | 服务端已授权的平台、城市和运营主体范围 |
| 运营公司工作身份 | 单一运营公司 | 当前成员关系绑定的运营公司 |

高层、治理、审计和平台职能角色均以平台工作身份展示，不形成第三类后台账号。

## 领域关系

```text
internal_user 1 ── 1 admin_account
internal_user 1 ── N organization_membership
organization_membership 1 ── N role_binding
role_binding 1 ── N scope_binding
admin_account 1 ── N admin_invitation
admin_account 1 ── N mfa_enrollment
admin_account 1 ── N session_family
session_family 1 ── N admin_session
admin_session 1 ── 1 work_identity
work_identity N ── 1 organization_membership
```

`work_identity` 只是当前会话对成员关系、角色和作用域的授权快照，不拥有独立权限，也不能覆盖阶段一授权结果。

## 对象契约

### 内部用户

必填字段：

```text
internal_user_id
status
maximum_data_classification
created_at
```

约束：

- 唯一自然人；
- 不直接绑定权限；
- 与产品用户账号分离；
- 多组织任职不复制内部用户。

### 后台认证账号

必填字段：

```text
admin_account_id
internal_user_id
normalized_work_email
status
password_digest
failed_authentication_count
locked_until
credential_changed_at
created_at
updated_at
```

约束：

- 与内部用户一对一；
- 规范化工作邮箱全局唯一；
- 不保存业务角色或组织作用域；
- 密码摘要算法固定为 `Argon2id`；
- 认证秘密不进入普通日志和审计。

### 组织成员关系

继续使用阶段一字段：

```text
membership_id
internal_user_id
organization_type
organization_id
status
valid_from
valid_until
```

新增冻结规则：

- `organization_type` 只允许 `platform` 或 `operator`；
- 一个成员关系只能属于一个组织；
- 运营公司成员关系必须固定 `operator_id`；
- 终止、暂停或作用域变化必须触发会话撤销；
- 业务角色不能直接绑定到 `admin_account`。

### 邀请

必填字段：

```text

normalized_work_email

membership_id
organization_type
organization_id
initial_role_summary
token_digest
status

expires_at
created_at
used_at
revoked_at
```

状态：

```text

→ accepted
pending
→ expired
pending
→ revoked
```

`accepted`、`expired` 和 `revoked` 为终态。

### MFA 登记

必填字段：

```text
mfa_enrollment_id
admin_account_id
method
secret_ciphertext
status
verified_at
created_at
revoked_at
```

约束：

- `method` 固定为 `totp`；
- 激活账号前必须完成验证；
- TOTP 秘钥必须加密存储；
- 恢复码逐个保存摘要和使用状态；
- 同一时间只允许一个有效 TOTP 登记。

### 会话族与会话

会话族必填字段：

```text
session_family_id
admin_account_id
status
created_at
absolute_expires_at
revoked_at
revocation_reason
```

会话必填字段：

```text
admin_session_id
session_family_id
admin_account_id
membership_id
work_identity_digest
refresh_token_digest
authenticated_at
mfa_verified_at
last_activity_at
idle_expires_at
absolute_expires_at
device_digest

```

约束：

- 单个会话只绑定一个成员关系；
- 刷新令牌轮换后旧摘要不可再次使用；
- 工作身份切换签发新会话并撤销旧会话；
- 服务端每请求重新验证账号、成员关系、作用域、会话和门禁。

## 状态机

### 账号状态

| 当前状态 | 允许进入 | 触发条件 |
| --- | --- | --- |
| `invited` | `pending_activation`、`revoked` | 接受有效邀请；管理员撤销 |
| `pending_activation` | `active`、`revoked` | 密码和 TOTP 完成；管理员撤销 |
| `active` | `locked`、`suspended`、`departed`、`revoked` | 失败次数、管理决定、离职或安全撤销 |
| `locked` | `active`、`suspended`、`departed`、`revoked` | 锁定到期或授权解锁；管理决定 |
| `suspended` | `active`、`departed`、`revoked` | 独立批准恢复；离职或安全撤销 |
| `departed` | 无 | 终态 |
| `revoked` | 无 | 终态 |

禁止直接跳过 `pending_activation` 激活账号。终态重新入职不得复活旧成员关系。

### 成员关系状态

```text
invited
→ active
→ suspended
→ active
→ departed

invited | active | suspended
→ revoked
```

`departed` 与 `revoked` 为终态。

### 会话状态

```text
active
→ rotated
→ active

active | rotated
→ logged_out | expired | revoked | replay_revoked
```

`logged_out`、`expired`、`revoked` 和 `replay_revoked` 为终态。

## 邀请激活流程

1. 授权管理员选择组织、工作邮箱和初始角色摘要；
2. 服务端校验邀请人的组织范围和邀请权限；
3. 服务端创建有效期 `PT72H` 的单次邀请，只保存令牌摘要；
4. 受邀人打开邀请并验证令牌；
5. 受邀人设置至少十四字符的密码；
6. 服务端检查常见和已泄露密码，并保存 `Argon2id` 摘要；
7. 受邀人登记并验证 TOTP；
8. 系统一次性显示恢复码；
9. 受邀人确认组织和初始角色摘要；
10. 服务端再次校验邀请、成员关系、角色批准和组织状态；
11. 账号与成员关系进入 `active`；
12. 用户重新登录并选择工作身份。

邀请重发必须撤销旧邀请。激活页面不得允许修改组织、角色或作用域。

## 登录流程

1. 输入工作邮箱和密码；
2. 服务端返回统一认证结果，不披露账号是否存在；
3. 密码通过后要求输入 TOTP；
4. TOTP 通过后读取所有有效成员关系；
5. 无有效成员关系时拒绝签发业务会话；
6. 只有一个有效工作身份时仍显示确认页；
7. 多个有效工作身份时按“平台工作身份”“运营公司工作身份”分组选择；
8. 服务端针对所选成员关系重新授权；
9. 签发只绑定该工作身份的会话；
10. 进入该角色的授权工作台。

密码通过但 MFA 未通过时不得签发业务会话。

## 工作身份选择与切换

工作身份卡片只显示：

- 工作身份类型；
- 组织名称；
- 角色产品名称；
- 授权城市摘要；
- 最近使用时间；
- 状态异常提示。

不得展示 `membership_id`、门禁名、作用域摘要算法或其他技术字段。

切换规则：

- 切换必须重新验证成员关系和角色绑定；
- 高风险工作身份切换可要求重新输入 TOTP；
- 切换成功后签发新会话并使旧访问令牌失效；
- 平台工作身份内只能在授权范围内缩小或改变观察范围；
- 运营公司工作身份不能改变 `operator_id`；
- 深链接进入另一个身份的页面时不得自动切换，必须回到身份选择。

## 密码、MFA 与恢复

| 项目 | 固定规则 |
| --- | --- |
| 密码长度 | 最少 14 个字符 |
| 密码摘要 | `Argon2id` |
| 第二因素 | 强制 TOTP |
| 高风险 MFA 新鲜度 | `PT15M` |
| 失败锁定阈值 | 5 次 |
| 锁定时间 | `PT30M` |
| 密码恢复令牌 | 单次使用、摘要存储、`PT30M` |
| 恢复码 | 一次性、只显示一次、只保存摘要 |
| MFA 重置 | 独立平台管理员批准并撤销全部会话 |

短信验证码不得作为后台唯一 MFA。密码恢复不得绕过 MFA。

## 会话策略

| 项目 | 固定规则 |
| --- | --- |
| Access Token | `PT15M` |
| 刷新会话绝对有效期 | `PT8H` |
| 空闲超时 | `PT30M` |
| 活动会话上限 | 每账号 3 个 |
| 刷新令牌 | 每次轮换 |
| 重放处理 | 撤销整个会话族 |
| 记住我 | 不提供 |
| Web Cookie | `HttpOnly`、`Secure`、`SameSite=Strict` |
| 请求保护 | CSRF 防护和每请求服务端重授权 |

## 撤销矩阵

| 事件 | 撤销范围 |
| --- | --- |
| 主动退出 | 当前会话 |
| 工作身份切换 | 当前旧会话 |
| 刷新令牌重放 | 当前会话族 |
| 密码重置 | 账号全部会话 |
| MFA 重置 | 账号全部会话 |
| 账号锁定、暂停、离职、撤销 | 账号全部会话 |
| 成员关系暂停、离职、撤销 | 该成员关系全部会话 |
| 角色或作用域变化 | 受影响工作身份全部会话 |
| 超过三个活动会话 | 最旧活动会话 |

## 服务端授权边界

每个业务请求必须同时满足：

```text
synthetic_admin_authentication 已启用
+ 账号为 active
+ 会话为 active
+ 会话未超过空闲与绝对有效期
+ 成员关系为 active
+ 工作身份摘要仍与角色和作用域一致
+ 阶段一统一授权允许本次动作
+ 目标业务模块门禁已启用
```

任何一项缺失均失败关闭。客户端提交的组织、角色、作用域或工作身份声明不可信。

## 页面状态

邀请、激活、登录、MFA、恢复和身份选择页面至少处理：

- `ready`；
- `submitting`；
- `invalid_input`；
- `expired`；
- `revoked`；
- `already_used`；
- `locked`；
- `suspended`；
- `no_active_membership`；
- `session_expired`；
- `scope_denied`；
- `feature_disabled`；
- `service_unavailable`；
- `unknown_result`。

未知结果不得自动重复创建邀请、重置 MFA 或签发第二个会话，必须查询原请求结果。

## 实施门禁

当前允许：

- 维护本产品契约、机器规范、Schema、验收场景和治理检查；
- 使用合成示例说明状态与流程。

当前禁止：

- 新增后台认证运行时代码、数据库迁移、HTTP API 或登录页面实现；
- 发送真实邮件；
- 使用真实人员、组织或凭据；
- 默认开启 `synthetic_admin_authentication`；
- 开启 `real_admin_organization_accounts`、`production_authentication` 或 `production_admin_enabled`。

## 验收结论

本契约完成只代表重构第一项实施前设计冻结，不代表后台登录能力已实现，也不改变“阶段五技术控制验收通过，但完整运营后台产品验收未通过”的项目状态。
