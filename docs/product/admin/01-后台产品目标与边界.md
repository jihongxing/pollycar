# 运营控制台产品目标与边界

## 产品定义

PollyCar 运营控制台是平台人员、多运营主体内部人员和项目高层共同使用的多组织内部工作系统，用于完成准入、运力、行程、客服、安全、资金、合规、经营分析、审计和系统运行任务。

它不是通用数据库管理器，不是拥有全部权限的超级管理员面板，也不是把 Server 方法直接包装成表格和按钮的 CRUD 工具。

## 产品目标

运营控制台必须同时满足：

1. 平台可以跨城市和运营主体执行治理、监督、复核与异常处置。
2. 运营主体只能在本主体和授权城市范围内管理车主、车辆、行程、客服和资金任务。
3. 项目高层通过聚合指标、重大风险和待决事项了解经营状态，但不能因职级绕过敏感数据和职责分离。
4. 所有高风险操作均具备明确任务、结构化理由、权限守卫、独立复核和不可变审计。
5. 资金金额、行程状态、资格状态和安全结论继续由对应领域事实源决定，后台不得建立第二套权威状态。

## 主要使用者

### 平台人员

- 平台运营与城市运营；
- 运营主体管理；
- 车主与车辆审核；
- 客服与申诉；
- 安全与应急；
- 财务经办与财务复核；
- 风险、合规与隐私；
- 审计；
- 技术运维。

### 运营主体人员

- 运营主体负责人；
- 运营主管；
- 运力专员；
- 车主服务人员；
- 客服人员；
- 财务经办人；
- 财务复核人；
- 安全联络人；
- 只读审计人员。

### 项目高层

- 项目负责人；
- 运营负责人；
- 财务负责人；
- 安全与合规负责人；
- 城市或区域负责人；
- 经批准的董事会或投资观察角色。

高层角色默认只读，并受组织范围、城市范围、数据等级和披露目的约束。

## 产品原则

### 任务优先于数据表

页面以“需要完成的任务、需要处理的异常和需要作出的决定”为中心，不以数据库表名和内部技术对象为导航。

### 组织隔离优先

运营主体人员进入系统后自动锁定所属主体，不能通过筛选器、URL 参数或导出功能访问其他主体数据。平台跨主体访问也必须具备角色、城市范围和业务目的。

### 权威事实不复制

- 行程状态来自行程领域；
- 资格状态来自资格领域；
- 审核结论来自审核任务；
- 安全结论来自安全案件；
- 资金余额来自复式账本分录及可重建投影；
- 对账差异来自对账批次和差异案件。

后台可以提供聚合视图、任务状态和解释信息，但不得维护独立余额、钱包、影子订单状态或可编辑的历史结论。

### 最小必要披露

列表默认只展示完成任务所需摘要。身份证件、银行账户、聊天证据、精确位置和支付报文等敏感内容必须通过目的、工单、临时授权和审计控制。

### 职责分离

经办、复核、审计、技术运维和高层观察必须分离。任何角色不得复核自己的决定，也不得通过临时切换角色模拟另一名真实内部人员。

### 异常优先

工作台优先展示即将超时、未知结果、对账差异、付款逾期、安全事件和系统失败，而不是只展示总量和增长数字。

### 可恢复而非模糊成功

所有写操作必须有明确成功、明确失败或结果未知状态。结果未知时只允许使用原幂等键查询和恢复，不允许重复创建业务动作。

## 产品范围

### 组织与城市

- 运营主体入驻、能力、限制、迁移和退出；
- 城市经营范围和运行状态；
- 内部人员、组织角色和授权范围。

### 运力

- 车主和车辆审核；
- 主运营关系；
- 资格、配额、冻结和恢复；
- 证照到期和服务质量。

### 行程

- 实时行程、预约行程和异常行程；
- 匹配、接单、取消、责任和恢复；
- 关联客服、安全和资金记录。

### 客服与申诉

- 乘客、车主和运营主体案件；
- 费用、退款、取消和资格申诉；
- SLA、升级、通知和补偿审批。

### 安全与应急

- 安全案件、风险告警和证据保全；
- 临时冻结、紧急响应和恢复访问；
- 重大事件协作与复盘。

### 资金运营

- `15%/45%/40%` 分配查询；
- 运营主体清算；
- `T+1` 车主付款；
- 退款、冲正和付款手续费；
- 对账、差异、资金案件和日终关账；
- 账本交易和余额投影只读查询。

### 风险、合规与隐私

- 风险指标、规则命中和限制任务；
- 合规任务、隐私请求和数据生命周期；
- 权限与数据披露异常。

### 经营分析与高层驾驶舱

- 城市、运营主体、运力、行程、服务、资金和安全指标；
- 重大风险、待决事项和数据新鲜度；
- 受控钻取和导出。

### 审计与系统运行

- 操作、权限和字段披露审计；
- 任务运行、幂等、Outbox、死信和人工重放；
- 供应商健康、功能门禁和内部沙箱状态。

## 非目标

- 不允许后台直接修改账本余额、分录或历史流水；
- 不允许后台任意覆盖行程、支付、审核、安全或资格状态；
- 不建立平台钱包、运营主体钱包或车主钱包；
- 不提供跨运营主体的无目的全库搜索；
- 不提供无理由批量批准、拒绝、付款或冲正；
- 不允许高层角色直接执行经办和复核操作；
- 不允许技术运维修改业务结论；
- 不接入真实资金、真实主体、真实材料或生产凭据，除非完成独立高风险批准。

## 首轮设计出口

首轮设计必须完成：

1. 产品边界和多组织模型；
2. 角色与职责分离矩阵；
3. 完整能力地图；
4. 顶层信息架构；
5. 核心实体关系；
6. 六条端到端关键流程；
7. 页面与状态清单；
8. 高层驾驶舱指标口径；
9. 分阶段实施方案；
10. 功能门禁和验收标准。
