# 运营后台产品化实施前设计评审

- 结论：`高保真设计通过；已批准内部沙箱合成代码实现`
- 评审日期：`2026-07-15`
- 实施批准日期：`2026-07-15`
- 评审范围：账号入口、工作身份、授权导航、全局 Shell、角色工作台、统一分页、产品语言和异常恢复
- 默认门禁：继续关闭

## 产品评审

通过：

- 登录、激活、MFA 和身份选择形成完整入口；
- 平台人员和运营公司人员在同一产品壳内保持清晰组织边界；
- 十个一级业务域替代阶段和技术模块导航；
- 普通页面使用任务语言，不要求运营人员理解内部架构；
- 统一列表支持增长后的搜索、筛选、排序和返回恢复。

保留边界：

- 不存在公众注册；
- 不存在超级管理员；
- 高层、审计和技术运维不获得普通业务写权限；
- 手机端不承载高风险写操作。

## 安全评审

通过：

- MFA 前不签发业务会话；
- 工作身份切换必须重签会话；
- 菜单隐藏、路由守卫和 API 授权彼此独立；
- 服务端导航清单不能替代每请求授权；
- 游标绑定查询摘要与组织范围摘要；
- 运营公司不能通过筛选、总数、搜索、导出或游标推断其他公司数据；
- 权限变化使旧导航清单和会话失效。

实施前仍需：

- 对密码摘要、TOTP 秘钥、令牌轮换和 Cookie 属性编写安全测试；
- 对游标签名、重放、篡改和跨范围复用编写契约测试；
- 对所有路由建立正向与越权测试。

## 隐私评审

通过：

- 普通列表只返回角色字段档位允许的字段；
- 搜索、排序、筛选和导出不能旁路字段权限；
- 高敏感和严格受限字段使用产品化限制说明；
- 高层和分析页面坚持去标识聚合；
- 技术运维页不展示业务正文。

实施前仍需：

- 确认真实员工邮箱、登录日志和设备摘要保留期限；
- 确认真实邮件服务商和身份基础设施的数据处理边界；
- 对导出临时文件执行删除与恢复演练。

## 运营评审

通过：

- 平台运营、本公司运营、客服、安全、财务、高层和审计均有明确工作台；
- 待办、阻断、等待复核和结果确认中是统一运营语言；
- 列表状态可恢复，不要求用户重复配置筛选条件；
- 运营公司上下文固定，避免误操作其他主体。

实施前仍需：

- 使用实际内部岗位名称复核产品角色名称；
- 由财务、安全、客服和运营负责人各完成一次角色走查；
- 明确上线初期每个角色的支持和培训负责人。

## 工程评审

通过：

- 账号、权限、导航和分页均有机器契约；
- 前端不硬编码角色名称；
- 导航清单具备版本、范围摘要和有效期；
- 游标分页具备稳定排序、查询摘要和失效恢复；
- 高保真原型覆盖桌面、窄桌面和入口移动视口。

代码实现建议顺序：

```text
认证领域与会话存储
→ 邀请激活和登录 API
→ 服务端授权导航 API
→ 全局 Shell 与路由守卫
→ 操作和字段权限
→ 统一游标分页组件与 API
→ 迁移增长型列表
→ 产品语言清理
→ 角色产品验收
```

- 首批迁移列表；
