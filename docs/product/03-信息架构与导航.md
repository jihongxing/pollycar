# 信息架构与导航

## 用户 App 全局结构

用户 App 采用共享外壳加身份工作台：

```text
App
├── 顶部：当前身份、身份切换、沙箱标识
├── 当前身份工作台
│   ├── 乘客：首页、行程、消息、我的
│   └── 车主：接单、行程、资格、我的
├── 共享：通知、安全中心、帮助、隐私
└── 全局阻断：维护、冻结、功能关闭、版本不兼容
```

底部导航随当前身份切换，但账户、安全中心、通知、帮助和隐私入口保持共享。

## 身份切换入口

身份切换器位于所有一级页面可见的统一位置，至少展示：

- 当前身份名称；
- 当前身份状态；
- 可切换身份；
- 目标身份的待办数量；
- 不可切换时的明确原因。

不得使用颜色作为唯一身份区分方式。页面标题、身份标签和关键操作文案必须共同表明当前身份。

## 切换规则

允许直接切换：

- 当前没有进行中的关键提交；
- 当前没有必须立即处理的安全确认；
- 目标身份已存在且账户未被整体冻结。

需要二次确认：

- 有未提交表单；
- 有即将超时的任务；
- 有进行中行程但切换不会改变履约责任。

禁止切换：

- 切换会绕过强制安全处置；
- 账户需要重新认证；
- 目标身份不存在或已撤销；
- 客户端状态与服务端身份状态不一致。

禁止切换时仍可进入说明页、帮助和申诉入口。

## 车主身份激活

未具备车主身份的乘客可从身份切换器进入“申请车主身份”，但这不是直接切换：

```text
申请车主身份
→ 阅读准入要求
→ 提交车主资料
→ 添加车辆
→ 等待审核
→ 审核通过
→ 激活车主身份
→ 首次进入车主工作台
```

审核中、需补充、已拒绝和已撤销均应提供对应状态页，不得展示可接订单入口。

## 深链接与返回

- 深链接必须携带预期身份上下文。
- 当前身份不匹配时，先展示安全切换确认，不得直接执行操作。
- 切换后返回目标身份的原任务页。
- 无权访问时进入状态解释页，不返回其他身份中名称相似但语义不同的页面。

## 内部沙箱

- 所有一级页面持续显示“内部沙箱”标识。
- 合成用户可预置单身份或双身份状态。
- 身份切换、审核、任务和审计使用真实应用规则，但只处理合成数据。
- 所有真实能力关闭时，页面必须展示关闭原因，不使用伪成功结果。
