# 旅程 0001：车辆准入与审核

## 目标

让已登录的合成用户在单一 App 中申请车主身份、提交合成车辆资料，由内部审核员完成审核，并让用户在车主身份上下文中看到可信、可恢复、可审计的结果。

## 参与角色

- 申请车主身份的用户；
- 普通审核员；
- 高级审核员；
- 安全人员；
- 系统任务处理器。

## 进入条件

- 当前为内部沙箱；
- 使用合成账户和合成材料；
- 账户未被整体冻结；
- 用户已具备乘客身份或基础账户身份；
- 真实身份、车辆原件和生产数据写入保持关闭。

## 正常路径

1. 用户从身份切换器选择“申请车主身份”。
2. App 展示车主与车辆准入要求。
3. 用户创建车主身份申请。
4. 用户填写合成车主资料并添加一辆合成车辆。
5. App 执行本地完整性检查并提交。
6. Server 校验身份、权限、状态和材料结构。
7. 系统创建审核任务并记录审计事件。
8. 审核员在后台认领任务。
9. 审核员根据客观车辆准入标准批准申请。
10. 系统更新车主身份和车辆审核状态。
11. 用户收到带身份归属的通知。
12. 用户切换到车主身份并进入车主工作台。

## 分支路径

### 需要补充材料

- 审核员选择明确的缺失项；
- 用户收到补充任务；
- 原申请保持同一关联标识；
- 用户只修改允许补充的字段；
- 再提交后重新进入审核队列。

### 审核拒绝

- 必须选择机器可识别的拒绝原因；
- 用户看到安全允许范围内的解释；
- 可申诉时展示申诉入口和截止时间；
- 不可申诉时展示重新申请条件。

### 审核升级

- 普通审核员不能处理的高风险情况升级给高级审核员或安全人员；
- 升级前后均保留任务、理由和访问审计；
- 用户侧显示“进一步审核中”，不披露风控细节。

### 并发冲突

- 重复提交使用幂等键返回同一结果；
- 审核任务只能被一个审核员有效认领；
- 旧版本更新返回并发冲突；
- 客户端重新加载服务端最新状态，不覆盖新决定。

## 页面

用户 App：

- 身份切换器；
- 申请车主身份说明；
- 车主资料；
- 车辆资料；
- 提交确认；
- 审核进度；
- 补充材料；
- 审核结果；
- 车主工作台。

运营后台：

- 车辆审核队列；
- 审核任务详情；
- 补充材料要求；
- 审核决定确认；
- 升级与复核。

## 命令与事件

首个实现切片应定义以下应用命令：

- 创建车主身份申请；
- 保存车辆草稿；
- 提交车辆审核；
- 认领审核任务；
- 要求补充材料；
- 批准车辆；
- 拒绝车辆；
- 升级审核；
- 重新提交材料。

具体事件名称和状态必须引用车辆审核机器契约；本旅程不另行复制可变枚举。

## 权限与数据

- 用户只能读取和修改自己的申请。
- 审核员不得批准自己的申请或复核自己的决定。
- 审核列表只展示完成任务所需的最小字段。
- 合成材料也按真实敏感等级执行日志拒绝和访问审计。
- 安全升级后的限制优先于普通审核操作。

## 沙箱和关闭行为

- 页面持续展示内部沙箱标识。
- 上传能力只接受预置合成附件引用，不接收真实证件或车辆原件。
- 审核通过只激活合成车主身份，不开放真实接单。
- 上海试点和真实邀请关闭不阻止该合成审核旅程。
- 任一真实数据输入被检测到时拒绝提交并记录安全事件。

## 验收标准

- 单身份用户可以进入车主身份申请，不会直接获得车主权限。
- 双身份用户可以显式切换，且切换前后数据和导航正确隔离。
- 正常批准、补充材料、拒绝、升级和并发冲突均可走通。
- 每个状态变化都有授权校验、领域结果和审计记录。
- 任务认领、重试、死信和人工重放不造成重复审核决定。
- App 和运营后台均正确处理功能关闭和沙箱状态。
- 全流程只使用合成数据，不连接真实身份、存储或通知供应商。
