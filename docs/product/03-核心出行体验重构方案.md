# 核心出行体验重构方案

## 文档状态

- 状态：设计候选
- 适用范围：默认叫车首页、车主工作模式首页及两者的核心出行入口
- 本轮目标：形成可评审的产品设计与 HTML 高保真预览
- 明确不包含：修改现有 Expo App、调整 Server 状态机、启用真实订单或真实支付

## 第一性原则

PollyCar 是一个 App、一个账户。普通用户打开 App 后直接进入叫车首页，不需要识别、选择或持续看到“乘客身份”。只有需要接单的用户才主动进入车主工作模式。

进入产品后，界面必须优先帮助用户完成当前身份最主要的任务：

- 默认用户：确定起点和终点、选择人数与场景、确认行程、在行程中联系车主。
- 车主：决定是否上线、浏览符合车辆容量的订单、自主决定是否接单、在履约中联系乘客。
- 双方：仅在有效行程上下文中进入临时会话、安全和异常处理。

身份、审核、资格、配额、沙箱说明和治理状态只作为必要边界或二级入口，不得占据首页主体。

## 成熟出行产品通用结构

### 默认叫车模式

1. 地图或位置画布承担首页主视觉。
2. “你要去哪里”是首要操作，不使用工作台或状态面板作为主入口。
3. 上车点默认使用当前位置，并允许快速修改。
4. 最近地点和常用地点提供低成本复用。
5. 人数是必选业务参数，默认 1 人，允许 1–3 人。
6. 场景是可选参数，不阻断快速叫车。
7. 已有行程时，首页优先呈现车主位置、预计到达时间和联系入口。

### 车主身份

1. 在线／离线是首页最重要的全局控制。
2. 离线时明确说明不会收到新订单。
3. 在线时以地图和附近订单为主体，不展示平台强制派单倒计时。
4. 每个订单必须明确起点、终点、距离、预计时间、人数和可选场景。
5. 接单和不接单都由车主决定；平台不得自动接受或强制指派。
6. 超过车辆单次乘客最大人数的订单不得展示，接受时 Server 再次校验。
7. 已接订单时，首页优先进入接驾、导航、联系乘客和异常处理。

## 导航模型

底部主导航保持三个位置。默认叫车模式不显示身份名称；进入车主工作模式后才明确显示车主状态：

| 位置 | 默认叫车模式 | 车主工作模式 |
| --- | --- | --- |
| 首页 | 叫车与进行中行程 | 上线与订单 |
| 消息 | 行程临时会话与通知 | 行程临时会话与通知 |
| 我的 | 账户、身份、主题、安全 | 账户、车辆、资格、配额、安全 |

头像是账户入口，不显示“乘客”。账户面板只提供“进入车主模式”；进入车主模式后，顶部明确显示“车主”和在线状态，并提供“退出车主模式”。

## 默认叫车首页候选

### 默认状态

- 顶部：普通账户头像，不显示“乘客”或身份下拉文案。
- 主体：地图、当前位置和附近车辆的合成示意。
- 底部浮层：
  - 主输入：“你要去哪里？”
  - 当前上车点。
  - 家、公司或最近地点快捷项。
  - 内部沙箱使用低干扰但可识别的标签呈现。

### 行程创建状态

- 起点和终点。
- 乘车人数：必选，默认 1，最多 3。
- 乘车场景：可选，包括通勤、机场／车站、就医、其他。
- 费用和车型在真实计价未批准前只显示“内部合成行程”，不得伪造真实报价。
- 主操作：“确认合成行程”。

### 等待与进行中状态

- 使用车主自主接单的等待语义。
- 匹配后显示车主头像、车主自愿公开的性别图标、车辆颜色、车型、车牌合成标识和预计到达时间，帮助乘车人完成接驾前识别。
- 车主接单后的 3 分钟内，乘车人可以主动取消行程。
- 取消原因可以选择或补充，但不是取消成功的强制条件。
- 主要操作为联系车主和查看行程。
- 安全入口始终可达，但不抢占主操作。

## 车主首页候选

### 离线状态

- 顶部：头像、车主身份、车辆简要信息。
- 主体：地图。
- 底部：醒目的“开始接单”控制。
- 辅助信息：今日合成行程、车辆单次最大乘客人数。

### 在线待接状态

- 顶部在线状态可随时关闭。
- 地图显示订单起点分布。
- 底部订单卡展示乘车人头像、乘车人自愿公开的性别图标、前往乘车人距离、起终点、预计时间、人数和可选场景。
- 主操作为“接单”，次操作为“暂不接单”。
- 不使用强制倒计时，不把拒绝包装成惩罚性行为。

### 已接订单状态

- 进入接驾导航主状态。
- 显示乘客上车点、预计到达时间和人数。
- 主要操作为到达上车点、联系乘客。
- 到达目的地必须使用滑动条确认，降低驾驶过程中误触风险，不使用普通点击按钮。
- 取消、举报和安全处理进入次级菜单。

## 身份展示与公平性边界

- 头像用于双方在接驾前识别，不作为平台排序或匹配依据。
- 性别图标只展示用户自愿公开的信息；未公开时显示中性占位，不得强制填写或推断。
- 平台不得按性别提高、降低或隐藏订单曝光，不得把性别作为资格、价格、配额或风控的自动决定因素。
- 用户可以基于自己看到的信息自主决定是否接受或取消，但平台必须持续监测是否产生系统性歧视或安全风险。
- 举报、骚扰、安全冻结和申诉入口必须保持可用。

## 车主资金与订单

- 车主“我的”中必须包含订单与资金入口。
- 订单页区分进行中、已完成和已取消，并显示合成金额、人数和路线。
- 资金中心显示可提现余额、待结算金额和累计合成收入。
- 提现前必须绑定本人银行卡；真实绑卡与真实提现在外部批准前保持关闭。
- 内部沙箱只允许使用合成银行卡尾号和合成提现结果，不得暗示真实资金已经可用。

## 视觉原则

- 延续暖雾白、夜蓝黑、城市蓝、克制梅紫和路灯琥珀设计令牌。
- 地图采用低饱和城市网格，不伪装成真实地图服务。
- 城市蓝用于叫车和位置操作，不解释为“乘客身份色”；车主梅紫用于车主工作模式与在线状态。
- 琥珀仅用于需要立即决策的主操作。
- 沙箱标识持续存在，但降级为顶部小标签或地图水印，不再占据产品内容主体。
- 页面文案使用“叫车、接单、联系、到达”等用户语言，不使用“状态预览、能力说明、治理信息”等内部语言。

## 评审决策点

在进入 Expo 重构前，需要确认：

1. 默认叫车首页是否采用“地图 + 去哪里”作为唯一主入口。
2. 车主首页是否采用“在线控制 + 自主订单卡”作为唯一主入口。
3. 底部导航是否使用“首页、消息、我的”。
4. 是否确认默认模式不显示“乘客”，账户面板只提供“进入车主模式”。
5. 是否接受地图为主视觉、业务卡片从底部浮出的布局。
6. 是否继续保留当前品牌色和字体方向。

## 主要页面设计范围

本轮设计评审必须至少覆盖以下主要页面，不得只评审首页：

### 默认叫车流程

1. 叫车首页。
2. 目的地搜索。
3. 行程确认：起终点、人数和可选场景。
4. 等待车主自主接单。
5. 车主接驾：车主头像、性别图标、车辆颜色／车型／车牌、预计到达和联系入口。
6. 接单后取消：3 分钟内可主动取消，原因非强制。
7. 行程进行中：目的地、预计到达、安全和联系入口。
8. 行程完成：结果摘要和再次叫车。

### 车主工作流程

1. 车主离线首页。
2. 在线订单列表／订单卡：展示乘车人头像和自愿公开的性别图标。
3. 已接单接驾。
4. 到达上车点并等待乘车人。
5. 行程进行中：通过滑动条确认到达目的地。
6. 行程完成摘要。
7. 订单列表。
8. 资金中心。
9. 绑定银行卡。
10. 提现确认与结果。

### 共享主要页面

1. 行程临时会话。
2. 消息与通知列表。
3. 我的／账户入口。

审核、车辆材料、资格、配额、隐私与安全设置仍属于二级流程，本轮不要求逐页高保真，但必须能从“我的”进入。
