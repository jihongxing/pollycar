# 跨端体验原则

## 规则由服务端执行

App 和运营后台负责呈现、收集意图和解释结果。资格、配额、审核、权限、并发和安全规则必须由 Server 应用服务和领域内核执行。

## 状态完整

每个可操作页面至少定义：

- 加载；
- 正常；
- 空状态；
- 待处理；
- 成功；
- 可恢复错误；
- 不可恢复错误；
- 权限不足；
- 功能关闭；
- 身份受限；
- 安全冻结；
- 并发冲突；
- 沙箱状态。

## 错误可行动

错误展示必须回答：

1. 发生了什么；
2. 用户现在能做什么；
3. 是否可以重试；
4. 是否需要补充材料、切换身份、申诉或等待；
5. 在安全允许范围内如何获取帮助。

客户端不得根据错误文案判断业务分支，应使用机器错误码。

## 身份明确

- 所有关键页面必须展示当前身份。
- 身份切换后不得保留上一身份的订单列表、配额或操作按钮。
- 共享通知必须标注其所属身份。
- 从通知进入任务时必须验证并切换到正确身份上下文。

## 安全优先

- 安全冻结优先于履约便利和转化率。
- 证据、身份原件、精确位置和支付数据不得出现在通用日志。
- 运营后台敏感访问必须展示目的、工单和审计提示。
- 高风险操作必须支持二次确认和职责分离。

## 默认关闭

生产级页面可以实现，但以下能力保持关闭：

- 真实支付；
- 付费弹性资格；
- 真实用户邀请；
- 上海试点；
- 真实数据写入；
- 真实位置、聊天和身份材料接入。

关闭态是正式产品状态，必须可测试、可解释、可审计，不得使用隐藏入口绕过。

## 可访问性与一致性

- 关键状态不只依靠颜色表达。
- 所有操作提供明确名称和结果反馈。
- 相同领域状态在 App 与运营后台使用一致术语。
- 时间、额度和状态变化展示服务端权威值。
- 破坏性操作必须说明影响和恢复条件。
