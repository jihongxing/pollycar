# 验证与验收计划

## 验证原则

- 以外部可观察行为为准，不依赖内部实现细节。
- 每个变更单元运行最小但足够的验证。
- 高风险流程必须覆盖正常、拒绝、并发、重试、回滚和审计路径。

## 当前检查入口

| 变更类型 | 最低验证 | 命令 |
| --- | --- | --- |
| 仅文档 | 文档索引、中文约束和治理检查 | `./scripts/test/check-doc-governance.ps1` |
| API | OpenAPI 契约和 API 测试 | 尚未配置 |
| 领域逻辑 | 单元测试和状态机测试 | 尚未配置 |
| 数据结构 | 迁移、约束和回滚验证 | 尚未配置 |
| 客户端界面 | 构建、可访问性和目标流程冒烟 | 尚未配置 |
| 配置与交付 | 预检和发布检查表 | `./scripts/test/preflight.ps1 -SkipProjectTests` |

## MVP 核心验收场景

- 不同时段正确显示固定价格和分账。
- 无人接单时正确释放预授权。
- 多车主并发接受时只有一人成功。
- 接单成功立即占用滚动额度。
- 24 小时 3 单、7 日 10 单、30 日 15 单的边界正确。
- 不同取消责任下正确保留或释放额度。
- 未进入等单状态的车主无法浏览订单。
- 车主无法无限浏览、收藏或回看乘客。
- 行程完成前不能请求开启临时对话。
- 单方同意时不能聊天；双方同意后才开始 72 小时倒计时。
- 任一方提前关闭后不能重新开启。
- 举报后订单、对话或账号可及时冻结并保全证据。
- 无权限人员无法访问身份、支付、位置、聊天和安全审计数据。

## 弹性参与资格验收场景

- 未满足资格条件时，支付不能绕过审核。
- 资格通过后使用 4/12/18 上限，而不是无限接单。
- 基础与弹性资格都按同一原子接单规则竞争，不存在付费优先。
- 同一车主不能叠加、转让或囤积多个资格周期。
- 90 日周期内超过允许启用天数时不能继续购买或自动续期。
- 资格到期、暂停或撤销后立即恢复基础配额。
- 已占用额度在资格暂停后不会被错误释放。
- 风险冻结优先于付费权益，且所有决定可审计、可申诉。
- 资格费用、审核费用和退款结果符合已披露规则。
- 监控付费与未付费车主的订单集中度、完成率、取消率、举报率和职业化风险差异。

## 上线验收

公开付费测试前，除自动化测试外还必须完成：

- 合规、协议、保险、税务与支付方案评审。
- 客服和严重安全事件演练。
- 真实设备、弱网、定位异常和支付异常测试。
- 数据备份、恢复、回滚和审计重建演练。
- 封闭邀请种子测试及退出条件评审。

## 报告规则

每个完成报告必须写明运行的命令、验证内容、结果、跳过项和残余风险。
