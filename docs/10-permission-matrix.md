# 权限矩阵

本文档定义 PollyCar 的角色、操作权限、数据可见范围、审批要求和职责分离，是授权设计的唯一真相源。

## 授权原则

- 默认拒绝：未明确允许的操作一律禁止。
- 最小权限：只授予完成当前职责所需的最少能力。
- 职责分离：审核、安全、财务、客服和系统运维不得互相替代。
- 双人控制：高风险配置、证据导出、大额退款和永久处置需要第二人批准。
- 临时授权：紧急权限必须限时、说明原因、关联工单并自动失效。
- 自我操作禁止：人员不得审批、退款、解封或导出与自己相关的记录。
- 状态机约束：权限允许不代表状态转换一定合法，仍须通过 `docs/09-state-machines.md` 的守卫。
- 全量审计：敏感读取、导出、修改、批准和拒绝必须记录。

## 角色定义

| 角色 | 职责 | 不得承担 |
| --- | --- | --- |
| 乘客 | 管理本人资料、发起与履行行程、举报和申诉 | 查看车主后台资料、审核证据或其他用户数据 |
| 车主 | 管理本人及车辆资料、等单接单、申请资格、举报和申诉 | 查看完整乘客身份、其他车主数据或风险模型 |
| 客服人员 | 处理一般咨询、订单进度和非安全投诉 | 查看完整身份材料、聊天正文、精确位置、修改资金或风险结论 |
| 普通审核员 | 审核乘客、车主、车辆及弹性资格材料 | 处理严重安全事件、修改支付流水、批准自己的决定 |
| 高级审核员 | 复核复杂审核、处理一般审核申诉 | 修改支付流水、删除安全证据、覆盖安全冻结 |
| 安全人员 | 调查举报、安全冻结、证据保全和严重事件处置 | 修改支付原始流水、调整业务价格或掩盖审计记录 |
| 安全负责人 | 批准永久封禁、重大证据导出和高风险恢复 | 单独完成调查、批准和删除全链路 |
| 财务人员 | 支付对账、退款处理、分账和财务异常调查 | 修改安全风险、资格审核结果或订单履约事实 |
| 财务负责人 | 批准大额或异常退款、账务调整 | 单独发起并批准同一调整 |
| 运营人员 | 管理邀请、候补、开放规模和一般运营配置 | 查看严格受限证据、修改支付或安全结论 |
| 运营负责人 | 批准区域、时段、价格和开放规模配置发布 | 绕过决策记录、发布未批准高风险配置 |
| 隐私与合规人员 | 处理用户数据权利、法律保留和合规评审 | 直接修改业务状态、支付流水或安全事实 |
| 数据分析人员 | 使用脱敏或聚合数据评估产品与试验 | 访问直接身份、聊天正文、精确位置或单用户证据 |
| 技术运维人员 | 维护系统、恢复服务和执行受控数据操作 | 因运维便利浏览业务敏感数据或修改业务决定 |
| 系统定时任务 | 执行到期、保留、删除、额度窗口和通知任务 | 使用超出任务范围的通用管理员权限 |
| 风险规则系统 | 计算风险信号、提出暂停或复核建议 | 在无授权规则时永久撤销资格 |
| 支付回调系统 | 确认支付、退款和分账外部结果 | 改变资格、安全或订单责任结论 |
| 审计人员 | 只读检查敏感操作、决策和控制有效性 | 修改被审计数据或批准业务操作 |
| 紧急响应人员 | 在严重事件中执行限时冻结和证据保全 | 永久处置、常规批量导出或关闭审计 |

## 临时权限与紧急访问

- 仅用于严重安全事件、系统恢复或法律要求。
- 必须关联事件编号或工单。
- 必须限制数据范围、操作范围和有效时间，默认不超过 4 小时。
- 访问开始和结束均通知安全或隐私负责人。
- 24 小时内完成事后复核。
- 不得用于常规查询、业务分析或绕过审批。

约束：

- 高层职级不产生通用管理员权限，也不继承经办、复核或技术恢复权限。
- 驾驶舱最高只展示聚合脱敏数据，严格敏感原文必须留在原职责工作台。
- 筛选、钻取和导出不能扩大服务端组织范围。
- 未关账、陈旧和小样本数据必须明确标识或抑制。
- 待决事项只能链接原工作台，不得在驾驶舱内直接批准。
- 高层意见不可修改或删除，只能以新记录显式替代，且不得改变原业务状态。
- 单次导出只能属于一个职责域，并由平台隐私合规和对应职责域负责人双人批准。

## 审计要求

以下操作必须记录成功和失败尝试：

- 查看或导出身份、支付、精确位置、聊天和安全证据。
- 审核批准、拒绝、暂停、撤销、恢复和申诉决定。
- 退款、账务调整和对账修复。
- 责任分类、永久封禁和证据冻结。
- 高风险配置发布和回滚。
- 临时权限授予、使用和失效。

审计记录至少包含主体、角色、目的、工单、资源、字段范围、时间、结果、来源设备或服务、关联标识和策略版本。

## 禁止组合

- 同一人员不得发起并批准同一退款、永久封禁、证据导出或高风险配置。
- 审核员不得复核自己作出的拒绝决定。
- 财务人员不得改变安全结论或资格状态。
- 安全人员不得修改支付流水或价格配置。
- 客服不得查看严格受限原文。
- 数据分析人员不得获得可直接识别个人的明细数据。
- 技术运维不得使用共享管理员账号访问业务数据。
- 系统服务不得使用无范围限制的通用超级权限。

## 实施验收

- 每个 API 和后台操作均映射到明确角色和权限动作。
- 每个拒绝结果返回稳定原因码并生成审计记录。
- 权限变化立即生效，缓存不得扩大撤销窗口。
- 临时权限自动过期。
- 可以证明禁止组合无法由单一账号完成。
- 敏感字段按角色进行字段级过滤。
- 用户、角色、租户或环境边界不能通过参数篡改绕过。
- 权限矩阵变更必须更新测试和安全评审。
