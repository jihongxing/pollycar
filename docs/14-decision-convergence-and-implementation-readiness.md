# 决策收敛与可实施准备

## 目的

本文件定义阶段 0 后半程的统一关口：先收敛高风险产品决策，再把已批准规则转化为可实施、可测试、可回滚的工程输入。

文档、Schema 和预检通过只能证明内部一致性，不能替代法律、保险、财务、安全、隐私、公平性或项目决策人批准。

## 状态定义

### 决策收敛

一项决策同时满足以下条件，才可标记为“已收敛”：

- 问题、目标、非目标和候选方案完整。
- 最终规则不存在“建议”“待定”“推荐基线”等会改变实现的表述。
- 法律、保险、支付、安全、隐私、公平性等适用评审已关闭阻断项。
- 负责人、批准人、批准日期和证据引用完整。
- 生效、暂停、退出、回滚和替代条件明确。
- 生效规则已同步到对应产品、领域、数据、权限、API 和验收真相源。

“评审中”不等于已收敛；“内部方案明确”也不等于获得外部批准。

### 可实施准备

一项能力同时满足以下条件，才可进入生产代码实现：

- 依赖的高风险决策均已收敛。
- 用户流程、状态机、领域事件和错误语义完整。
- 角色权限、职责分离和数据等级完整。
- OpenAPI、操作策略和数据约束足以支持目标流程。
- 正常、拒绝、边界、并发、权限、审计和恢复场景已进入验收矩阵。
- 功能开关、配置、可观测性、容量、迁移和回滚要求明确。
- 不存在需要通过代码“先做再定”的核心业务规则。

### 可原型验证

未达到生产实现门槛时，只允许：

- 无真实资金、无真实乘客和无真实安全风险的交互原型。
- 纯计算、状态机、契约和测试夹具验证。
- 使用匿名、合成或明确授权测试数据的内部验证。

原型不得被描述为生产实现，不得绕过决策阻断项。

## 决策依赖顺序

| 顺序 | 决策 | 收敛原因 | 下游依赖 |
| ---: | --- | --- | --- |
| 1 | `0002` 首期运营范围 | 确定辖区、围栏、时段和试点规模 | 法律、保险、车辆、支付、安全响应 |
| 2 | `0005` 安全证据与数据保留 | 决定敏感数据最小收集和保留边界 | API、数据库、审计、举报和申诉 |
| 3 | `0003` 车辆准入标准 | 决定审核字段、证据和复核规则 | 车主准入、保险和运营后台 |
| 4 | `0004` 支付退款与取消责任 | 决定资金状态、责任和异常处理 | 支付契约、账务、客服和退款 |
| 5 | `0001` 弹性参与资格 | 依赖辖区、数据保留、保险和收费定性 | 资格收费、配额和公平性试验 |

弹性资格的免费邀请试验可以在 `0001` 尚未批准收费的情况下单独评审，但仍依赖 `0002`、`0005` 和安全控制。

## 分阶段实施切片

### 切片 A：无资金领域内核

允许准备：

- 用户、车辆和资格的状态机纯逻辑。
- 配额滚动窗口计算。
- 领域事件信封、幂等键和错误模型。
- 权限决策接口和审计事件模型。
- 合成数据验收测试。

禁止：

- 真实用户注册、真实证件上传、真实位置跟踪。
- 真实支付、退款、分账或弹性资格收费。

### 切片 B：内部审核沙箱

进入条件：

- `0005` 已批准。
- `0003` 至少达到有条件通过。
- 数据字段、访问角色、脱敏、删除和审计规则已进入机器契约。

允许准备：

- 使用合成或明确授权测试资料的审核工作流。
- 安全冻结、申诉和审计查询沙箱。

### 切片 C：零金额封闭测试

进入条件：

- `0002`、`0003`、`0005` 已批准。
- 城市、安全响应、车辆保险和封闭测试协议已签署。
- 功能开关、监控、回滚和人工响应演练通过。

限制：

- 仅邀请制。
- 不发生真实订单收费、资格收费、分账或钱包交易。
- 达到容量、时段、区域或安全阈值时自动停止扩张。

### 切片 D：真实收费试验

进入条件：

- `0004` 已批准。
- 适用法律、保险、税务、账务和支付评审通过。
- 退款、取消、争议、对账和资金异常场景全部验收。

弹性资格收费还要求 `0001` 已批准；普通行程收费批准不自动批准弹性资格收费。

## 实施就绪输入

每个准备实施的能力必须提供实施包：

| 输入 | 必需内容 |
| --- | --- |
| 决策引用 | 已批准决策编号、版本和批准日期 |
| 范围 | 本次实现与明确不做 |
| 用户流程 | 正常、拒绝、暂停、申诉和退出路径 |
| 领域契约 | 状态、事件、守卫、不变量和并发优先级 |
| API 契约 | 操作、请求响应、错误码、权限和幂等 |
| 数据契约 | 字段、等级、保留、删除、索引和迁移 |
| 验收 | 场景编号、预期结果和审计证据 |
| 运行要求 | 配置、开关、日志、指标、告警和容量 |
| 回滚 | 触发条件、状态恢复和数据处理方式 |

缺少任一关键输入时，任务只能标记为“设计准备”，不能标记为“可实施”。

## 当前停止线

- 不开始真实支付和生产收费实现。
- 不收集真实身份证件、完整支付凭据或持续位置轨迹。
- 不实现手工修改配额、风险阈值或安全证据的通用后台接口。
- 不因公开人口代理评分直接批准试点城市。
- 不因 Schema、OpenAPI 或预检通过宣称业务决策已批准。

## 阶段退出标准

阶段 0 进入实现阶段前必须满足：

- `0002`、`0003` 和 `0005` 已批准。
- `0004` 至少完成不涉及真实资金的责任边界收敛。
- `0001` 对免费邀请试验形成明确结论；付费部分可以继续保持禁止。
- 首个实施切片及其实施包已批准。
- 应用架构、数据库、测试工具链和本地开发命令已形成技术决策。
- CI 能执行治理、Schema、契约、测试、静态检查和构建。

## 维护规则

1. 本文件是决策收敛和实施准入定义的唯一真相源。
2. 当前状态、负责人和下一任务属于 `ROADMAP.md` 和对应评审清单。
3. 决策状态变化时必须重新检查下游实施切片是否仍被允许。
4. 任何扩大真实数据、真实资金、真实用户或真实运营风险的变化都必须重新评审。
