# 文档体系

项目采用代码优先、风险升级的轻量治理模式：新增文档必须有明确的风险、法律、外部依赖或长期维护价值；普通实现不再以文档作为开始编码的前置条件。

## 活跃文档

| 文档 | 唯一职责 | 更新条件 |
| --- | --- | --- |
| `../ROADMAP.md` | 当前目标、近期任务、阻断项和冻结能力 | 优先级、范围或阻断项改变 |
| `decisions/README.md` | 高风险、难逆转或需外部批准的决策索引 | 决策状态改变 |
| `../spec/` | 已进入代码、需要机器检查的状态、接口、权限和数据契约 | 代码行为或契约改变 |
| `../DESIGN.md` | 已实现 App 的共享设计令牌与体验约束 | 共享视觉或交互规则改变 |
| `../PRODUCT_LANGUAGE.md` | 用户界面最终态、内部状态展示映射和产品化验收 | 跨页面产品语言或界面完成标准改变 |
| `product/09-地图与位置能力设计.md` | 高德官方能力、配额、许可和地图位置架构 | 地图供应商、配额、许可或位置生命周期改变 |
| `product/10-发起行程与预约时间设计.md` | 即时叫车、连续快捷预约和滚动 72 小时预约规则 | 行程时间、预约状态、冲突或取消规则改变 |
| `finance/README.md` | 真实资金、复式账本和自动对账的高风险设计索引 | 资金架构、账务规则、供应商边界或对账规则改变 |
| `implementation/README.md` | 高风险实施切片的历史证据 | 新建高风险实施包或状态改变 |

## 历史基线

`00-14`、`product/`、`reviews/` 和既有实施包记录了项目已完成的设计与治理基线。除非要改变其中定义的高风险规则、共享设计令牌或公开契约，否则不要求在普通功能改动中同步更新，也不要求为每项代码创建新页面、旅程、评审或实施包文档。

## 最小记录规则

1. 普通 UI、内部沙箱应用服务、修复与测试：代码、测试和必要时的 `ROADMAP.md` 一行状态即可。
2. 新增或改变公开 API、状态转换、权限或数据载荷：更新对应 `spec/` 契约与测试；不重复编写说明文档。
3. 涉及真实资金、真实数据、生产启用、法律合规、外部服务或不可逆迁移：新增决策；必要时再新增评审或实施包。
4. 所有新增项目文档仍必须使用简体中文。
