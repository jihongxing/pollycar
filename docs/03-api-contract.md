# API 契约说明

## 当前状态

尚未批准具体端点。完成阶段 0 的领域决策和技术架构选择后，以 `spec/api/openapi.yaml` 作为机器可检查的 API 唯一真相源。

## 契约要求

每个 API 变更单元必须定义：

- 业务目的和适用状态。
- 调用方、身份认证、授权和数据最小化要求。
- 请求、响应和错误结构。
- 并发、幂等、超时和重试语义。
- 审计事件、敏感数据处理和保留要求。
- 可执行契约测试和失败场景。

## 首批契约范围

架构确定后，优先定义：

1. 用户注册、实名、成年和审核状态。
2. 车主、车辆申请与审核。
3. 行程创建、价格试算和支付预授权。
4. 等单、订单浏览、原子接单和配额校验。
5. 接驾、行程状态转换、取消和安全终止。
6. 支付释放、扣款、退款、分账和争议。
7. 临时对话选择、开放、关闭、到期和举报冻结。
8. 举报、安全事件、审计和运营配置。
