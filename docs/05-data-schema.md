# 数据结构规划

## 唯一真相源

数据库建立后，可执行结构以迁移文件为准；本文档解释数据意图、约束、隐私分级和迁移顺序。

数据敏感等级、字段处理、事件载荷和非生产使用规则以 `docs/11-data-classification.md` 为准。

## 当前状态

持久化技术尚未选择，不得在领域不变量和合规方案未确定前建立生产数据结构。

## 预期数据域

| 数据域 | 目的 | 关键约束 |
| --- | --- | --- |
| 用户与资格 | 身份、成年、审核和限制状态 | 敏感身份信息最小化、分级授权、访问留痕 |
| 车主与车辆 | 权属、合法使用权、保险、车况和绑定 | 车辆与实际履约主体一致 |
| 运营配置 | 城市、区域、时段、距离、价格、分账和开放规模 | 版本化、可审计、变更可追溯 |
| 行程 | 请求、接单、履约、取消、完成和争议 | 状态转换原子化、幂等、保留完整审计 |
| 配额与风险 | 滚动额度占用、释放和职业化信号 | 支持 24 小时、7 日、30 日窗口与人工复核 |
| 支付与结算 | 预授权、释放、扣款、退款、分账 | 财务流水不可覆盖，必须可对账 |
| 临时对话 | 双方选择、消息、关闭、到期和冻结 | 前台可见期与安全证据保留期分离 |
| 举报与安全事件 | 举报、证据、冻结、调查、申诉和处置 | 证据不可被普通业务流程删除 |
| 审计日志 | 关键访问、状态变化和运营操作 | 防篡改、可检索、最小授权 |

## 车辆准入数据契约

车辆准入业务规则以 `docs/decisions/0003-车辆准入标准.md` 为唯一真相源。持久化设计至少需要表达：

| 数据对象 | 必需内容 | 关键约束 |
| --- | --- | --- |
| 车辆主体 | 内部标识、车型、能源类型、首次登记日期、当前里程 | 不以品牌或车价形成用户等级 |
| 车辆标识 | 车辆识别代号受控引用、号牌掩码、登记地区 | 原件和完整标识按 `L4` 管理 |
| 权属授权 | 权属类型、所有人受控引用、关系或控制证明、授权有效期 | 非本人车辆授权剩余至少 12 个月 |
| 法定文件 | 行驶证、年检状态、召回状态 | 到期或重大召回触发暂停或复核 |
| 保险摘要 | 保险机构、险种、保额、有效期、驾驶人覆盖、核验结果 | 不保存完整支付凭据；到期自动暂停 |
| 实车检查 | 检查版本、检查项结果、缺陷类别、检查人员、检查时间 | 纯线上照片不能单独批准 |
| 准入决定 | 状态、原因码、规则版本、决定人、决定时间 | 决定不可覆盖，只能追加转换 |
| 绑定关系 | 车主、车辆、生效和结束时间 | 同车单一有效车主，同车主单一有效车辆 |
| 复核任务 | 触发原因、截止时间、结果和证据引用 | 常规 6 个月，事件可即时触发 |
| 申诉 | 原决定、申诉理由、复核人和结果 | 原审核员不得单独处理申诉 |

数据库必须使用唯一约束或等效事务守卫保证有效绑定唯一性，并允许重建保险到期、里程退出、暂停、恢复和撤销历史。

## 迁移规则

- 默认采用向后兼容迁移。
- 破坏性迁移必须明确、可恢复并经过发布审批。
- 数据保留、删除、匿名化和导出规则必须与隐私及安全决策一致。
- 新增或修改结构时，同时更新本文档、迁移、测试和回滚方案。
- 不得在日志、测试夹具或开发配置中写入真实身份、支付、位置或聊天数据。
