# 验收矩阵

本文档把产品规则、决策、状态机、权限和数据保护要求映射为可验证场景。机器场景以 `spec/tests/eligibility-scenarios.yaml` 为准。

## 场景结构

每个场景至少包含：

- 场景编号和中文名称。
- 关联规则或规范。
- 初始状态和前置数据。
- 操作者和命令。
- 预期领域事件。
- 预期最终状态或错误码。
- 审计等级和最高数据等级。
- 是否阻断发布。

## 发布阻断规则

以下场景失败时必须阻断发布：

- 资金重复扣款、退款或状态不一致。
- 安全冻结、撤销或权限隔离失效。
- 配额边界、并发接单或在途订单规则错误。
- `L4` 数据进入普通日志、通用事件或非生产环境。
- 付费改变订单排序、乘客资料范围或接单优先级。
- 未批准规范被标记为生产启用。

## 覆盖要求

- 每个状态至少有进入或退出场景。
- 每个错误码至少由一个规范、API 或验收场景引用；纯内部兜底错误除外。
- 每个高风险授权动作至少有允许和拒绝场景。
- 每个 `L4` 数据域至少有禁止泄露或访问控制场景。
- 所有并发场景必须验证幂等、版本和最终事件数量。

## 后续实现

技术栈确定后，应把机器场景转换为参数化测试，并保留场景编号作为测试标签，确保产品规则、规范和自动化测试可追溯。
