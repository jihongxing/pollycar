# 实施包 0005：运营后台首个合成审核切片

## 状态

`已完成`

本实施包批准生产级代码实现，但继续禁止生产启用、真实数据接入和范围外后台能力。

## 实施目标

建立首个运营后台纵向切片，只验证以下五步：

```text
合成车辆审核队列
→ 单任务原子认领
→ 查看最小必要摘要
→ 要求补充合成材料
→ 查看追加式审计记录
```

该切片用于验证：

- 桌面后台应用边界；
- 任务所有权与租约；
- 最小必要字段披露；
- 补充材料决定和用户文案预览；
- 幂等、并发、错误和审计；
- 明暗主题、环境标识和可访问性；
- App、后台和 Server 共享公开契约但保持独立界面。

## 明确范围

### 后台页面

只实现：

1. 内部沙箱入口；
2. 普通审核员工作台；
3. 合成车辆审核待处理队列；
4. 单任务最小摘要详情；
5. 要求补充材料确认；
6. 当前任务审计记录；
7. 任务已被他人认领；
8. 任务所有权失效；
9. 网络失败和未知结果恢复；
10. 明暗主题。

### 后台操作

只允许：

- 查看合成队列；
- 认领一个任务；
- 查看任务所有权和租约；
- 查看 `queue_summary` 与 `review_field` 层级字段；
- 选择预批准的补充材料原因；
- 预览用户可见文案；
- 提交要求补充材料命令；
- 查看当前申请的追加式审计摘要；
- 主动释放任务；
- 处理认领冲突和所有权失效。

### Server 能力

允许为本切片新增：

- 审核任务队列读模型；
- 原子认领、续约、释放和超时回收应用服务；
- 任务所有权校验；
- 后台专用合成查询和命令适配器；
- `request_material` 的幂等命令编排；
- 审计查询读模型；
- 内部沙箱 HTTP 适配器或进程内适配器；
- 仅合成数据的错误映射。

## 公开契约

实施前或同一变更单元中建立 `packages/contracts/src/admin-review.ts`，至少包含：

- `AdminReviewTaskSummary`；
- `AdminReviewTaskDetail`；
- `AdminReviewTaskStatus`；
- `AdminReviewLease`；
- `AdminReviewAuditEntry`；
- `ClaimAdminReviewTaskCommand`；
- `RenewAdminReviewTaskCommand`；
- `ReleaseAdminReviewTaskCommand`；
- `RequestVehicleMaterialAdminCommand`；
- `AdminReviewClient`。

公开契约必须：

- 不包含身份、保险或权属原文；
- 不包含安全证据；
- 不包含批准、拒绝、升级和复核命令；
- 包含 `task_version` 与 `vehicle_review_version`；
- 包含幂等键；
- 明确 `synthetic: true`；
- 使用现有机器错误码。

## 数据与安全边界

- 队列只返回 `queue_summary` 字段。
- 任务详情只返回 `review_field` 字段。
- 不实现 `temporary_original` 和 `safety_evidence`。
- 内部角色固定为预置合成普通审核员。
- 禁止页面参数覆盖角色或任务所有者。
- 任务认领必须由 Server 原子判断。
- 所有写命令必须同时校验任务所有权、租约和业务版本。
- 日志不得包含材料原文、联系方式、车牌或保险内容。
- 所有页面持续显示内部沙箱。

## 任务规则

- 一个任务只能有一个有效所有者。
- 认领租约为 30 分钟。
- 允许在到期前 5 分钟内续约。
- 失去所有权后所有写操作立即拒绝。
- 主动释放必须选择结构化原因。
- 任务超时由受控系统任务回收。
- 并发认领失败返回 `ADMIN_TASK_ALREADY_CLAIMED`。
- 所有权失效返回 `ADMIN_TASK_OWNERSHIP_LOST`。
- 网络结果未知时按幂等键查询，不重复提交。

## 要求补充材料

首切片只允许以下原因：

- `insurance_expiry_incomplete`；
- `authorization_evidence_incomplete`；
- `synthetic_attachment_invalid`。

提交前必须：

- 当前任务处于 `in_progress`；
- 当前审核员持有有效租约；
- 当前车辆审核状态允许补充；
- 结构化原因已选择；
- 用户可见文案已预览；
- 任务版本和车辆审核版本均匹配。

提交成功后：

- 车辆审核进入等待补充状态；
- 审核任务进入 `waiting_user`；
- 任务不再占用活跃认领名额；
- 写入审计；
- 页面进入只读结果状态。

## 验收矩阵

### 正常场景

- 合成审核员能看到队列摘要。
- 可成功认领一个可用任务。
- 认领后可看到最小必要详情。
- 可选择允许的补充原因并预览用户文案。
- 提交后任务和车辆审核状态一致。
- 审计记录包含认领、字段访问和补充决定。
- 明暗主题不改变权限、所有权或状态。

### 拒绝场景

- 未认领任务不能要求补充。
- 非任务所有者不能提交。
- 租约到期后不能提交。
- 缺少结构化原因不能提交。
- 未预览用户文案不能提交。
- 试图访问严格受限原文被拒绝。
- 试图调用批准、拒绝或升级能力被拒绝。
- 真实数据输入被拒绝。

### 边界与并发

- 两个审核员并发认领只有一个成功。
- 续约只能在允许窗口内完成。
- 释放后原所有者立即失去写权限。
- 任务版本冲突需要刷新。
- 车辆审核版本冲突需要刷新。
- 重复幂等键返回同一结果。
- 网络结果未知可以恢复原命令结果。

### 审计与数据保护

- 列表和详情不包含严格受限原文。
- 审计记录不可通过后台修改或删除。
- 日志不包含敏感原文。
- 任务、主体、原因、版本、时间和关联 ID 均被记录。
- 技术运维角色无法作业务决定。

### 可访问性与体验

- 键盘可以完成队列导航和普通表单操作。
- 认领冲突、所有权失效和未知结果不只用颜色表达。
- 弹层关闭后焦点返回触发位置。
- 明暗主题均满足环境标识和状态对比。
- 页面返回后保留队列筛选与滚动上下文。

## 回滚策略

### 代码回滚

- `apps/admin` 是独立 workspace 包，可整包移出 workspace。
- 删除或禁用 `apps/admin` 不得影响 App、Server 或 Domain 构建。
- 后台新增 Server 服务通过端口和适配器隔离。
- 若后台切片失败，保留公开 Contracts 和 Server 测试，但撤销后台入口和运行脚本。
- 不通过修改现有用户 App 实现回滚。

### 配置回滚

- 后台默认不开启任何生产监听。
- 内部沙箱入口使用独立 feature gate，缺失配置时关闭。
- 回滚时关闭后台入口并拒绝所有后台会话。
- 真实能力 feature gates 保持原值 `false`。

### 数据回滚

- 首切片只使用内存合成任务。
- 不需要生产迁移或数据修复。
- 回滚时丢弃内存任务和合成审计数据。
- 不允许为了保留演示状态引入持久化。

### 契约回滚

- 已公开的 DTO 标识不直接改名。
- 若契约设计失败，增加版本或标记未实施字段，不破坏 App 车辆审核契约。
- 禁止把后台专用字段加入用户 App DTO。

### 用户体验回滚

- 后台入口关闭后显示“内部审核工作台暂不可用”。
- 不展示部分可用或伪成功状态。
- 高保真原型保留为设计证据，不作为运行回退页面。
