# 领域事件

本文档定义 PollyCar 已发生业务事实的统一语言。事件名称、业务含义和最小字段属于本文件；状态转换是否合法由 `docs/09-state-machines.md` 定义。

当前重点覆盖弹性参与资格和接单配额。本文档不代表 `docs/decisions/0001-弹性参与资格.md` 已批准生效。

## 事件设计原则

- 事件使用过去时，表示已经发生且不可被直接修改的事实。
- 命令表达“请求做什么”，事件表达“最终发生了什么”，两者不得混用。
- 事件不得包含可从其他受控来源查询且无审计必要的敏感原文。
- 同一业务动作重试时不得产生重复业务结果。
- 事件发布失败不能导致业务状态与审计事实永久不一致。
- 支付、安全冻结和配额占用属于高风险事件，必须具备幂等键和关联链路。

## 通用事件信封

每个持久化领域事件至少包含：

| 字段 | 含义 |
| --- | --- |
| `event_id` | 全局唯一事件标识 |
| `event_type` | 稳定的事件类型标识 |
| `event_version` | 事件结构版本 |
| `aggregate_type` | 聚合类型，例如弹性资格、车主配额 |
| `aggregate_id` | 聚合标识 |
| `aggregate_version` | 聚合版本，用于并发控制 |
| `occurred_at` | 事实发生时间，使用 UTC |
| `recorded_at` | 平台持久化时间，使用 UTC |
| `actor_type` | 车主、审核员、安全人员、财务人员、系统任务或外部回调 |
| `actor_id` | 操作者标识；系统任务使用受控系统主体 |
| `reason_code` | 稳定原因码，不存储自由文本敏感细节 |
| `correlation_id` | 一次业务流程的关联标识 |
| `causation_id` | 直接触发本事件的命令或前序事件标识 |
| `idempotency_key` | 防止同一业务动作重复生效 |
| `trace_id` | 请求或异步链路追踪标识 |
| `data_classification` | 事件载荷的最高数据敏感等级，取值遵循 `docs/11-data-classification.md` |
| `payload` | 事件特有字段 |

## 事件版本与兼容

- 已发布事件字段不得改变既有含义。
- 新增可选字段时增加事件版本并保持旧消费者可处理。
- 删除字段、改变单位、改变枚举含义或拆分事件时必须提供迁移方案。
- 事件消费者必须忽略未知可选字段，不得忽略未知事件版本。
- 事件类型和原因码使用稳定英文标识，中文业务含义由本文档解释。

## 幂等与一致性

- 同一 `idempotency_key` 对同一聚合只能产生一次业务结果。
- 重复命令返回第一次结果，不重复收费、退款、启用、占用或释放额度。
- 聚合写入和事件持久化必须处于同一事务，或使用可证明最终一致的事务性发件箱。
- 消费者使用 `event_id` 去重。
- 外部支付回调同时按平台支付请求标识和支付机构流水去重。
- 安全冻结、资格到期和支付回调并发时，按状态机优先级处理，而不是按消息到达顺序盲目覆盖。

## 数据与审计规则

- 事件中不得保存身份证件照片、完整支付凭据、精确聊天正文或完整位置轨迹。
- 审核材料、证据和支付原始响应存放在受控数据域，事件只保存引用标识和摘要。
- 人工决定必须记录决定人、原因码、依据引用和决定时间。
- 自动决定必须记录规则版本、输入摘要和结果。
- 资格收费、退款、暂停、撤销和申诉决定必须能够从事件链重建。

## 弹性参与资格事件

### `flex_eligibility_application_submitted`：弹性资格申请已提交

- 触发条件：合格车主主动提交申请，且不存在进行中的申请。
- 操作者：车主。
- 前置状态：未申请、已拒绝且允许重新申请、已到期且满足重新申请条件。
- 后置状态：审核中。
- 最小字段：`driver_id`、`application_id`、`policy_version`、材料引用、申请渠道。
- 幂等键：`driver_id + policy_version + client_request_id`。
- 敏感等级：高。
- 消费方：资格审核、审计、通知。

### `flex_eligibility_review_started`：弹性资格审核已开始

- 触发条件：审核任务被审核员或系统领取。
- 操作者：审核员或审核系统。
- 前置状态：审核中。
- 后置状态：审核中。
- 最小字段：`application_id`、`review_id`、审核策略版本。
- 幂等键：`review_id`。
- 敏感等级：内部。
- 消费方：审核时限监控、审计。

### `flex_eligibility_application_approved`：弹性资格申请已批准

- 触发条件：资格、履约、安全和职业化风险检查全部通过。
- 操作者：授权审核员。
- 前置状态：审核中。
- 后置状态：待确认。
- 最小字段：`application_id`、批准依据摘要、资格周期、价格版本、确认截止时间。
- 幂等键：`application_id + approval_version`。
- 敏感等级：高。
- 消费方：支付或免费试验启用流程、通知、审计。

### `flex_eligibility_application_rejected`：弹性资格申请已拒绝

- 触发条件：未满足资格条件或存在阻断风险。
- 操作者：授权审核员。
- 前置状态：审核中。
- 后置状态：已拒绝。
- 最小字段：`application_id`、拒绝原因类别、是否允许申诉、再次申请最早时间。
- 幂等键：`application_id + rejection_version`。
- 敏感等级：高。
- 消费方：通知、申诉、审计。

### `flex_eligibility_confirmation_expired`：资格确认已失效

- 触发条件：车主在确认截止时间前未主动确认。
- 操作者：系统定时任务。
- 前置状态：待确认。
- 后置状态：已失效。
- 最小字段：`application_id`、确认截止时间。
- 幂等键：`application_id + confirmation_deadline`。
- 敏感等级：内部。
- 消费方：通知、审计。

### `flex_eligibility_activation_confirmed`：资格启用已确认

- 触发条件：车主接受资格条款和价格，主动确认启用。
- 操作者：车主。
- 前置状态：待确认。
- 后置状态：免费试验进入待启用；付费试验进入待支付。
- 最小字段：`application_id`、条款版本、价格版本、试验类型。
- 幂等键：`application_id + confirmation_request_id`。
- 敏感等级：内部。
- 消费方：支付流程或免费启用流程、审计。

### `flex_eligibility_payment_succeeded`：资格费用支付成功

- 触发条件：支付机构确认资格费支付成功。
- 操作者：支付回调系统。
- 前置状态：待支付。
- 后置状态：待启用。
- 最小字段：`payment_id`、金额、币种、支付机构流水、价格版本。
- 幂等键：支付机构流水标识。
- 敏感等级：高。
- 消费方：资格启用、财务对账、审计。

### `flex_eligibility_payment_failed`：资格费用支付失败

- 触发条件：支付被拒绝、超时关闭或确认失败。
- 操作者：支付回调系统或支付超时任务。
- 前置状态：待支付。
- 后置状态：待支付或支付失败，具体转换见状态机。
- 最小字段：`payment_id`、失败原因类别、是否可重试。
- 幂等键：支付机构流水或支付尝试标识。
- 敏感等级：高。
- 消费方：通知、支付重试、审计。

### `flex_eligibility_payment_retry_requested`：资格费用支付重试已请求

- 触发条件：确认仍有效且支付策略允许重试时，车主主动再次发起支付。
- 操作者：车主。
- 前置状态：支付失败。
- 后置状态：待支付。
- 最小字段：`payment_attempt_id`、原失败支付引用、价格版本。
- 幂等键：`application_id + payment_retry_request_id`。
- 敏感等级：内部。
- 消费方：支付流程、审计。

### `flex_eligibility_activated`：弹性资格已启用

- 触发条件：免费试验确认完成，或付费试验支付成功；启用日限制和风险状态检查通过。
- 操作者：资格系统。
- 前置状态：待启用。
- 后置状态：已启用。
- 最小字段：`eligibility_id`、开始时间、结束时间、启用日策略版本、配额策略版本。
- 幂等键：`eligibility_id + activation_period`。
- 敏感等级：内部。
- 消费方：配额判定、通知、试验分析、审计。

### `flex_eligibility_activation_rejected`：资格启用已阻止

- 触发条件：确认或支付后发现 90 日启用日、风险冻结、资料有效性等条件不满足。
- 操作者：资格系统。
- 前置状态：待启用。
- 后置状态：启用受阻。
- 最小字段：阻止原因、可重试时间、是否触发退款。
- 幂等键：`eligibility_id + activation_attempt_id`。
- 敏感等级：高。
- 消费方：退款、通知、审计。

### `flex_eligibility_activation_retry_requested`：资格启用重试已请求

- 触发条件：启用阻断原因已解除，系统或授权审核员请求重新执行最终守卫。
- 操作者：资格系统或高级审核员。
- 前置状态：启用受阻。
- 后置状态：待启用。
- 最小字段：原阻断决定引用、解除依据引用、重试请求时间。
- 幂等键：`eligibility_id + activation_retry_id`。
- 敏感等级：高。
- 消费方：资格启用、审计。

### `flex_eligibility_suspended`：弹性资格已暂停

- 触发条件：风险调查、资料过期、指标异常或人工复核阻断。
- 操作者：安全人员、授权审核员或风险系统。
- 前置状态：已启用。
- 后置状态：已暂停。
- 最小字段：暂停原因、证据引用、是否允许申诉、复核截止时间。
- 幂等键：`eligibility_id + suspension_case_id`。
- 敏感等级：严格受限。
- 消费方：配额判定、安全调查、通知、审计。

### `flex_eligibility_suspension_cleared`：资格暂停原因已解除

- 触发条件：材料补齐或风险复核确认阻断原因消除。
- 操作者：授权审核员或安全人员。
- 前置状态：已暂停。
- 后置状态：待恢复。
- 最小字段：复核决定、依据引用、原结束时间。
- 幂等键：`suspension_case_id + clearance_version`。
- 敏感等级：严格受限。
- 消费方：恢复资格、审计。

### `flex_eligibility_restored`：弹性资格已恢复

- 触发条件：暂停原因解除，原资格周期未结束且启用日限制允许恢复。
- 操作者：资格系统。
- 前置状态：待恢复。
- 后置状态：已启用。
- 最小字段：恢复时间、原结束时间、是否因平台错误获得补偿。
- 幂等键：`eligibility_id + restoration_id`。
- 敏感等级：内部。
- 消费方：配额判定、通知、审计。

### `flex_eligibility_revoked`：弹性资格已撤销

- 触发条件：严重安全事件、欺诈、身份车辆不一致、线下收费、商业导流或规避配额。
- 操作者：授权安全人员。
- 前置状态：已启用、已暂停、待恢复。
- 后置状态：已撤销。
- 最小字段：撤销原因、证据引用、重新申请最早时间、是否永久禁止。
- 幂等键：`eligibility_id + revocation_case_id`。
- 敏感等级：严格受限。
- 消费方：配额判定、申诉、退款评估、通知、审计。

### `flex_eligibility_appeal_submitted`：资格申诉已提交

- 触发条件：车主在允许期限内针对拒绝、暂停或撤销提交一次申诉。
- 操作者：车主。
- 前置状态：已拒绝、已暂停、已撤销。
- 后置状态：申诉中。
- 最小字段：`appeal_id`、原决定引用、申诉材料引用。
- 幂等键：`original_decision_id + driver_id`。
- 敏感等级：严格受限。
- 消费方：申诉复核、通知、审计。

### `flex_eligibility_appeal_approved`：资格申诉已批准

- 触发条件：非原决定人员完成复核并推翻原决定。
- 操作者：授权复核人员。
- 前置状态：申诉中。
- 后置状态：待确认、待恢复或已到期，取决于原决定和周期状态。
- 最小字段：`appeal_id`、复核结论、补偿方式、后续状态。
- 幂等键：`appeal_id + decision_version`。
- 敏感等级：严格受限。
- 消费方：资格恢复或重新确认、退款、通知、审计。

### `flex_eligibility_appeal_rejected`：资格申诉已驳回

- 触发条件：复核维持原决定。
- 操作者：授权复核人员。
- 前置状态：申诉中。
- 后置状态：恢复到已拒绝、已暂停或已撤销。
- 最小字段：`appeal_id`、维持原因类别、最终状态。
- 幂等键：`appeal_id + decision_version`。
- 敏感等级：严格受限。
- 消费方：通知、审计。

### `flex_eligibility_expired`：弹性资格已到期

- 触发条件：资格周期结束时间到达。
- 操作者：系统定时任务。
- 前置状态：已启用、已暂停、待恢复。
- 后置状态：已到期。
- 最小字段：周期开始、周期结束、到期时滚动计数摘要、在途订单数量。
- 幂等键：`eligibility_id + period_end`。
- 敏感等级：内部。
- 消费方：配额判定、通知、续期入口、审计。

### `flex_eligibility_refund_requested`：资格退款已创建

- 触发条件：平台错误、政策变化、错误审核或其他符合退款规则的原因。
- 操作者：资格系统、财务人员或申诉流程。
- 前置状态：任意已支付状态。
- 后置状态：不直接改变资格主状态，退款作为独立支付子状态。
- 最小字段：`refund_id`、原支付标识、金额、原因、计算依据。
- 幂等键：`original_payment_id + refund_reason + refund_scope`。
- 敏感等级：高。
- 消费方：支付退款、财务对账、审计。

### `flex_eligibility_refund_completed`：资格退款已完成

- 触发条件：支付机构确认退款完成。
- 操作者：支付回调系统。
- 前置状态：退款处理中。
- 后置状态：退款已完成。
- 最小字段：`refund_id`、支付机构退款流水、金额、完成时间。
- 幂等键：支付机构退款流水。
- 敏感等级：高。
- 消费方：财务对账、通知、审计。

## 配额领域事件

### `quota_evaluation_requested`：配额检查已请求

- 触发条件：车主尝试接受订单。
- 操作者：车主。
- 最小字段：车主、订单、资格状态版本、请求时间。
- 幂等键：`driver_id + trip_id + accept_request_id`。
- 消费方：原子接单事务。

### `quota_evaluation_passed`：配额检查已通过

- 触发条件：车主、车辆、风险、等单和三个滚动窗口全部满足。
- 操作者：配额系统。
- 最小字段：使用的配额策略、三个窗口当前计数和上限、资格状态版本。
- 幂等键：与接单请求一致。
- 消费方：订单接受和额度占用。

### `quota_evaluation_rejected`：配额检查已拒绝

- 触发条件：任一资格、风险或滚动窗口检查不通过。
- 操作者：配额系统。
- 最小字段：拒绝原因类别、命中的窗口、可再次尝试时间。
- 幂等键：与接单请求一致。
- 消费方：用户提示、风险监控、审计。

### `quota_slot_occupied`：配额已占用

- 触发条件：订单接受成功。
- 操作者：订单系统。
- 最小字段：车主、订单、接受时间、配额策略版本、责任状态。
- 幂等键：`trip_id + accepted_driver_id`。
- 消费方：滚动窗口计算、订单流程、审计。

### `quota_slot_released`：配额已释放

- 触发条件：乘客无责取消、平台原因取消或确认不可抗力。
- 操作者：订单系统或授权运营人员。
- 最小字段：原占用事件、释放原因、责任决定引用。
- 幂等键：`original_occupancy_event_id + release_reason`。
- 消费方：滚动窗口计算、审计。

### `quota_slot_finalized`：配额占用已确认计入

- 触发条件：正常完成、车主责任取消、到达后拒绝履约或车主责任安全终止。
- 操作者：订单系统或安全处置流程。
- 最小字段：原占用事件、最终责任类别、完成或终止时间。
- 幂等键：`original_occupancy_event_id + final_responsibility_version`。
- 消费方：滚动窗口计算、职业化风险、试验分析。

## 事件消费边界

| 消费方 | 可消费事件 | 禁止行为 |
| --- | --- | --- |
| 资格系统 | 申请、审核、支付、暂停、到期、申诉事件 | 不得修改支付机构原始流水 |
| 配额系统 | 资格启用、暂停、撤销、到期和配额事件 | 不得绕过订单原子接受 |
| 支付系统 | 支付和退款请求 | 不得改变安全风险结论 |
| 安全系统 | 暂停、撤销、举报和证据事件 | 不得直接修改财务流水 |
| 通知系统 | 面向用户的状态变化 | 不得接收不必要的原始敏感材料 |
| 分析系统 | 脱敏后的资格、配额和试验事件 | 不得用于扩大乘客资料或关系排序 |

完成权限矩阵和数据分类后，再为以下领域补充事件：

1. 车主与车辆审核。
2. 行程创建、接受、履约、取消和安全终止。
3. 支付预授权、扣款、退款和分账。
4. 临时对话确认、开放、关闭、到期和举报冻结。
5. 举报、申诉、安全事件和证据冻结。
