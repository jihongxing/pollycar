# PollyCar App v2 产品设计宪法

## 1. 产品气质

PollyCar App v2 的第一印象应当是：

> 一种安静、可信、有人情味的城市出行选择。

用户不应该觉得自己打开的是：

- 订单管理后台；
- 组件库演示页；
- 豪车会所；
- 社交匹配应用；
- 技术状态观察器；
- 临时拼装的功能集合。

## 2. 四个气质关键词

### 安静

通过留白、低刺激动效、有限主行动和清晰层级减少视觉噪声。

### 可信

通过稳定的状态表达、可预测的操作反馈、克制的颜色和明确的安全入口建立信任。

### 城市

通过地图、路线、时间、位置和光影建立城市出行语境，但不使用俗套的霓虹、速度线或车辆炫耀。

### 有人情味

通过自然的中文、对等待和异常的体谅、适度的联系提示和不冷漠的恢复路径表达温度。

## 3. 视觉方向

### 主方向：夜行纸页

以偏暖的雾白作为阅读底色，以深墨蓝作为结构颜色，以路灯琥珀作为行动强调，以一组低饱和身份色区分乘客、车主和安全。

视觉应当像一张被城市灯光照亮的纸页：

- 背景不纯白；
- 深色不纯黑；
- 强调色不铺满页面；
- 卡片不是默认容器；
- 地图是场景，不是卡片背景；
- 主行动是灯光，不是警报。

### 颜色角色

| 角色 | 候选颜色 | 使用方式 |
| --- | --- | --- |
| 深墨蓝 | `#13243A` | 页面结构、主要文字、深色操作 |
| 雾白 | `#F6F3EC` | 页面背景和大面积阅读区域 |
| 纸白 | `#FFFDF8` | 面板、输入框和消息背景 |
| 路灯琥珀 | `#E3A34A` | 主要行动、选中、关键时间 |
| 乘客青 | `#3D8C92` | 乘客身份和相关状态 |
| 车主蓝 | `#4B72B5` | 车主身份和相关状态 |
| 安全砖红 | `#B75D50` | 真实安全阻断和危险确认 |
| 雾灰 | `#D9D7D0` | 边界、禁用、次要分隔 |

这些颜色是候选令牌，不代表可以直接进入生产代码。

## 4. 视觉反模式

以下表现一旦出现，视为产品感退化：

- 每个区域都被包成卡片；
- 同一页面出现两个以上强调级主按钮；
- 大面积高饱和蓝、黄、红；
- 纯黑背景搭配金色文字制造豪华感；
- 为展示状态而增加状态卡、徽章或说明横幅；
- 用阴影和圆角替代真正的信息层级；
- 每个页面采用不同的标题、按钮和输入框尺寸；
- 用大标题重复用户已经知道的状态；
- 用英文枚举、错误码或 API 字段作为用户文案；
- 正常路径持续强调内部沙箱、权限、配额和系统关闭；
- 失败页面只有“重试”，没有解释和可执行的下一步；
- 图标粗细、圆角和视觉重量不一致；
- 动效表现为闪烁、弹跳、粒子或装饰性庆祝；
- App 页面出现后台表格、技术面板或验收说明。

## 5. 排版规则

### 内容优先级

每个首屏按以下顺序组织：

1. 当前阶段；
2. 当前对象或行程上下文；
3. 用户此刻要做的事情；
4. 一个主要行动；
5. 必要的次要信息；
6. 失败、限制或安全后果。

### 文字气质

- 使用短句和动作动词；
- 避免把内部状态直接翻译给用户；
- 避免“系统提示”“当前状态为”“操作成功”等机械句式；
- 用“下一步”代替抽象的规则说明；
- 重要安全和责任信息必须保留，但放在对应行动附近；
- `24 小时联系建议` 与 `72 小时会话窗口`必须独立表达。

## 6. 组件气质

共享组件应当有稳定的默认形态，业务页面只能改变语义，不应重新发明视觉。

- 主按钮：像明确的行动，不像警报；
- 次按钮：像可逆的选择，不与主按钮争夺注意力；
- 状态面板：只解释当前阻断或下一步；
- 底部面板：承载任务，不把地图降级为背景图片；
- 消息气泡：优先阅读，不使用过重的装饰；
- 身份入口：清晰、重要、但不持续占据页面；
- 安全入口：随时可达，但不制造恐慌；
- Dialog：只用于需要确认或补充信息的关键动作。

## 7. 动效规则

- 页面进入：180–240ms；
- 面板展开：220–280ms；
- 状态变化：160–200ms；
- 主要按钮按下：轻微缩放，不跳动；
- 加载：局部、稳定、保持布局；
- 失败：保留用户输入和上下文；
- 减少动态效果设置下，所有核心信息仍然完整可用；
- 不使用粒子、心跳、速度线、庆祝彩带和模拟车辆疾驰。

## 8. 冻结样板的关系

R01、D01、S01 作为既有业务和交互基线：

- R01 验证地图、底部面板、乘客主行动；
- D01 验证车主身份、上线流程和工作状态；
- S01 验证联系、安全、消息和时间语义。

App v2 可以重新建立共同的视觉系统，但未经重新冻结不得：

- 改变三页的页面结构；
- 改变主行动语义；
- 改变 D01 的自动上线流程；
- 合并 S01 的 24 小时和 72 小时语义；
- 添加技术控制台式信息；
- 以新视觉稿替换业务契约。
