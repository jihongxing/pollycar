# 资金对账设计

## 文档状态

`已批准设计基线；禁止作为生产对账结论`

本设计定义如何证明业务订单、内部支付状态、复式账本和支付机构实际流水一致。对账不是报表功能，而是发现漏单、重复扣款、漏退款、错结算、手续费差异和孤立资金的生产安全机制。

## 对账目标

- 每笔外部资金流水都有内部支付订单和账本交易。
- 每笔内部支付成功、退款、结算和提现都能在支付机构找到对应记录。
- 汇总笔数和金额一致。
- 差异不会静默消失。
- 未解释差异阻止相关资金继续结算、提现或关账。
- 对账过程可重复、可恢复、可审计。

## 四方事实源

| 事实源 | 权威范围 | 不能单独证明 |
| --- | --- | --- |
| 业务订单与责任结论 | 应收金额、履约结果、退款和取消责任 | 支付机构是否实际扣款或退款 |
| 内部支付聚合 | 平台支付、退款、结算和提现状态 | 内部账务是否平衡 |
| 内部复式账本 | 资金归属、应收、应付、收入和费用 | 支付机构是否实际执行 |
| 支付机构流水与账单 | 外部扣款、退款、手续费、清算和付款事实 | 业务责任和平台内部归属 |

正式对账必须使四方通过稳定引用闭环。

## 对账层级

### 实时事件核对

每次支付机构回调或主动查询后立即检查：

- 商户号和应用标识。
- 平台订单号。
- 支付机构订单号。
- 金额和币种。
- 事件类型和状态转换。
- 是否已经入账。
- 是否存在重复事件。

实时核对用于快速阻断异常，但不能替代账单对账。

### 日内运营对账

定时扫描：

- 长时间处于 `processing` 或 `unknown` 的支付、退款、结算和提现。
- 支付成功但没有账本交易。
- 有账本交易但支付聚合状态不一致。
- 已退款但业务责任仍显示未退款。
- 已结算但存在安全冻结或争议。
- 孤立支付、孤立退款和孤立回调。

### 支付机构账单对账

下载支付机构提供的交易、退款、清算、手续费、分账和提现账单，完成逐笔和汇总对账。

### 日终关账对账

在账务日结束后验证：

- 当日各类交易笔数。
- 当日各类交易金额。
- 支付机构应收变化。
- 银行或支付机构清算变化。
- 乘车人待履约资金变化。
- 车主应付款变化。
- 退款应付款变化。
- 平台收入、税费和手续费变化。
- 运营主体经营份额应付款变化。
- 期初余额、当日变动和期末余额关系。

总金额差异不为零时不得正式关账。

## 对账输入

### 内部标准记录

统一生成 `ReconciliationRecord`：

```text

merchant_id
internal_order_id
provider_order_id
provider_event_id
amount_minor
fee_minor
currency
state
occurred_at
settled_at
source_digest
```

### 支付机构账单

账单进入系统前必须完成：

- 来源身份验证。
- 文件签名或摘要验证。
- 文件日期和商户号校验。
- 重复文件检测。
- 原始文件加密保存。
- 解析器版本记录。
- 总行数和控制金额校验。

解析失败不能生成部分成功的正式对账批次。

## 匹配键

优先使用：

1. 支付机构订单号。
2. 平台支付订单号。
3. 支付机构退款、分账或提现 ID。
4. 商户号。
5. 币种和金额。

禁止仅依赖金额和时间进行自动确定匹配。无法通过稳定唯一引用匹配时，进入人工差异案件。

## 差异分类

| 差异类型 | 示例 | 默认处置 |
| --- | --- | --- |
| `provider_only_payment` | 支付机构扣款成功，内部无支付订单 | 冻结、创建孤立支付案件、优先确认退款或补建合法订单 |
| `internal_only_payment` | 内部显示成功，支付机构无成功记录 | 阻止匹配和结算，主动查询 |
| `payment_amount_mismatch` | 支付机构金额与报价不同 | 最高优先级冻结，不自动入账 |
| `duplicate_provider_payment` | 同一业务订单出现多笔成功扣款 | 保留一笔合法支付，其余创建退款案件 |
| `provider_only_refund` | 支付机构已退款，内部无退款记录 | 冻结后续结算，补建退款事实和账本 |
| `internal_only_refund` | 内部显示退款，机构未执行 | 重试查询或重新提交原退款，不创建新业务退款 |
| `refund_amount_mismatch` | 退款金额不一致 | 冻结责任结论和剩余结算 |
| `ledger_missing` | 支付或退款成功但无账本交易 | 阻止关账，按原事件补记幂等账本交易 |
| `ledger_duplicate` | 同一外部事件产生多笔账本交易 | 冻结并创建冲正评审 |
| `fee_mismatch` | 支付手续费与合同规则不一致 | 财务复核和供应商申诉 |
| `settlement_mismatch` | 支付机构清算金额与账本应收不同 | 阻止关账和资金确认 |
| `payout_mismatch` | 车主付款状态或金额不同 | 冻结相关车主提现和重复付款 |
| `operator_settlement_mismatch` | 运营主体应收 `85%` 与支付机构实际清算不同 | 冻结运营主体结算、车主付款和账务日关闭 |
| `revenue_share_mismatch` | 平台、运营主体和车主份额之和不等于可分配金额 | 拒绝入账并创建最高优先级资金案件 |
| `chargeback_unrecorded` | 支付机构发生拒付，内部未记录 | 冻结相关应付款并创建安全财务案件 |

## 自动处置边界

允许自动执行：

- 对未知状态查询原请求。
- 对重复回调返回原处理结果。
- 对缺失但可以通过唯一事件确定的账本交易执行幂等补记。
- 对明确未提交成功的同一退款请求按原幂等键重试。
- 对跨账务日时间差在下一批次自动复核。

禁止自动执行：

- 根据相同金额猜测两笔流水属于同一订单。
- 自动核销任何非零金额差异。
- 修改原支付、退款或账本流水。
- 在金额不一致时自动以支付机构金额覆盖内部报价。
- 自动向用户再次扣款弥补差异。
- 在争议、安全冻结或拒付状态继续分账或提现。
- 在运营主体 `85%` 未完成对账时把车主 `40%` 标记为已付款。

## 差异处理权限

| 操作 | 经办人 | 复核人 | 约束 |
| --- | --- | --- | --- |
| 查看差异 | 财务运营、安全审计 | 不需要 | 数据按最小权限脱敏 |
| 标记时间差 | 财务经办 | 财务复核 | 下一批次强制复核 |
| 发起补记账本 | 财务经办 | 财务复核 | 必须引用确定外部事件 |
| 发起退款补偿 | 财务经办 | 独立财务复核 | 不能由原责任认定人单独批准 |
| 发起冲正 | 财务经办 | 财务负责人或授权复核人 | 必须引用原交易 |
| 关闭差异案件 | 财务经办 | 财务复核或审计 | 差异金额必须归零或有外部书面结论 |

## 对账任务可靠性

- 每个账单文件建立唯一摘要，重复导入返回原批次。
- 对账任务支持断点续跑。
- 批次重跑不能重复创建差异、账本交易或退款。
- 文件解析、逐笔匹配、汇总校验和案件创建分阶段持久化。
- 任务失败进入有限重试，超过上限进入人工队列。
- 对账服务不可用时不影响用户查看历史记录，但必须阻止受影响资金关账和继续结算。

## 关账门禁

以下条件全部满足后才能关闭账务日：

- 支付机构账单完整且签名或摘要校验通过。
- 账单总笔数和总金额控制值一致。
- 支付、退款、清算、手续费、分账和提现均已完成对应对账。
- 平台 `15%`、运营主体 `45%` 和车主 `40%` 的分配总额与订单可分配金额一致。
- 运营主体 `85%` 外部清算与运营主体经营份额、车主应付款和逆向资金一致。
- 内部账本借贷平衡。
- 所有非时间性差异金额为零。
- 时间性差异已有下一批次自动复核计划。
- 高风险孤立资金案件已经冻结后续动作。
- 关账操作完成经办和复核。

## 指标和告警

必须至少监控：

- 未匹配外部流水笔数和金额。
- 未匹配内部流水笔数和金额。
- 金额不一致笔数和金额。
- 重复扣款和重复退款笔数。
- 支付成功缺失账本笔数。
- 退款成功缺失账本笔数。
- 未知状态持续时间。
- 对账批次完成延迟。
- 未解决差异最长时间。
- 孤立支付、退款、结算和提现数量。

告警原则：

- 任意非零金额无法解释时立即阻止相关结算和关账。
- 任意支付金额不一致按最高等级处理。
- 任意重复真实扣款立即进入用户补救和资金安全流程。
- 不以“比例较低”为理由忽略真实资金差异。

## 数据保留

- 账本交易、账本分录、会计凭证和年度关账证据采用 `30 年`内部保守基线。
- 支付、退款、结算、提现、拒付、正式对账批次、支付机构及银行账单原文件、差异案件和审批证据采用 `10 年`内部保守基线。
- 没有发生资金效果的失败支付尝试采用 `5 年`内部保守基线；到期后删除敏感载荷，只保留满足防重和审计所需的最小摘要。
- 上述期限是架构实施基线，正式生产期限仍需财务、税务、法律和隐私负责人签署。
- 原文件加密保存并限制下载。
- 对账日志不记录支付密钥、完整银行卡号或身份明文。
- 删除用户账户不能删除依法必须保留的财务证据，但必须隔离并限制用途。

## 阶段七合成对账内核实现

阶段七新增四方标准事实、对账批次、持久化差异项、恢复动作和账务日关闭内核：

- `FinancialReconciliationService` 从业务订单、支付聚合、复式账本和支付机构账单四方事实执行逐笔、汇总笔数、汇总金额和手续费核对。
- 账单文件使用唯一 SHA-256 摘要；相同摘要重复执行返回原批次，不重复创建差异或恢复动作。
- 支付金额差异、手续费差异、重复支付机构账单、迟到回调、未知结果、支付聚合缺失和账本缺失均生成确定性持久化差异项。
- 未知结果只允许查询原请求；迟到事件进入下一批次复核；缺失账本只允许按确定事件幂等补记；重复支付进入独立退款案件，不允许盲目再次扣款。
- 恢复动作完成只代表恢复操作执行完毕，不自动清除差异或解除资金门禁。
- 差异解除必须逐项记录解决类型、证据引用，并由不同的经办人与复核人确认；缺失任一项时数据库拒绝解决，全部当前差异解决后，批次才能重新进入 `balanced`。
- `settlement`、`payout` 和 `close` 三类动作统一调用数据库门禁函数；批次未关闭、存在任何未解决案件或差异不为零时全部拒绝。
- 账务日关闭要求当日所有批次已关闭，并强制经办人与复核人不同。

正式迁移为 `apps/server/migrations/0008_financial_reconciliation.sql`。运行时角色只能读取专用表和执行六个 `SECURITY DEFINER` 函数，不能直接插入、更新或删除对账记录。

统一验证命令：

```powershell
pnpm test:ledger:stage7
```

该命令在一次性本机 PostgreSQL 17 中执行完整迁移链，以真实 `pollycar_ledger_runtime` 登录验证：

1. 四方逐笔和汇总一致的批次可以关闭，并允许清算、付款和关账门禁。
2. 任意非零逐笔或汇总金额差异同时阻止清算、付款和关账。
3. 相同账单摘要重复执行只保留一个批次和一组差异项。
4. 手续费、重复账单、迟到回调和未知结果均创建持久化恢复动作。
5. 恢复动作支持失败记录、按原请求重试和完成状态。
6. 运行时角色直接写对账表被数据库权限拒绝。

阶段七不下载真实支付机构账单，不接入真实业务订单、支付聚合、银行流水或生产数据库。阶段八仅获得合成多运营主体资金编排的实施资格，真实结算和真实付款仍需独立批准。
- 诉讼、调查、拒付、安全案件或监管要求触发时，对关联记录暂停删除。

## 验收场景

### 正常

- 支付、账本和支付机构账单逐笔及汇总一致。
- 退款、手续费、结算和提现分别完成对账。
- 日终批次差异金额为零并完成双人关账。

### 重复与并发

- 同一账单重复导入不会创建第二批次。
- 同一支付机构事件重复出现不会重复入账。
- 两个对账任务并发处理同一记录只生成一个差异项。

### 异常

- 支付机构有成功扣款、内部无订单。
- 内部支付成功、支付机构无记录。
- 金额、币种、商户号或订单号不一致。
- 退款一方成功、另一方未知。
- 支付成功但账本缺失。
- 同一支付事件存在重复账本分录。
- 支付机构账单缺页、摘要错误或控制金额不一致。
- 对账中途数据库重启后可以恢复。
- 关账后发现迟到回调，使用下一期间调整而非修改历史。

### 权限

- 客服不能关闭资金差异。
- 经办人不能批准自己的补记、退款或冲正。
- 开发人员不能在生产后台创建财务调整。
- 审计人员只能读取，不能执行资金动作。

## 验收标准

- 四方事实源可以按稳定唯一引用逐笔关联。
- 每个对账批次有输入摘要、控制总数、控制金额和处理版本。
- 任意非零金额差异都生成持久化差异项。
- 差异不能通过修改原流水消除。
- 对账重跑不产生重复账本、退款或案件。
- 差异未解决时相关结算、提现和关账被阻止。
- 已关闭批次可以完整重放并得到同一结果。
- 所有人工处置具备经办、复核、原因和证据。

## 评审结论与剩余阻断

| 原未决事项 | 收敛结论 | 状态 |
| --- | --- | --- |
| 支付机构账单格式、下载方式和签名机制 | 通过供应商适配器标准化，必须验证来源、摘要、商户号、控制笔数和金额；具体格式随供应商评审 | 部分收敛 |
| 账务日和账单时区 | `Asia/Shanghai` 自然日 | 已收敛 |
| 对账执行频率和恢复时限 | 实时事件核对、每 15 分钟日内扫描、每日正式账单对账；未知结果超过受控恢复窗口进入人工案件 | 已收敛 |
| 财务差异案件角色和审批链 | 财务经办、独立财务复核、只读审计；客服和开发无资金处置权 | 已收敛 |
| 财务证据保留期限 | 系统支持分类型期限；专业期限映射完成前禁止真实数据自动删除 | 外部阻断 |
| 银行流水是否纳入第五方对账 | 只要平台控制银行账户发生资金变化，银行流水必须纳入第五方核对 | 已收敛 |

本设计允许进入合成对账内核，不构成支付机构账单格式或法定保留期限批准。
