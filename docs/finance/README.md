# 资金设计索引

## 当前状态

`架构设计已批准；允许合成内核实现；禁止真实资金生产启用`

本目录定义 PollyCar 未来真实资金能力的架构基线。它用于回答“金额如何保证正确、资金请求如何证明合法、账务如何保持平衡、平台如何与支付机构完成对账”，不构成真实支付、退款、分账、绑卡、提现或生产启用批准。

以下门禁持续关闭：

```yaml
production_enabled: false
real_payment: false
real_settlement: false
real_bank_card_binding: false
real_withdrawal: false
paid_flex_trial: false
```

1. 已批准的高风险决策优先。
2. 生产门禁和安全停止线优先。
3. 未批准的设计不得改变已实现的零金额沙箱行为。

## 评审顺序

1. 评审真实资金边界、支付模式和供应商责任。
2. 评审复式账本、会计科目和资金归属。
3. 评审对账频率、差异处置和日终关账。
4. 由财务、税务、法律、安全和最终决策人共同确认。
5. 评审通过后才允许形成机器契约和路线图实施任务。

## 实施依赖顺序

资金系统必须按事实源依赖从底向上实现，不得因为多运营主体页面或业务流程更直观而提前建立上层余额和付款状态。

1. **复式账本内核**：先建立金额类型、账本账户、账本交易、账本分录、余额投影、数据库平衡约束、只追加、冲正、幂等和余额重建。
2. **资金对账与关账**：再建立业务、支付聚合、复式账本和支付机构四方事实源的逐笔与汇总对账、差异案件、阻断和异常恢复。
3. **多运营主体管理与结算**：只有前两层验收通过后，才实现运营主体分配、清算批次、车主付款、提前结算关闭态和资金案件。

多运营主体可以定义主体资料、主运营关系和合同快照，但不得自行维护余额、累计应付或已付款事实。所有资金状态必须来自复式账本交易和对账结果。

进入第三步前必须同时满足：

- 复式账本 PostgreSQL 表、迁移和 Repository 已完成。
- 借贷不平衡交易由数据库拒绝，不能只依赖应用层检查。
- 来源事件、交易类型和幂等键的唯一性已经过并发验证。
- 历史交易只允许追加冲正，不允许修改或删除。
- 余额投影可以从全量分录重建并得到完全一致的结果。
- 对账差异能够阻止清算、车主付款和账务日关账。
- 数据库重启、重复事件、迟到回调和未知结果恢复测试通过。

## 统一停止线

出现以下任一情况时，不得进入真实供应商接入或生产启用：

- 无法确认平台、支付机构、乘车人和车主之间的资金法律关系。
- 无法使用持牌支付机构完成收款、原路退款、分账、查询、验签和对账。
- 账本不支持不可变复式分录和冲正。
- 任意资金动作依赖 App 上传的金额作为权威金额。
- 支付、退款、结算、提现或对账允许绕过幂等和权限校验。
- 支付机构账单无法逐笔关联到内部支付订单和账本交易。
- 存在可以直接修改余额、删除流水或无复核人工调账的入口。
- 真实支付门禁可能被单一环境变量或客户端配置打开。
