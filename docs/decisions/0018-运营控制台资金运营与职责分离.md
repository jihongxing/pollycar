# 决策 0018：运营控制台资金运营与职责分离

## 决策状态

- 状态：`已批准进入默认关闭门禁后的合成代码实现`
- 设计批准日期：`2026-07-14`
- 适用环境：仅内部沙箱与合成数据
- 默认门禁：`synthetic_admin_finance_operations=false`
- 生产启用：禁止

## 背景

复式账本、资金对账和多运营主体资金编排已经完成合成内核，但运营控制台尚未形成统一的资金任务、主体隔离、复核、异常恢复和页面契约。若直接把现有应用服务包装为后台 CRUD，会产生影子余额、绕过对账门、职责混同、未知结果重复提交和跨运营主体数据泄露风险。

本决策只确定资金运营后台的任务和交互边界，不改变 `0013`、`0014` 以及 `spec/finance/` 已冻结的账本、对账、分配、清算和付款事实。

## 最终决策

### 权威事实源

后台不得拥有或复制资金权威状态。唯一事实源固定为：

- 支付订单、支付尝试和退款单：支付聚合领域；
- 账本交易、分录和余额投影：`pollycar_finance` 复式账本；
- 四方对账、差异、恢复动作和账务日：资金对账内核；
- `15%/45%/40%` 分配、运营主体清算批次、车主付款批次和资金案件：多运营主体资金编排内核。

后台只可拥有工作任务、复核分派、临时导出授权和未知结果恢复任务，不得建立运营主体余额表、车主余额表、钱包表或可编辑金额副本。

### 组织与角色

平台组织使用：

- `finance_officer`：准备批次、发起退款或完整冲正申请、调查差异；
- `finance_lead`：独立复核批次、退款例外、完整冲正、差异解决和账务日关闭；
- `auditor`：只读账本、对账、批次和审计；
- `technical_operations`：只查询原幂等请求、Outbox 和权威状态，不作业务决定。

运营主体组织使用：

- `operator_finance_officer`：查看本主体分配、准备本主体车主付款批次、处理本主体资金案件；
- `operator_finance_lead`：独立复核本主体车主付款批次和资金案件处置；
- 运营主体人员不得读取其他主体的付款明细、收款引用、清算批次或资金案件。

高层驾驶舱属于阶段五，本阶段不授予高层资金经办权限。

### 唯一写入路径

所有后台写动作必须通过一个资金运营命令入口，并映射到既有资金领域命令。命令必须携带：

- 幂等键；
- 请求摘要；
- 资源版本；
- 组织上下文；
- 理由码；
- 关联对账运行、业务日期或原交易标识；
- 经办人与复核人标识。

后台不得直接写账本表、对账表、分配表、清算表、付款表或余额投影。未知结果期间，同资源同动作冻结，只允许查询原请求。

### 金额与余额

- 所有金额由 Server 以整数最小货币单位返回，并同时返回币种；
- 页面负责格式化，不参与金额计算；
- 分配比例固定读取 `allocation-15-45-40-v1`，页面不得编辑；
- 车主付款手续费由运营主体承担，不减少车主应付款；
- 审批页面不得修改批次金额、退款金额、分配金额或账本分录；
- 所有“余额”只能来自账本余额投影，并显示投影时间和重建状态。

### 资金动作边界

- 分配：只读查询，不提供手工分配或改比例入口；
- 运营主体清算：平台财务经办准备，独立负责人复核后调用既有清算命令；
- 车主付款：运营主体财务经办准备 `T+1` 批次，独立负责人复核；提前结算继续关闭；
- 退款：引用原支付和责任结论，不使用负数支付，不覆盖原记录；
- 完整冲正：只允许引用一笔可冲正原交易，方向相反、金额相同，不提供任意手工记账；
- 差异解决：必须有原因、证据引用和独立复核，非零差异不得自动核销；
- 日终关账：全部对账运行关闭、四方事实完整且差异为零后，方可双人关闭；
- 账本查询：只读、按组织和数据等级过滤，不支持修改、删除或导出严格敏感原文。

### 对账硬门

任何以下情况必须同时阻止清算、车主付款和账务日关闭：

- 未解决非零差异；
- 未解决零金额案件；
- 缺失或无效支付机构账单；
- 对账运行未关闭；
- 未知结果恢复未完成；
- 资金案件仍标记为阻断。

前端禁用仅用于解释，Server 和数据库门禁必须再次拒绝。

### 职责分离

以下动作的经办人与复核人必须不同：

- 运营主体清算批次；
- 车主付款批次；
- 退款例外；
- 完整冲正；
- 对账差异解决；
- 账务日关闭；
- 受控资金导出。

同一内部用户不得通过切换组织上下文规避职责分离。

### 页面范围

阶段四固定为七页：

1. 资金运营中心；
2. 分配与运营主体清算；
3. `T+1` 车主付款；
4. 退款与完整冲正；
5. 对账差异与资金案件；
6. 日终关账；
7. 账本查询。

不保留其他实现候选供编码阶段选择。

## 明确禁止

- 运营主体或车主钱包；
- 余额编辑、补余额或覆盖历史金额；
- 任意借贷分录编辑器；
- 绕过对账门执行清算、付款或关账；
- 经办人复核自己的动作；
- 未知结果后创建替代请求；
- 运营主体跨主体查看付款或资金案件；
- 提前结算、真实清算、真实付款、真实退款或生产启用。

## 实现准入

当前批准：

- 编写阶段四契约、验收场景、授权规则、错误语义和高保真原型；
- 运行设计与治理检查。
- 在 `synthetic_admin_finance_operations` 默认关闭门禁后实现合成应用服务、唯一 HTTP 命令入口和七页后台工作区；
- 只使用合成权威快照，复用阶段一服务端组织上下文、统一授权和追加式审计。

当前未批准：

- 开启 `synthetic_admin_finance_operations`；
- 接入真实支付机构、真实账单、真实收款账户或真实资金。

阶段四合成代码实现已于 `2026-07-14` 获得明确批准。真实资金、真实账单、真实支付机构、真实收款账户和生产启用仍需新的独立批准。
