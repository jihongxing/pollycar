# 0032 车主上线前人脸活体检测

## 决策状态

已批准进入合成沙箱与关闭态生产级实现；真实生物识别、真实人脸数据和生产启用继续关闭。

## 实现状态

截至 2026-07-30，合成沙箱实现已经完成：

- Server 已实现随机一至三个动作、挑战过期、结果归类、五分钟一次性上线授权、账户／设备／登录会话／挑战／策略版本绑定、幂等、并发消费、重放防护和审计；
- 所有 `offline → online` 入口均由服务端消费活体授权，`online → busy → online` 保留同一上线会话，下线、强制下线、退出、设备或登录会话变化会使再次上线重新检测；
- App 已实现相机权限、动作引导、进度反馈、自动上线、权限拒绝、动作失败、超时、未知结果、网络异常和重试恢复；
- 合成 App 只请求并释放相机权限，不向业务 API 上传照片或视频；业务数据库、日志和审计不保存原始媒体、人脸模板或完整供应商令牌；
- 真实供应商仅保留安全接口和失败关闭适配器，`real_driver_liveness_verification=false`、`real_biometric_verification=false` 和 `external_identity_provider=false` 保持不变。

真实供应商接入仍需完成供应商、合同与数据处理条款、隐私影响、生物识别单独同意、数据驻留与删除、公平性和可访问性、反欺骗攻击、人工恢复与申诉、设备覆盖以及跨职能批准。

## 背景与待解决问题

现有车主上线流程允许具备车主身份的账户直接从离线切换为在线。该流程不能证明当前操作人仍是已授权车主，也不能降低账号借用、设备转交、照片或预录视频冒用等风险。

本决策在车主每次开始新的上线接单会话前增加主动人脸活体检测。检测不是新的实名流程，也不替代账户、车辆、资格、安全限制和位置门禁。

## 决策目标与非目标

### 目标

1. 每次 `offline → online` 前验证当前操作人正在摄像头前完成随机动作。
2. 服务端签发短时、一次性、绑定账户、设备、会话和上线请求的活体授权。
3. 活体检测未通过、结果未知、超时或服务不可用时禁止上线。
4. 支持版本化扩展动作，不把动作集合固化为三个客户端分支。
5. 默认不由 PollyCar 业务服务保存原始视频、照片或人脸模板。

### 非目标

- 不以活体检测替代成年资格、真实身份核验或车辆审核。
- 不在后台持续采集人脸，也不在车主在线期间静默录制。
- 不因一次检测失败永久冻结账号。
- 不允许客户端自行随机动作、自行判断通过或直接声明上线资格。

## 最终决策

### 触发规则

1. 车主每次从 `offline` 请求进入 `online`，必须重新完成一次活体检测。
2. 车主主动下线、被安全策略强制下线、退出账户、切换设备或上线会话失效后，再次上线必须重新检测。
3. 同一上线会话中的 `online → busy → online` 不因完成一笔行程自动重检；账号风险、设备变化、会话超时或人工安全处置可以强制结束上线会话并要求重新检测。
4. `returnOnlineAfterTrip` 只能恢复同一未失效上线会话，不能绕过已经结束或被撤销的活体授权。

### 随机动作

基础动作至少包括：

- `turn_head_left`：向左转头；
- `turn_head_right`：向右转头；
- `open_mouth`：张开嘴巴。

动作集合允许扩展为眨眼、点头、跟随屏幕目标等能力，但必须满足：

- 由 Server 或受信供应商按策略版本生成；
- 每次挑战随机选择一至三个动作并固定顺序；
- 返回动作标识、用户可理解的指令、单步时限和总时限；
- 客户端不得替换、跳过或重排；
- 新动作必须经过准确率、可访问性、欺骗攻击和设备兼容性评审；
- 因身体条件无法完成某类动作时提供受控替代流程，不得以无限重试代替申诉或人工处理。

### 状态与授权

活体任务状态为：

`created → in_progress → passed | failed | expired | cancelled | result_unknown`

规则如下：

1. 一个账户在同一设备和登录会话中最多存在一个有效挑战，新挑战使旧挑战失效。
2. 挑战默认五分钟失效，动作完成窗口由策略版本定义。
3. `passed` 后由 Server 签发 `livenessAuthorizationToken`，默认五分钟有效且只能消费一次。
4. 授权绑定 `accountId + deviceId + accountSessionId + challengeId + policyVersion`。
5. 上线成功即消费授权；上线请求失败时，仅可对明确可重试的技术错误保留授权，业务拒绝和身份变化必须撤销。
6. 下线会立即结束本次上线会话；已消费授权不得用于再次上线。

### 服务端强制边界

车主上线请求必须同时满足：

- 当前账户会话有效且当前身份为车主；
- 车辆、驾驶资格、账号状态和安全限制允许上线；
- `livenessAuthorizationToken` 有效、未消费、未撤销且绑定信息一致；
- 幂等键和预期版本有效；
- 其他既有上线与位置规则通过。

缺少或无效的活体授权返回 `DRIVER_LIVENESS_REQUIRED`，不得先上线后补检。

### 供应商与数据边界

1. App 只通过受控原生 SDK 或供应商会话采集检测所需画面。
2. PollyCar 业务 API 优先只接收供应商会话引用、签名结果或一次性结果令牌，不接收原始视频。
3. 供应商回调必须验签、校验时间窗、请求摘要和回调幂等键。
4. 业务数据库仅保存挑战 ID、策略版本、动作标识、结果分类、时间、设备摘要、供应商请求摘要、授权消费状态和审计引用。
5. 原始影像、人脸特征模板和供应商侧保留期限必须单独批准；未批准时禁止采集或保留。
6. 日志、监控、错误上报和分析系统不得记录原始影像、人脸模板、完整供应商令牌或可逆设备标识。

### 失败与恢复

- 用户取消、摄像头权限拒绝、未检测到人脸、动作不匹配、疑似翻拍、超时、挑战过期和次数超限均保持离线。
- 供应商超时或结果未知不得自动按通过处理；系统应查询结果或创建新挑战。
- 默认连续失败五次进入冷却期；具体时长和人工恢复责任需在真实供应商接入前批准。
- 客户端崩溃或网络中断后可以恢复仍有效的挑战，但不能上传本地自判结果。
- 供应商不可用时失败关闭，不提供“跳过后上线”按钮。

## 产品和业务影响

1. 车主点击“上线接单”后先进入全屏活体检测任务。
2. 页面只表达当前动作、剩余时间、重试或求助方式，不展示供应商错误码、置信度或内部风控规则。
3. 检测通过后自动继续原上线请求；失败或取消后返回车主首页并保持离线。
4. 下线后再次点击上线必须创建全新挑战。
5. 摄像头权限需要在进入检测前说明用途，并只在用户主动开始后申请。

## 安全、隐私、合规与公平性影响

- 人脸与活体数据属于高敏感身份数据，真实接入前必须完成隐私影响评估、单独授权、最小化、保存删除、供应商责任、数据驻留和安全事件响应评审。
- 必须测试照片、屏幕翻拍、预录视频、换脸、注入相机流、回调伪造、令牌重放、设备切换和并发挑战。
- 必须评估光照、肤色、年龄、面部差异、辅助器具、低端设备和身体障碍带来的误拒差异。
- 活体失败不能直接推导欺诈结论；欺诈处置必须有独立证据和申诉机制。

## 验收标准

- 所有 `offline → online` 路径在没有有效一次性活体授权时失败。
- 下线后原授权不可复用，再次上线生成不同挑战。
- 动作至少覆盖向左转头、向右转头和张嘴，并支持版本化扩展。
- 并发挑战、过期挑战、错误设备、错误会话、重复消费和伪造回调均被拒绝。
- 供应商超时、未知结果和客户端中断保持离线。
- 合成沙箱不采集真实人脸，只允许明确标识的合成场景。
- 原始影像不进入业务数据库、普通日志、分析系统或审计详情。

## 生效与退出条件

### 合成沙箱生效条件

- 领域与 API 契约、状态机、合成 Adapter、一次性授权和专项测试完成；
- `real_driver_liveness_verification` 与 `real_biometric_verification` 保持关闭；
- 所有合成响应继续标记 `synthetic: true`。

### 真实供应商测试条件

- 产品、移动端、身份合规、隐私、安全、法务和供应商采购完成书面批准；
- 数据流、保留删除、回调验签、密钥、测试账号和事件响应方案完成；
- 仅允许供应商测试数据和受控测试人员，不允许真实车主生产上线。

### 退出条件

- 误拒、公平性、安全攻击或供应商数据处理不能达到批准阈值时停止真实接入；
- 停止后撤销供应商凭据、关闭门禁、删除可删除数据并保留不可变审计证据。
