# 0031 生产构建供应链与凭据防线

## 决策状态

已批准实现；生产发布继续关闭。

## 背景与待解决问题

Android 发布构建曾复用调试签名，高德 Android Key 曾出现在受版本控制的 Manifest，HTTP 路由重复读取未限制大小的请求体，数据库迁移缺少跨实例锁和内容校验，且 GitHub 未执行自动化安全门禁。

## 最终决策

1. Android `release` 仅在独立发布签名配置完整时使用发布签名；未配置时只允许生成未签名 Release 用于 CI 编译，禁止回退到调试签名。
2. 高德 Android Key 只通过构建占位符和受控环境变量注入；已提交 Key 视为泄漏，必须由企业账户负责人完成吊销、轮换和绑定复核后才可启用真实地图。
3. Server 统一使用受限请求体读取接口，默认上限为 256 KiB；头像上传维持独立上限。
4. PostgreSQL 迁移必须持有 advisory lock，记录 SHA-256 checksum，并在查询失败或 checksum 不一致时失败关闭。
5. GitHub CI 必须执行高危依赖审计、类型检查、测试、构建、PostgreSQL 集成测试、Android/iOS Release 编译、CycloneDX SBOM 和漏洞扫描。
6. 镜像运行与发布只接受不可变 digest；镜像推送和 keyless 签名仅在仓库变量明确批准且标签发布时执行。

## 验收标准

- 生产门禁要求 Android 与 iOS 独立签名模式，且 Android Release 不再引用调试签名。
- 仓库静态检查不发现 Android Manifest 中的 32 位明文高德 Key。
- 所有 HTTP JSON 路由使用统一请求体读取边界。
- 迁移测试覆盖锁、checksum 不一致和查询失败。
- CI 工作流已纳入仓库，但不代表外部批准、云镜像仓库或生产凭据已经就绪。
