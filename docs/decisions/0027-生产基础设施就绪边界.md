# 0027 生产基础设施就绪边界

## 状态

已批准。

## 日期

2026-07-25。

## 背景

PollyCar 需要从内部沙箱配置过渡到可验证的正式基础设施，但当前尚未获得任何真实业务能力的启用批准。直接复用内部沙箱启动入口会保留本机数据库、回环监听、合成数据和业务路由，无法建立正式 PostgreSQL、HTTPS、密钥和监控边界。

## 决策

1. 新增独立 `ProductionConfig`，不得修改或放宽 `createInternalSandboxConfig()` 的本机和合成数据限制。
2. 正式基础设施模式固定为 `infrastructure-readiness`：环境为生产，数据模式为 `real-disabled`，全部业务门禁和业务路由保持关闭。
3. 正式数据库必须是远程 PostgreSQL，连接必须声明 TLS；本机地址、非 PostgreSQL 地址和未声明 TLS 的连接串一律拒绝。
4. TLS 在受信反向代理终止。公开地址、允许来源和 OTLP 端点必须为非本机 HTTPS 地址；服务端只接受带有 HTTPS 转发协议的请求。
5. 生产配置只接受托管密钥系统引用，不允许原始供应商 API Key、Access Key、Private Key 或 Token 出现在环境配置中；数据库连接串、密钥和凭据不得写入日志。
6. 生产基础设施服务只提供 `/health/live` 与 `/health/ready`。就绪检查必须验证 PostgreSQL 连通性，任何业务路径一律返回“业务能力尚未开放”。
7. 启动日志仅记录服务名、发布模式、健康检查地址和 OTLP 端点，不记录数据库连接串或密钥。

## 不在本阶段

- 启用真实数据、真实短信、正式认证、真实后台账号、地图、定位、车辆位置或任何支付能力；
- 迁移或写入真实用户数据；
- 发布面向用户或运营人员的正式业务 API；
- 指定或接入某一家真实密钥管理、监控、反向代理或云数据库供应商。

## 验证要求

- `ProductionConfig` 必须拒绝缺失或不安全的 PostgreSQL、HTTPS、密钥和监控配置；
- 所有业务门禁在生产基础设施模式下必须为 `false`；
- 存活、就绪、HTTPS 代理和业务路由关闭均须具备自动化测试；
- 生产运行契约、文档治理、门禁对齐、全仓类型检查、测试和构建必须通过；
- 后续接入真实供应商前必须补充对应批准证据、正式密钥系统和部署验收。
