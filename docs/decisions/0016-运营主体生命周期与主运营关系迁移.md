# 决策 0016：运营主体生命周期与主运营关系迁移

## 决策状态

`已批准`

- 批准日期：`2026-07-14`
- 实施批准日期：`2026-07-14`
- 允许范围：机器契约、合成数据、内部沙箱、高保真设计，以及默认关闭的 `synthetic_admin_operator_management` 门禁后的阶段二合成代码实现
- 禁止范围：真实运营主体入驻、真实材料、真实组织账号、生产城市能力、真实主运营关系迁移、门禁默认开启和生产启用
- 功能门禁：`synthetic_admin_operator_management` 默认关闭，并依赖 `synthetic_admin_multi_organization`

实施批准仅覆盖：

- 合成运营主体档案、生命周期和追加式状态事件；
- 合成入驻案件与独立复核；
- 合成城市与能力授权；
- 运营主体、车主和车辆 360° 只读聚合；
- 合成主运营关系迁移案件及其阻断、双方确认、独立复核和未来生效；
- 对阶段一组织上下文、统一授权和追加式审计的复用。

实施批准不自动授权真实数据、真实迁移、行程／客服／安全／资金写操作或生产启用。

## 背景与待解决问题

阶段一已经建立统一内部身份、组织上下文、服务端授权和追加式审计，但运营主体名录仍是只读摘要。阶段二需要支持运营主体生命周期、城市能力、入驻案件、车主与车辆 360°、主运营关系和迁移设计。

这些能力涉及跨租户边界、资格与车辆审核、历史关系、资金归属和破坏性变更。如果编码阶段临时选择“直接编辑主体状态”“覆盖主运营主体字段”或“页面聚合后前端过滤”，将破坏已有多组织授权、车辆审核与资金编排事实源。

## 决策目标与非目标

目标：

- 冻结运营主体生命周期和唯一状态转换入口。
- 将主体档案、入驻案件、城市能力授权和组织账号明确分离。
- 保证 360° 页面只聚合已有权威事实，不复制资格、车辆审核、行程或资金状态。
- 沿用 `pollycar_finance.driver_operator_memberships` 作为主运营关系权威事实。
- 用追加式、双人复核迁移案件替代直接修改主运营关系。
- 保证平台与运营主体人员在同一页面获得不同动作和字段披露。

非目标：

- 不批准真实运营主体或真实材料接入。
- 不在阶段二建立真实组织账号、银行账户或资金操作。
- 不修改历史行程的运营主体快照。
- 不建立新的车主资格、车辆审核、行程、账本或余额事实源。
- 不在本决策中实现代码、数据库迁移或 HTTP API。

## 可选方案及权衡

### 方案 A：运营主体档案直接包含所有状态和能力

优点：

- 表面结构简单。

缺点：

- 法定档案、入驻审查、城市授权和账号启用互相耦合。
- 无法表达同一主体在不同城市具有不同能力和有效期。
- 容易让一次字段修改绕过案件、复核和审计。

结论：否决。

### 方案 B：主运营关系使用车主表上的可编辑运营主体字段

优点：

- 查询简单。

缺点：

- 覆盖历史归属，无法可靠解释既有行程和资金分配。
- 与阶段八已经完成的唯一主运营关系事实冲突。
- 并发迁移可能产生两个有效主体。

结论：否决。

### 方案 C：档案、案件、授权与关系分离，全部使用追加式状态和受控命令

优点：

- 保留历史并支持职责分离。
- 城市和能力可独立授予、暂停、到期和撤销。
- 复用既有车辆审核、资格和资金编排事实。
- 可以在数据库层证明唯一有效主运营关系。

缺点：

- 页面和命令契约更复杂。
- 迁移必须协调资格、车辆、未结任务和资金阻断。

结论：采用。

## 最终决策

### 主体档案与生命周期

运营主体生命周期固定为：

```text
candidate
→ onboarding_review
→ pending_activation
→ active
→ restricted
→ suspended
→ exit_pending
→ exited
```

- `candidate` 只能由平台获批角色创建合成档案。
- `onboarding_review` 只表示入驻案件受理，不表示具备运营能力。
- `pending_activation` 表示入驻决定通过，但城市能力、组织账号和生产门禁仍需分别满足。
- `active` 只表示至少一个合成城市能力有效。
- `restricted` 禁止新增车主、车辆或主运营关系，但保留已有关系和必要服务任务。
- `suspended` 禁止产生新的运营活动；历史查询、案件和退出处理继续可见。
- `exit_pending` 必须先关闭未完成入驻、迁移、资格、车辆、行程、安全和资金阻断。
- `exited` 为终态；重新合作必须创建新主体档案和新入驻案件，不得恢复原档案。

所有生命周期变化必须追加状态事件，禁止直接覆盖历史状态。限制、暂停、恢复和退出均要求结构化理由、证据引用、经办人与复核人分离。

### 入驻案件

- 一个候选主体同一时间最多存在一个未关闭入驻案件。
- 案件清单固定覆盖主体身份摘要、联系人遮蔽摘要、申请城市与能力、运营责任、数据处理、安全协作、车辆与车主治理准备度。
- 材料原文默认不可见；阶段二高保真只展示合成摘要和检查结果。
- 案件决定固定为 `approve`、`request_changes` 或 `reject`。
- 经办人不得复核自己的决定。
- 入驻通过只将主体推进到 `pending_activation`，不自动开通账号、真实数据、资金或生产能力。

### 城市与能力

- 授权唯一键为 `operator_entity_id + city_code + capability_type + effective_from`。
- 能力类型固定为 `driver_operations`、`vehicle_operations`、`trip_coordination`、`support_coordination` 和 `safety_collaboration`。
- 每项授权必须具有开始时间，可选结束时间、规则版本、批准案件和批准人。
- 能力状态固定为 `pending`、`active`、`restricted`、`suspended`、`expired`、`revoked`。
- 禁止通配城市、全国范围或“全部能力”授权。
- 运营主体人员不能自行授予、扩大或恢复城市能力。

### 360° 页面

- 运营主体 360° 聚合主体档案、生命周期、城市能力、入驻案件、运力摘要、风险和关闭态资金摘要。
- 车主 360° 聚合产品账户、资格、配额、主运营关系、车辆、行程与案件引用。
- 车辆 360° 聚合车辆档案、审核状态、有效车主关系、证照到期、行程和案件引用。
- 360° 页面不拥有任何聚合事实，不允许通过通用“编辑”表单修改源领域状态。
- 严格敏感字段继续要求目的、工单、临时授权和披露审计。

### 主运营关系与迁移

- 权威事实继续使用 `pollycar_finance.driver_operator_memberships`。
- 唯一范围固定为 `driver_account_id + city_code + vehicle_id`。
- 同一范围只能存在一个 `active` 关系。
- 历史关系只能结束，不能修改运营主体、开始时间或已有行程快照。
- 迁移案件状态固定为：

```text
draft
→ checks_pending
→ awaiting_source_acknowledgement
→ awaiting_target_acknowledgement
→ awaiting_independent_review
→ scheduled
→ effective
```

终止状态为 `cancelled` 或 `rejected`。

- 来源主体确认只证明已知悉和完成交接，不拥有否决平台合规迁移的绝对权力。
- 目标主体必须确认接收责任、城市能力和运力准备度。
- 独立复核人与经办人、来源确认人和目标确认人均不得为同一内部用户。
- 生效时间必须晚于批准时间，并使用数据库事务原子结束旧关系、建立新关系和追加审计事件。
- 生效前发现阻断可取消；生效后不得回滚历史，只能创建新的反向迁移案件。
- 既有行程、资金分配、清算和付款继续引用创建时的运营主体快照。

### 迁移阻断

以下任一条件存在时不得安排或执行迁移：

- 目标主体缺少对应城市的有效 `driver_operations` 与 `vehicle_operations` 能力；
- 车主资格或车辆审核不是可服务状态；
- 同范围已有未关闭迁移案件；
- 存在进行中行程、未完成安全移交或严格主体锁定案件；
- 存在未解决非零对账差异、未知付款结果或阻止主体退出的资金案件；
- 资源版本已经变化；
- 经办与复核不满足职责分离。

### 授权与审计

- 平台运营负责人可管理主体生命周期、入驻案件和迁移案件，但高风险决定必须独立复核。
- 运营主体运营人员只能查看本主体档案、能力、关联车主车辆和需要其确认的迁移任务。
- 审核员继续通过既有车辆审核权限处理审核，不因进入 360° 页面获得主体生命周期权限。
- 财务、安全、合规只提供阻断状态和案件引用，不向阶段二角色开放领域写操作。
- 每次查看、字段披露、案件领取、决定、确认、安排和生效均追加审计。

## 后果

- 阶段二获得明确批准后的实现必须建立明确命令入口和资源版本校验，不能以通用 CRUD 替代案件动作。
- 阶段二可复用阶段一 Shell、组织上下文和审计框架。
- 真实运营主体、真实材料和生产启用仍需单独高风险批准。
- 阶段二完成不会自动批准阶段三行程、客服或安全操作。
