# 决策 0028：本地生产就绪基础设施验收

## 决策状态

已批准。本决策仅批准本地隔离环境的基础设施部署与恢复验收，不批准生产启用、真实数据接入或任何业务能力开放。

## 背景与待解决问题

独立 `ProductionConfig` 已建立正式 PostgreSQL、HTTPS、密钥系统引用和监控边界，但仍需证明这些边界能够在可重复的本地基础设施环境中共同运行，并验证部署、迁移、备份、恢复和健康检查链路。

## 决策目标与非目标

目标是建立一套与内部沙箱隔离的本地生产就绪栈，验证 PostgreSQL TLS、反向代理 TLS、生成式本地密钥材料、OTLP Collector、生产迁移入口、备份恢复和健康检查。

非目标包括真实云资源、真实供应商凭据、真实用户数据、长期生产运维、互联网暴露、业务路由、身份、地图、定位、支付、结算或提现能力。

## 可选方案及权衡

1. 复用内部沙箱数据库和服务：成本较低，但无法证明配置、数据和网络边界独立，否决。
2. 直接部署真实云环境：最接近生产，但外部批准、预算、供应商、隐私和生产启用条件尚未关闭，否决。
3. 使用本地隔离容器栈模拟正式基础设施边界：可重复验证关键机制，同时保持真实能力关闭，采用。

## 最终决策

- 使用独立 Compose 项目 `pollycar-production-readiness`，包含 PostgreSQL、生产就绪 Server、Caddy 和 OpenTelemetry Collector。
- PostgreSQL 使用独立命名卷和 TLS 证书；数据库口令由初始化脚本随机生成并通过只读文件挂载，不写入编排文件或镜像。
- Server 镜像从主机锁定依赖生成的离线部署产物构建，容器运行时不访问 npm registry。
- Caddy 仅在 `127.0.0.1:8444` 提供 HTTPS，只有 `/health/live` 与 `/health/ready` 可反向代理，其他路径统一返回 `503`。
- 健康检查必须验证本地 CA 与证书 SAN，不允许通过跳过证书验证完成验收。
- 验收脚本必须执行镜像构建、栈启动、生产迁移、HTTPS 存活与就绪检查、`pg_dump`、恢复到独立数据库、迁移历史验证和默认清理。
- 本地生成的证书、私钥、口令、数据库状态、部署产物和备份必须被版本控制忽略。

## 产品和业务影响

本决策不改变用户产品行为，不开放任何业务路由。它只证明生产基础设施边界具备进入下一阶段外部环境设计与批准准备的工程基础。

## 安全、隐私、合规与公平性影响

- 本地证书和口令仅用于隔离验收，不得复制到共享环境或真实生产环境。
- 本地 CA 无吊销服务；Windows 验收仅关闭吊销查询，仍验证 CA、有效期和 SAN。真实生产证书必须使用具备正式生命周期和吊销能力的托管证书服务。
- 备份只包含本地空库结构和迁移历史，不得写入真实用户数据。
- OpenTelemetry Collector 当前只使用本地 debug exporter，不向外部监控平台发送遥测。
- 所有业务门禁继续关闭，因此本决策不引入新的公平性决策或用户影响。

## 验收标准

- `podman compose config` 可解析独立编排。
- PostgreSQL 通过 TLS 启动并完成 9 项现有迁移。
- Caddy 证书链与 `api.pollycar.example` SAN 验证通过。
- 存活检查返回 `live`，PostgreSQL 就绪检查返回 `ready`。
- 备份可恢复到 `pollycar_restore`，恢复后的迁移历史不为空。
- 验收结束后容器、网络和数据库卷默认清理。
- 所有生产业务能力、真实数据和生产启用状态保持关闭。

## 生效与退出条件

本决策自本地端到端验收通过后生效。进入共享预生产或真实生产基础设施前，必须另行批准云资源、网络、托管 PostgreSQL、证书、密钥管理、监控存储、备份保留、灾难恢复、访问控制、成本和数据处理边界。

## 未决事项、负责人和截止时间

- 工程与运维负责人：设计共享预生产环境及基础设施即代码方案，进入下一阶段前完成。
- 安全负责人：批准托管密钥、证书、网络访问和备份加密方案，真实环境创建前完成。
- 产品与生产决策负责人：在任何真实数据或业务能力启用前完成独立生产启用评审。
