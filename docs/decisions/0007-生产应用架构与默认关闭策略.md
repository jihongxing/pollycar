# 决策 0007：生产应用架构与默认关闭策略

## 决策状态

`已批准`

- 批准日期：`2026-07-11`
- 批准人：`项目决策人`
- 批准范围：允许生产级代码结构、接口、迁移、任务、审计和可观测性实现。
- 限制：所有真实能力默认关闭，仅合成数据和内部沙箱可用。

## 背景与待解决问题

无资金领域内核已经具备实现基础，但进入生产级代码开发还需要明确 App、后端、数据库、API、身份、异步任务、审计和可观测性边界。需要允许按生产质量实现，同时避免任何代码完成被误解为生产启用批准。

## 最终决策

采用 pnpm workspace：

```text
apps/
  app/
  server/
packages/
  domain/
  contracts/
  test-support/
```

### 用户端应用

- `apps/app` 是用户端应用。
- 首期只允许实现合成数据和内部沙箱模式。
- App 不直接访问数据库、任务队列或第三方服务。
- App 只通过 `packages/contracts` 定义的公开 API 与服务端通信。
- 具体 UI 框架和发布渠道可在 App 实施包中单独决定。

### 后端服务

- `apps/server` 是模块化单体后端。
- HTTP 框架：Fastify。
- 输入输出验证：JSON Schema；OpenAPI 是公开接口契约。
- 应用服务调用 `packages/domain`，不得在控制器或数据库层复制业务规则。
- 外部服务通过端口和适配器隔离。

### 数据库

- 生产关系数据库目标：PostgreSQL。
- 数据访问与迁移工具：Drizzle ORM 与版本化 SQL 迁移。
- 内部沙箱首期可以使用隔离的本地 PostgreSQL；若环境未提供数据库，只允许使用内存适配器做合成测试。
- 迁移默认向后兼容，破坏性变更需要单独批准和恢复演练。
- 真实用户数据写入功能保持关闭。

### 身份与授权

- 服务端定义身份端口，不在领域包依赖身份供应商。
- 内部沙箱只允许固定合成主体和受控内部身份。
- 真实用户注册、邀请、实名和会话签发默认关闭。
- 授权依据 `spec/security/roles.yaml` 和 `authorization-rules.yaml`，默认拒绝。

### 任务与事件

- 首期使用数据库事务内写入 outbox，后台 worker 处理异步任务。
- 不在首期引入独立消息中间件。
- 任务必须具备幂等键、最大尝试次数、退避、死信状态和人工重放审计。
- 删除、冻结复核、保险到期、资格到期、零金额支付查询和孤立支付处置均通过受控任务执行。

### 审计

- 状态转换、权限决定、敏感访问、配置变化和任务人工重放必须追加审计。
- 审计记录不可通过普通业务 API 修改或删除。
- 沙箱不得记录真实敏感原文。

### 可观测性

- 结构化 JSON 日志。
- 请求关联 ID、主体 ID、聚合 ID和任务 ID。
- OpenTelemetry 兼容的追踪与指标端口。
- 健康检查分为进程存活和依赖就绪。
- 首期允许使用本地控制台和内存指标适配器，不连接真实监控平台。

### 默认关闭策略

所有应用、配置和机器契约必须默认：

```yaml
production_enabled: false
real_payment: false
paid_flex_trial: false
real_user_invitation: false
shanghai_pilot: false
real_data_ingestion: false
```

- 缺少配置时一律按关闭处理。
- 不允许使用开发默认值自动开启真实能力。
- 生产启用必须通过独立决策、配置变更、发布检查和双人批准。
- 单个功能开关不能绕过依赖开关；例如上海试点关闭时，真实邀请和真实支付即使误设为真也不得生效。

## 产品和业务影响

- 团队可以开始生产质量的代码、数据库迁移、API 和运维基础设施实现。
- 代码完成不代表可以接入真实用户、资金或上海试点。
- App 和后端可以并行开发，共享公开契约而不共享内部实体。

## 安全、隐私、合规与公平性影响

- 默认关闭和依赖门禁降低误启用风险。
- 合成数据模式必须可从配置和日志中明确识别。
- 真实身份、支付、位置、聊天和车辆原件仍禁止进入沙箱。
- 所有角色和数据访问默认拒绝，开放必须有明确规则。

## 验收标准

- workspace 中存在 App、Server、Domain、Contracts 和 Test Support 边界。
- 后端控制器不包含领域业务规则。
- 数据库、身份、任务、审计和可观测性均通过端口可替换。
- 所有真实能力默认关闭且存在依赖门禁测试。
- 完整预检、类型检查、测试和构建通过。

## 生效与退出条件

立即允许生产级代码实现。

生产启用不随本决策生效，必须另行批准。

退出条件：

- 架构无法满足事务、审计、容量或安全要求。
- App 与 Server 边界导致规则重复或敏感数据泄露。
- 默认关闭策略可被单一配置错误绕过。
