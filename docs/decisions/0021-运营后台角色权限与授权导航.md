# 决策 0021：运营后台角色权限与授权导航

## 决策状态

- 状态：`实施前设计已冻结；已批准内部沙箱合成代码实现`
- 实施批准日期：`2026-07-15`
- 冻结日期：`2026-07-15`
- 适用环境：内部沙箱与合成数据
- 默认门禁：`synthetic_admin_role_access_matrix=false`
- 生产启用：禁止

## 背景与待解决问题

阶段一已经证明组织成员关系、功能角色、作用域和服务端统一授权可行，但现有后台菜单仍由前端身份样例和模块门禁拼装，角色名称也混合了平台职能、运营公司职能和历史技术角色。若继续在页面开发时临时决定菜单、字段、导出或组织范围，将形成“菜单隐藏但 URL 可访问”“平台身份自动获得全权限”“运营公司跨主体筛选”和“页面可见字段与导出字段不一致”等风险。

## 决策目标与非目标

目标：

- 冻结平台与运营公司功能角色目录；
- 冻结十个一级菜单及固定路由域；
- 让菜单、路由、操作、字段、批量操作、导出和 API 使用同一授权判定；
- 明确平台身份不是全权限，运营公司身份只能访问本公司；
- 保持阶段一职责分离、临时授权和追加式审计不被放宽。

非目标：

- 不改变已经冻结的导航接口、路由守卫或菜单组件契约；
- 不改变业务领域状态机；
- 不批准真实内部账号、真实组织数据或生产启用；
- 不在本轮制作高保真页面。

## 方案权衡

### 平台超级管理员

否决。无差别管理员会绕过职责分离、字段等级和组织作用域，也无法证明高风险操作由独立角色完成。

### 每页自行维护角色判断

否决。页面、按钮、API 和导出会快速出现不一致，新增角色时无法完整审计影响范围。

### 仅隐藏菜单

否决。菜单隐藏只改善体验，不能构成路由、字段和 API 授权边界。

### 服务端角色权限矩阵与授权导航

采用。服务端以当前工作身份为输入，计算菜单、路由、操作、字段、导出和组织范围；客户端只消费结果，不自行扩权。

## 最终决策

授权公式固定为：

```text
允许
= 有效账号
+ 有效工作身份
+ 组织类型允许该角色
+ 功能角色允许该能力
+ 服务端组织范围包含目标资源
+ 字段档位允许
+ 导出档位允许
+ 资源状态允许
+ 职责分离满足
+ MFA 新鲜度满足
+ 功能门禁开启
```

任何维度缺失均拒绝。角色只表达职责，不隐含组织范围；平台工作身份也必须有明确城市和运营主体范围。

## 角色目录

平台角色固定为：

1. `platform_access_administrator`：平台账号、成员关系和角色绑定管理；
2. `operations_officer`：平台日常行程与运营任务；
3. `operations_lead`：跨主体运营协调与独立复核；
4. `operator_management_officer`：运营公司入驻、能力和迁移经办；
5. `reviewer`：车主与车辆标准审核；
6. `senior_reviewer`：升级审核与独立复核；
7. `customer_support`：平台客服案件经办；
8. `support_lead`：客服升级、补偿建议和质量复核；
9. `safety_officer`：安全调查与证据申请；
10. `safety_lead`：重大安全决定与独立恢复复核；
11. `finance_officer`：平台财务经办；
12. `finance_lead`：平台财务独立复核与精确聚合金额；
13. `privacy_compliance`：隐私、披露和合规审批；
14. `data_analyst`：去标识经营分析；
15. `auditor`：全程只读控制审计；
16. `technical_operations`：技术恢复和运行诊断；
17. `executive_sponsor`：平台高层聚合观察与追加式意见。

运营公司角色固定为：

1. `operator_account_administrator`：本公司成员邀请、暂停和角色申请；
2. `operator_operations_lead`：本公司运力、行程和服务质量；
3. `operator_fleet_officer`：本公司车主、车辆和主运营关系协作；
4. `operator_customer_support`：本公司关联行程和客服案件；
5. `operator_safety_liaison`：本公司安全协作任务；
6. `operator_finance_officer`：本公司清算和付款经办；
7. `operator_finance_lead`：本公司财务独立复核；
8. `operator_auditor`：本公司只读审计；
9. `operator_executive`：本公司高层聚合观察与追加式意见。

`emergency_responder` 是按事件临时授予的特殊用途角色，不进入常规菜单；系统角色和 App 用户角色不进入运营后台角色目录。

## 禁止角色组合

- `auditor`、`operator_auditor` 不得与任何业务写角色在同一工作身份组合；
- `technical_operations` 不得与审核、客服、安全或财务业务写角色组合；
- `executive_sponsor`、`operator_executive` 不得与日常经办角色在同一会话目的组合；
- `platform_access_administrator` 不得给自己新增角色、扩大作用域或批准自己的高权限变更；
- 财务经办与财务复核可以属于同一自然人的不同成员关系，但不得在同一工作身份或同一业务批次兼任；
- 安全调查人与恢复复核人必须不同；
- 邀请、角色绑定和临时授权的申请人与批准人必须不同。

## 一级菜单与路由域

固定十个一级菜单：

1. 工作台：`/admin/workbench/*`；
2. 组织与账号：`/admin/organization-accounts/*`；
3. 运营公司：`/admin/operators/*`；
4. 车主与车辆：`/admin/fleet/*`；
5. 行程运营：`/admin/trips/*`；
6. 客服与安全：`/admin/cases/*`；
7. 资金运营：`/admin/finance/*`；
8. 数据与报表：`/admin/reports/*`；
9. 高层驾驶舱：`/admin/executive/*`；
10. 审计与系统：`/admin/governance/*`。

菜单清单由服务端根据工作身份返回。无权一级菜单和子菜单必须完全隐藏；直接访问路由必须再次授权。资源深链接越权统一返回不泄漏资源存在性的拒绝结果。

## 组织范围

- 平台角色使用显式 `city_scopes` 与 `operator_scopes`，不得因平台身份自动获得全量范围；
- 运营公司角色固定为成员关系中的单一 `operator_id`，城市范围不得超过该公司的有效城市能力；
- 请求参数、筛选器、搜索词、导出条件和批量选择只能缩小范围，不能扩大范围；
- 列表、详情、搜索、计数、聚合、操作和导出使用同一服务端范围；
- 平台跨主体操作必须由具体动作明确允许，仅有跨主体读取范围不等于拥有写权限；
- 不允许使用通配运营公司范围；全局审计也必须使用批准的审计范围。

## 字段权限

字段档位固定为：

- `internal_l2`：内部与敏感摘要；
- `operational_l3_masked`：运营所需高敏感字段，仅脱敏展示；
- `assigned_review_l4`：已分配审核案件的严格受限材料，按任务披露；
- `safety_evidence_l4`：安全案件严格证据，临时授权和双人审批；
- `finance_l3_exact`：授权组织内精确资金金额，不含完整付款凭据；
- `privacy_case_l4`：隐私或法律案件的最小必要严格字段；
- `aggregate_l2`：去标识聚合；
- `audit_reference_l3`：审计引用和摘要，不含业务秘密原文；
- `technical_metadata_l2`：运行状态、请求标识和恢复元数据，不含业务字段。

前端隐藏字段不构成授权。服务端响应必须按字段档位裁剪；排序、筛选、搜索、聚合和导出也不能使用无权字段形成侧信道。

## 导出权限

导出档位固定为：

- `none`：禁止；
- `aggregate_deidentified`：去标识 L2 聚合；
- `operational_scoped`：授权范围内的业务摘要，需用途和短期文件；
- `review_material_controlled`：已分配案件材料，严格审批；
- `safety_evidence_controlled`：证据字段双人批准和短期加密存储；
- `finance_controlled`：已对账、已关账范围，申请人与批准人分离；
- `executive_controlled`：单一职责域、双人批准、聚合脱敏；
- `audit_reference_controlled`：审计引用和控制证据，不导出业务秘密原文。

导出范围必须等于或小于页面范围，字段必须等于或少于页面字段。导出不是读取权限的替代入口。

## 批量操作

批量操作仅允许任务分配、标签、受控通知和安全的队列编排。批量审核通过、批量拒绝、批量安全恢复、批量付款、批量退款、批量冲正、批量差异核销、批量关账和批量角色授予全部禁止。

## 授权导航

服务端导航清单至少返回：

```text
navigation_version
work_identity_id
organization_context
role_ids
items
route_permissions
operation_permissions
field_profiles
export_profiles
scope_digest
expires_at
```

导航清单不是长期凭证。每个路由、操作和数据请求必须重新授权；角色、作用域、成员关系或门禁变化时撤销相关会话并重新签发导航清单。

## 审计

必须审计：

- 角色绑定、撤销和拒绝；
- 菜单清单签发和版本变化；
- 路由、操作、字段和导出允许与拒绝；
- 跨主体范围切换和拒绝；
- 批量操作申请和拒绝；
- 临时字段披露和导出批准；
- 角色组合冲突；
- 作用域摘要变化导致的会话撤销。

审计不得记录严格受限字段、导出文件内容或认证秘密原文。

## 验收标准

- 角色目录、菜单、路由、操作包、字段档位、导出档位和组织范围具有唯一机器契约；
- 平台身份不自动获得全部菜单或全部数据；
- 运营公司角色不能看见或推断其他运营公司；
- 菜单隐藏、路由拒绝、API 拒绝、字段裁剪和导出限制一致；
- 无超级管理员或通用管理员角色；
- 三十二项以上正向与越权场景通过；
- 默认门禁关闭，未获批准前不存在新增导航或权限代码。

## 生效与退出条件

本决策在产品契约、机器规范、Schema、场景和专项治理检查全部通过后成为实施前冻结基线。进入代码实现需再次明确批准，并保持 `synthetic_admin_role_access_matrix=false` 默认关闭。

真实内部账号、真实组织数据和生产启用必须另行批准。
