# 0010 全用户实名与法定性别披露

## 背景与待解决问题

PollyCar 只向已验证为成年人的账户开放叫车、车主申请、接单、聊天、举报和其他业务功能。产品采用身份证件核验与本人活体人脸比对完成成年资格验证，并从经过验证的证件结果中取得身份主体、出生日期和法定性别。

在领域、权限和审计层面，该流程构成全用户实名准入；在面向用户的普通产品文案中，应以“完成成年资格验证”“确认已年满十八周岁”等目的性表达为主，不使用“强制实名”“不实名不得使用”等压迫性表述。

该要求涉及身份认证、身份证件、法定性别、未成年人风险、数据最小化、歧视、公平性和安全责任，因此属于高风险且难逆转的产品决策。

## 决策状态

评审中。

在法律、隐私、安全和身份服务供应商评审完成前，只允许生产级代码实现和合成数据验收，不允许接收真实身份证件。

## 可选方案及权衡

### 方案一：实名可选

- 隐私侵入较低。
- 不满足产品要求。
- 无法建立统一身份责任链。

### 方案二：实名强制，性别自愿展示

- 能建立身份责任链。
- 不满足法定性别强制披露要求。

### 方案三：成年资格验证前置，法定性别按交易阶段强制弱展示

- 满足产品要求。
- 通过身份证件核验与本人活体人脸比对确认用户不是未成年人。
- 车主可在接单前结合乘车人头像和法定性别图标自主决定是否接单。
- 乘车人可在车主接单后结合车主头像和法定性别图标决定是否取消行程。
- 增加身份证件、生物识别信息、第三方处理、歧视和骚扰风险。
- 必须限制披露对象和阶段，并禁止用于平台匹配、排序、价格、资格和自动风控。

## 最终决策

采用方案三。

1. 所有账户必须通过成年资格验证后才能使用 PollyCar 的业务功能；系统内部必须将该结果作为实名准入事实执行，不得仅依赖用户勾选年龄声明。
2. 未验证、验证中、需补充材料、未通过、过期、暂停或撤销状态只能进入注册、成年资格验证、申诉、隐私说明和退出登录页面。
3. 成年资格验证必须包含身份证件正反面核验、证件有效性校验、出生日期计算、本人活体检测和人脸一致性比对。
4. 姓名、证件号码、出生日期和法定性别必须来自经过验证的身份证件结果，不允许用户自行修改；业务准入只保存“已满十八周岁”的必要结论，不应向普通业务模块扩散完整出生日期。
5. 身份证核验、人脸活体检测和人脸一致性比对可以由经批准的第三方身份服务完成，但必须经过供应商安全、隐私、数据流、保留期限、删除机制和跨境风险评审。
6. 面向用户的普通入口、按钮和状态文案应使用“成年资格验证”“确认已年满十八周岁”“继续完成验证”等表述，不得使用“强制实名”“不实名不得使用”等强调强制性的产品文案。
7. 前端文案可以采用目的性表达，但在采集身份证件或人脸信息前，必须清晰告知处理目的、数据类型、处理方式、第三方接收方或类型、保留期限、退出影响和申诉渠道，并取得适用规则要求的单独同意或授权；不得以委婉文案替代必要法律告知。
8. 乘车人发单后，有权查看该订单且满足接单资格的车主，可以在接单前查看乘车人的头像和法定性别图标，并自主决定是否接单；平台不得强制派单。
9. 车主接单后，当前行程乘车人可以查看车主的头像和法定性别图标，并自主决定是否按照已批准的取消规则取消行程。
10. 法定性别统一使用性别图标进行弱展示，不以文字标签、醒目色块、排序标签或筛选条件突出显示。
11. 性别展示属于业务强制要求，不提供同意展示、拒绝展示、隐藏、修改或按行程关闭的入口。
12. App 不得在叫车、待接订单或行程页面展示“要求展示性别”“强制公开性别”“性别来自身份证件”或其他强调披露义务的提示；相关数据处理规则必须在成年资格验证及隐私流程中独立、完整地告知。
13. 除第八条规定的接单前展示和第九条规定的接单后展示外，法定性别不得在公开搜索、营销页面、普通账户目录、无订单关系页面或非必要后台摘要中披露。
14. 法定性别不得用于平台自动匹配、排序、资格、配额、价格、收入机会、推荐、筛选或自动风险决定。
15. 身份证原图、人脸图像、活体检测材料和生物特征模板不得进入普通业务载荷、聊天、通知、通用日志、分析或订单快照。
16. 真实身份证件和真实人脸数据接入在外部批准前保持关闭；内部沙箱只允许带明显水印的合成证件和不可对应真实个人的合成人脸材料。

## 产品和业务影响

- 注册流程增加成年资格验证步骤，普通产品文案不强调“强制实名”。
- 叫车首页、车主工作模式和消息入口必须由全局成年资格门禁保护。
- 车主审核不能替代账户成年资格验证。
- 身份证件核验和本人活体人脸比对共同构成通过条件，任何单项成功均不能开放业务能力。
- 第三方验证返回未知结果、超时或处理中时，系统必须保持业务能力关闭，不得按成功处理。
- 待接订单卡必须向有权接单的车主弱展示乘车人头像和法定性别图标，供车主自主判断是否接单。
- 车主接单后，行程详情必须向乘车人弱展示车主头像和法定性别图标，供乘车人判断是否取消。
- 前端不提供性别披露开关，也不在业务页面强调强制披露要求。
- 未实名账户不能创建行程、申请车主、接单、聊天、举报或查看业务消息。

## 安全、隐私、合规与公平性影响

- 身份证原图、证件号码、人脸图像、活体检测材料和可用于识别个人的生物特征模板为最高敏感等级数据。
- 原则上应优先由经批准的第三方身份服务直接处理人脸材料；PollyCar 只接收必要的验证结论、供应商请求编号和可审计结果，除非另有批准不得长期保存原始人脸材料。
- 法定性别属于敏感个人信息，只允许向有权查看待接订单的合格车主或当前已接单行程的乘车人按阶段、按目的披露。
- 必须提供访问审计、数据保留期限、撤销、申诉、更正和人工复核。
- 必须监测基于性别的取消、拒单、骚扰和举报差异。
- 不得把性别写入车主拒单原因、乘车人取消原因或运营人员处置标签，也不得据此对单个用户作出自动不利决定。
- 如公平性指标超过批准阈值，应停止性别披露或停止相关试点，而不是扩大披露范围。
- 本决策不能替代适用法律、隐私影响评估或专业法律意见。

## 验收标准

1. 未通过成年资格验证的账户访问任何业务 API 均返回成年资格前置错误。
2. App 未通过验证时只能看到注册、成年资格验证、隐私说明、申诉和退出入口。
3. 普通产品页面不出现“强制实名”“不实名不得使用”等强调强制性的文案。
4. 身份证件和人脸材料使用专用敏感数据接口或经批准的第三方直传通道，不进入通用文件上传。
5. 身份证件核验、出生日期成年判定、活体检测和人脸一致性比对全部成功后，服务端才能写入“成年资格已验证”状态。
6. 身份结果中的姓名、证件号码和法定性别由服务端写入。
7. 身份证件或人脸验证失败、超时、未知或未完成时，业务能力保持关闭并提供重试或申诉路径。
8. 采集前告知和必要授权必须可被自动化测试和审计验证，第三方身份服务不得在未告知情况下接收数据。
9. 有权查看待接订单且满足接单资格的车主，可以在接单前看到乘车人头像和法定性别图标。
10. 车主接单后，当前行程乘车人可以看到车主头像和法定性别图标。
11. 性别仅以统一图标弱展示，页面不存在性别筛选、排序、隐藏或修改入口。
12. 叫车、待接订单和行程业务页面不得出现“要求展示性别”“强制公开性别”“性别来自身份证件”等强调性提示。
13. 无权查看订单的用户、无订单关系用户及公开页面不得获得法定性别字段。
14. 匹配、排序、价格、资格、配额、推荐和风控逻辑不得读取法定性别字段。
15. 车主是否接单必须由车主主动确认，平台不得因性别或其他个人资料自动代替车主作出接单决定。
16. 身份证件、人脸验证请求、访问和结果变更必须严格审计。
17. 真实身份和人脸数据门禁关闭时，真实数据请求必须被拒绝。

## 生效与退出条件

### 生效条件

- 身份验证供应商、人脸活体与比对方案、安全方案、隐私影响评估和数据保留方案获得批准。
- 成年资格门禁、分阶段披露、审计、申诉和公平性监测通过验收。
- 真实数据接入获得单独批准。

### 退出条件

- 法律或隐私评审否决强制披露。
- 出现无法接受的歧视、骚扰或安全风险。
- 身份服务无法满足数据最小化、删除、审计或跨境要求。
