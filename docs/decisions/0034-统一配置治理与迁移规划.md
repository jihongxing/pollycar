# 0034 统一配置治理与迁移规划

## 状态

已批准实施。

## 日期

2026-07-30。

## 背景

Admin、Server、App、Android、iOS、EAS、GitHub Actions、本地脚本和基础设施目前分别读取环境变量、构建参数和代码默认值。同一概念存在多套命名和多处默认值，已经造成过后台与 Server 合成功能门禁不一致、真实本地环境登录失败等问题。

本决策基于两轮全量审计。审计覆盖运行时代码、构建脚本、原生工程、测试脚本、CI、基础设施、生产准备规范和供应商接入决策。共发现约 127 个配置形态标识；剔除错误常量、测试样例、历史字符串和重复引用后，归并为 26 个配置族；批次四新增版本化公开快照入口后，共形成 55 个统一配置键。

## 目标

1. 建立 Admin、Server、App 共用的配置命名、类型、敏感等级、Profile 和校验契约。
2. 保持 Server 私密配置、浏览器／App 公开配置、密钥引用、构建凭据和安全策略相互隔离。
3. 清除业务代码中的环境判断、本地端口回退和重复功能门禁。
4. 让本地、测试、Demo、共享预生产、生产准备和生产使用同一配置生成与校验流程。
5. 所有真实能力继续失败关闭；配置迁移不得替代批准、证据或生产启用决策。

## 非目标

- 本批次不改变现有 Admin、Server、App 启动行为。
- 本批次不启用真实短信、身份、生物识别、地图、定位、支付或真实数据。
- 不把公开 API 路径、错误码、领域不变量或功能门禁依赖关系变成环境变量。
- 不允许通过配置放宽一次性授权、身份准入、审计、数据最小化等业务安全规则。

## 敏感等级

| 等级 | 含义 | 允许进入 Admin/App 构建产物 |
| --- | --- | --- |
| `L0` | 公开配置，例如公开 API 地址和浏览器受限 Key | 是 |
| `L1` | 内部运行参数，例如端口、日志等级、连接池和安全策略 | 否 |
| `L2` | 完整性敏感配置，例如批准引用、密钥引用、镜像 digest | 否 |
| `L3` | 机密配置，例如数据库凭据、签名密码和原生供应商 Key | 否 |

## 不应配置化的内容

1. 公开 API 路径、错误码和状态机名称继续由 `spec/` 管理。
2. 核心领域规则和安全不变量继续由代码与契约强制执行。
3. 功能门禁依赖关系继续由 `feature-gates` 契约计算。
4. 测试 Fixture 的 `example.invalid` 地址不属于部署配置。
5. 路由解析使用的内部占位 URL 不属于外部端点。
6. 供应商 SDK 版本应进入受版本控制的依赖清单，而不是任意环境变量。

## 迁移批次

### 批次一：统一配置契约

- 建立 55 项统一配置目录、六类 Profile、敏感等级、暴露范围和旧名映射。
- 建立公开敏感配置、重复键、重复旧名、未知变量和原始密钥检查。
- 只建立契约，不接管现有运行入口。

### 批次二：本地沙箱网络与能力

- 统一 `4173/4321/8181`、API 地址、CORS 和 Vite Proxy。
- 从同一能力配置生成 Server 门禁与 Admin 公开快照。
- 本地启动脚本只选择 Profile。
- 已于 2026-07-30 完成：新增 `@pollycar/configuration` 作为 `local-sandbox` 单一事实源，三端构建、启动脚本和 Playwright 均从该 Profile 派生网络与合成能力；App/Admin 已删除浏览器端口猜测和旧 API 回退。

### 批次三：Server 配置入口

- 合并生产、沙箱和生产认证准备配置。
- 除配置模块和测试外禁止直接读取 `process.env`。
- 统一 PostgreSQL、代理、监控、SecretProvider、Provider 端点和 HTTP 限制。
- 已于 2026-07-30 完成：`@pollycar/configuration` 统一解析沙箱、生产准备、生产认证准备、迁移和 PostgreSQL 集成测试配置；Server 全部源码不再直接读取 `process.env`，本地 PostgreSQL、远程 TLS PostgreSQL、HTTPS 代理、托管密钥引用、OTLP 监控、日志等级、受控供应商 SecretProvider 与 JSON Body Limit 均从同一配置 seam 派生，所有真实能力继续关闭。

### 批次四：Admin/App 公开配置

- Admin/App 只消费白名单生成的 PublicConfig。
- 删除业务代码中的环境变量和端口判断。
- 构建时阻断 L2/L3 配置进入前端产物。
- 已于 2026-07-30 完成：新增版本化 `public.snapshot`，Admin 与 App 各自只读取 `VITE_POLLYCAR_PUBLIC_CONFIG` 或 `EXPO_PUBLIC_POLLYCAR_PUBLIC_CONFIG`；API 地址、Admin 合成能力、App 展示环境和 Web 地图公开字段均由 `@pollycar/configuration` 白名单生成并失败关闭解析。构建子进程会剥离其余全部 `VITE_*` 与 `EXPO_PUBLIC_*` 变量，批准引用、Secret Reference、数据库配置和旧公开变量不得进入前端产物；真实能力继续关闭。

### 批次五：供应商、密钥与安全策略

- 统一短信、身份、OIDC、OCR 和地图服务端配置。
- 原始 Secret 改为 Secret Reference。
- 会话、挑战、尝试次数和 Body Limit 进入受控策略。
- 已于 2026-07-30 完成：生产准备配置新增统一 `server.providers.sms`、`server.providers.identity`、`server.providers.adminOidc`、`server.providers.vehicleOcr`、`server.providers.amapWebService` 与 `server.cryptography.keyReferences` 关闭态快照，供应商地址、批准引用和托管 Secret Reference 统一校验；高德 Server Adapter 不再读取固定环境密钥名，腾讯云 OCR Adapter 不再在构造配置中接收原始 `SecretId`／`SecretKey`，统一通过 `SecretProvider` 解引用。新增版本化 `authentication.v1` 策略，收口手机号验证码时效、重发间隔、小时限额、最大尝试次数、用户会话、车主活体挑战与一次性授权，以及运营后台登录锁定、MFA、身份选择和访问／空闲／绝对会话时效；HTTP Body Limit 增加 `16 KiB` 至 `2 MiB` 范围校验。所有真实供应商和生产认证能力继续关闭。

### 批次六：原生构建、EAS、CI 与供应链

- 统一签名、高德原生 Key、工具链版本、测试数据库和镜像 digest。
- GitHub Actions、EAS 和本地构建使用同一校验器。
- 已于 2026-07-30 完成：新增共享构建配置校验器，固定 Node 22、pnpm 10.22.0、Java 17、EAS CLI 21.4.0 与 `postgres:17-alpine`，并按 `native-ci`、`postgres-ci`、`production-release`、`container-evidence`、`container-publication` 五类目标分别失败关闭。App 本地生产发布准备、EAS 生产 Profile、GitHub 质量门禁、PostgreSQL 集成测试、Android／iOS 无签名 Release 编译和供应链工作流统一调用同一校验器；生产发布只消费版本化 `PublicConfig`，真实签名、高德原生 Key、正式应用标识与外部批准缺失时继续阻断。供应链证据可在本地生成，但镜像发布必须同时具备四项不可变基础镜像 digest、镜像仓库、OIDC 签名身份和发布批准，并只对实际构建输出的 digest 签名；当前未登记或伪造任何真实 digest，未发布镜像或启用生产能力。

### 批次七：删除旧入口

- 项目尚未上线，不保留长期兼容层。
- 删除旧变量、隐式默认值和重复门禁。
- 未登记变量和废弃变量直接导致治理检查失败。
- 已于 2026-07-30 完成：App 演示构建不再读取 `EXPO_PUBLIC_POLLYCAR_API_BASE_URL`，统一从本地沙箱 Profile 生成版本化 `PublicConfig`；Playwright 删除 `POLLYCAR_E2E_*` 端口别名，只使用 `POLLYCAR_LOCAL_SANDBOX_*`；生产 PostgreSQL 统一为 `POLLYCAR_DATABASE_URL`，本地生产基础设施和机器契约同步删除 `POLLYCAR_PRODUCTION_DATABASE_URL`；`.env.example` 删除两套 Admin 合成能力变量和通用占位配置。新增 44 项废弃环境变量清单、运行时硬拒绝、源码静态扫描和独立预检门禁，旧品牌变量、旧公开 API 变量、旧 Admin Vite 能力变量、旧高德公开变量、旧端口和数据库别名不得再被静默清洗、映射或兼容读取。历史名称只保留在治理契约、专项测试与迁移记录中用于审计，不构成运行入口；未登记变量、废弃变量与原始密钥分别失败关闭。

## 安全与合规影响

- L2/L3 配置禁止进入 Admin/App 公开构建产物。
- 原始生产认证 Token、Secret、Private Key 和 Password 禁止进入环境配置。
- 密钥引用、批准引用和镜像 digest 不等同于生产启用。
- `production-readiness` 明确禁止合成业务和真实业务能力。
- `production` 允许真实能力只是配置能力，不改变现有默认关闭门禁。

## 验收标准

1. TypeScript 配置目录、机器规范和本文档中的统一键可自动对齐。
2. 六类 Profile 不重复，只有 `production` 可声明允许真实能力。
3. 公开配置只能是 `L0`；Secret Reference 只能是 `L2`；Secret 只能是 `L3`。
4. 历史变量只保留审计映射，不得作为运行入口或兼容回退。
5. 未登记和已废弃的 PollyCar 配置变量可分别识别并失败关闭。
6. Admin、App、Server、EAS、CI 和基础设施只使用批次七保留的唯一正式入口。

## 生效与退出条件

本决策在批次一契约、规范、测试和治理检查通过后生效。每完成一个后续批次，应删除对应旧入口；批次七完成后不再接受旧变量兼容。
